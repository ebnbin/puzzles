# Puzzles

Simon Tatham 的四十个谜题，做成了一个网页应用。手机上可以装到主屏幕，断网也能玩。

**<https://puzzles.ebnbin.dev/>**

## 关于 vibe coding

这个项目是纯 vibe coding 的产物。除了上游那些 C 代码，这里的每一行都是和模型对话写出来
的：界面、构建脚本、深色调色板、中文翻译，以及你正在读的这份 README。

上面那句 tagline 就是这么来的。vibe coding 的大半时间是在等模型干活，而等的时候脑子是
空着的——这四十个谜题，就是拿来填那段空的。

## 能做什么

- 四十个逻辑谜题：Net、Solo、Mines、Bridges、Loopy……
- 随手关掉，回来还是上次那一局
- 深色模式，棋盘跟着一起变
- 界面和完整手册都有中文
- 可以装到主屏幕，像个独立应用一样打开
- 不用注册，不联网，进度只在你自己的浏览器里

## 这一层做了什么

上游自己就有网页版——那些 C 代码本来就能编译成 WebAssembly。所以这个项目不是「把它搬上
网」，而是把它外面那层壳整个换掉。上游的 C 一行没动，动的只是它的 JavaScript 外壳，以及
围绕它的一切。三件事，其余都是围着这三件转的。

### 深色棋盘

不是给页面套滤镜，也不是把颜色反过来。棋盘是一块 canvas，上面每个像素都由引擎按自己的色号
画出来——而引擎只在启动时报一次颜色表，之后只按编号引用。所以深色模式是**我们这边把那张表
整个翻译一遍**，wasm 全程不知道自己正画在一块深色板子上。

翻译不是挑颜色，是定规则。五条基础规则——翻转、压缩、罩黑、提亮、棋盘变纸——加四条叠加规则，
由六个常量驱动。每个色位走哪条，取决于它在那个游戏里**是什么意思**：格子的底、笔画的墨、
光源、错误标记、斜面的高光与阴影，各有各的去处。**四十个谜题的每一个色位都是算出来的，没有
一个是手挑的**，六个常量都附了量过的依据（对比度、感知色距）。

浅色主题下这一层什么都不做，所以浅色棋盘仍然逐像素等于上游。哪个游戏的哪个色位属于哪一类，
这是算不出来的知识，写在几张表里，由 `npm run verify-palette` 强制它们的不变量。

细节和取舍都在 [`src/engine/palette.ts`](src/engine/palette.ts) 的注释里。

### 手机上的界面

上游的网页版是个桌面页面：顶上一条菜单栏、系统对话框、固定尺寸的 canvas。这里把整套交互
重画了一遍，前提换成一块窄屏和一根手指。

- **棋盘拿走所有剩下的空间**。上面一条标题栏，下面两个最常按的键，其余全部收进从底部推上来
  的抽屉，只在打开的那一刻才盖住棋盘。
- **虚拟键盘**。3x3 的 Solo 要 1-9，4x4 的还要 a-g，Undead 要三只怪物——上游有个
  `request_keys()` 能回答这个问题，但它的网页版根本不调用。所以这里按 game id 里的参数重新
  推了一遍。认不出来的 id 一律不显示键盘，而不是显示一个错的。另外补了几个没有键盘就够不到的
  键：一次填满所有铅笔标记、走一步提示、Net 的重新打乱。
- **没有路由**。地址永远是 `/`，画廊和棋盘互相替换而不是互相嵌套，返回键直接离开 app。冷启动
  回到上次那一局，回画廊回到上次滚到的位置。
- **每走一步存一次档**，用的是引擎自己的存档格式，和桌面版的 `.sav` 文件逐字节相同。
- 长按收起不玩的谜题、长按图标问它是什么、刘海避让、装到主屏幕、离线可玩。

### 中文手册

界面上那些词只是一小半。上游那份四十五页的手册——每个谜题的规则、操作、参数、偏好设置——
整份译成了中文，[`doc-zh/`](doc-zh/) 是手写的译文。

顺带把手册本身也修了。上游发布的是 halibut 的原始输出：HTML 4.01，没有 CSS，没有 viewport
标签，在手机上按桌面宽度渲染，得靠双指缩放才读得了。这里给每页换了 head、套上 app 的外壳、
接上同一套深浅色和语言切换，**但 `<main>` 里的正文一个字节都没碰**。

`npm run verify-doc` 会重新跑一遍 halibut 逐字节比对英文页，再拿中文页和英文页做结构比对——
标签序列、锚点、链接目标全部一致。这是四十五页译文里每一个交叉引用都还能跳对的原因。

## 开发

```bash
npm install
npm run dev
```

打包：

```bash
npm run build      # 类型检查 + 校验，产物在 dist/
npm run preview    # 预览 dist/
```

没有测试框架，也没有 linter，`npm run build` 就是全部的自动检查。动过调色板或者手册的话，
再跑一次 `npm run verify-palette` / `npm run verify-doc`（后者需要 halibut）。

| 路径 | 是什么 |
| --- | --- |
| `src/` | 界面 |
| `src/engine/` | C 与界面之间的那层契约，以及调色板 |
| `doc-zh/` | 手写的中文手册 |
| `vendor/sgtpuzzles/` | 上游源码，未经修改 |
| `public/` | 编译好的 wasm、手册、图片 |
| `scripts/` | 构建脚本 |

wasm、手册、缩略图这些产物都已经提交进仓库，日常开发不用重新生成。真要重新生成，步骤
和依赖在 [CLAUDE.md](CLAUDE.md)。
