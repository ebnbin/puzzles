# 上游谜题的输入参考

Simon Tatham's Portable Puzzle Collection 四十个游戏的**全部输入**——鼠标、键盘、触摸——
以及每个输入在每个游戏里做什么。

**来源**:`vendor/sgtpuzzles/`,commit `3c3632259d298ab62aafa8a5858823569ab1af46`(2026-07-19)。
全部结论直接读 C 源码得出,不引用手册——手册讲的是怎么玩,不是每个按钮在每种状态下的行为,
两者不是一回事。每条都带 `文件:行号`,升级上游后可以照着重查。

**这份文档不描述本仓库的 Web 界面。** 上游的键盘和这一侧 `src/games/` 画出来的键盘
是两件东西(`emcc.c` 不调用 `request_keys()`)。这里只写上游。

## 怎么读

分三部分,由粗到细:

1. **[输入模型](#一输入模型)**——四十个游戏共有的那一层:一次按键从前端到游戏要经过哪些
   改写、哪些键在游戏之前就被 midend 吃掉、返回值的四种含义。**这一层里的规则对四十个游戏
   一律生效,第三部分不再重复。**
2. **[总览矩阵](#二总览矩阵)**——四十行 × 输入列,用来横向扫「哪些游戏用右键拖拽」这类问题。
3. **[逐游戏详表](#三逐游戏详表)**——按上游顺序,每个游戏一节,列全该游戏的每个输入、
   每种状态下的行为、以及源码位置。

顺序是**上游的收录顺序**(Net 第一,Mosaic 最后),不是首字母序——和 `src/games.json`
一致,也和手册的章节顺序一致。

## 一、输入模型

### 1.1 一次输入要走过的路

```
前端(gtk.c / emcc.c / osx.m …)
    │  把真实事件翻成一个 int:LEFT_BUTTON、'a'、CURSOR_UP | MOD_SHFT …
    ▼
midend_process_key()                                    midend.c:1115
    │  ① 拖拽/释放归一化   ② 按钮优先级   ③ 一串键值改写
    ▼
midend_really_process_key()                             midend.c:983
    │  ④ MOD_STYLUS 的取舍
    ▼
游戏的 interpret_move()                                  <game>.c
    │
    ├─ 返回走子串 / MOVE_UI_UPDATE / MOVE_NO_EFFECT  →  游戏认领了,结束
    │
    └─ 返回 NULL 或 MOVE_UNUSED                      →  ⑤ 轮到全局键
```

**最后那个分叉是这份文档里最容易被忽略的一条**:全局键(撤销、重做、新局……)只在游戏
**没有**认领这个键时才生效。游戏自己吃掉的字母会把全局键盖住,而且盖得静悄悄。
见 [1.5](#15-全局键以及它们何时被遮蔽)。

### 1.2 按键常量

全部定义在 `puzzles.h:32-63`。前端只能送这些值(或它们与修饰符的按位或)。

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `LEFT_BUTTON` `MIDDLE_BUTTON` `RIGHT_BUTTON` | 0x0200-0x0202 | 三个键按下 |
| `LEFT_DRAG` `MIDDLE_DRAG` `RIGHT_DRAG` | 0x0203-0x0205 | 按住移动 |
| `LEFT_RELEASE` `MIDDLE_RELEASE` `RIGHT_RELEASE` | 0x0206-0x0208 | 松开 |
| `CURSOR_UP` `CURSOR_DOWN` `CURSOR_LEFT` `CURSOR_RIGHT` | 0x0209-0x020C | 四个方向键 |
| `CURSOR_SELECT` | 0x020D | 「确认」。**回车被 midend 改写成它** |
| `CURSOR_SELECT2` | 0x020E | 「次确认」。**空格被 midend 改写成它** |
| `UI_QUIT` `UI_NEWGAME` `UI_SOLVE` `UI_UNDO` `UI_REDO` | 0x0210-0x0214 | 菜单动作。**永远不会传给游戏** |
| `MOD_STYLUS` | 0x0800 | 这一下是触摸/触控笔,不是鼠标 |
| `MOD_CTRL` | 0x1000 | Ctrl |
| `MOD_SHFT` | 0x2000 | Shift |
| `MOD_NUM_KEYPAD` | 0x4000 | 这个数字来自小键盘 |

除此之外,任何**可打印 ASCII** 和少数控制字符都可以作为 button 值直接送进来——各游戏自己
认的字母、数字就是这么来的。

`UI_*` 那一档由前端在用户点菜单时伪造,`midend_really_process_key` 里
`if (!IS_UI_FAKE_KEY(button))` 一句把它们挡在 `interpret_move` 之外(midend.c:1004)。
所以**游戏永远看不到「用户点了撤销菜单」**,只看得到全局键那一层的结果。

### 1.3 游戏看到它之前,midend 会改写

按 `midend_process_key` 里的实际顺序(midend.c:1115-1163)。**这一层的每一条都是全局的**,
所以第三部分的表里写的是改写**之后**的值——写 `CURSOR_SELECT2` 而不是「空格」。

| # | 条件 | 改写 | 位置 |
| --- | --- | --- | --- |
| ① | 收到 DRAG 或 RELEASE,但当前没有按下的键 | **整个丢弃** | midend.c:1211 |
| ② | 收到 DRAG 或 RELEASE,有按下的键 | 改成**那个键**的 DRAG/RELEASE(前端中途换键也纠正回来) | midend.c:1201-1209 |
| ③ | 一个键按下时另一个键已经按下 | 若 `BUTTON_BEATS(旧,新)` 则**丢弃新的**;否则先伪造旧键的 RELEASE,再放行 | midend.c:1213-1226 |
| ④ | `MOD_CTRL` + 0x40..0x7F | 折成控制字符(Ctrl+A → `\x01`) | midend.c:1230 |
| ⑤ | Ctrl+Shift+Z | → `UI_REDO` | midend.c:1233 |
| ⑥ | 带 `MOD_CTRL`,且键值 ≥ 0x20,且不是方向键 | **整个拒绝**,返回 `PKR_UNUSED` | midend.c:1238 |
| ⑦ | 不是方向键、也不是 Tab | 剥掉 `MOD_CTRL` 和 `MOD_SHFT` | midend.c:1241 |
| ⑧ | 键值不在 `'0'`..`'9'` | 剥掉 `MOD_NUM_KEYPAD` | midend.c:1244 |
| ⑨ | `\n` 或 `\r` | → `CURSOR_SELECT` | midend.c:1249 |
| ⑩ | 空格 | → `CURSOR_SELECT2` | midend.c:1251 |
| ⑪ | `\177`(另一个退格码) | → `\b` | midend.c:1261 |

**⑥⑦ 两条的后果值得单独说,因为它们决定了「哪些组合根本不存在」:**

- **Ctrl + 鼠标点击不存在。** `LEFT_BUTTON` 是 0x0200,远大于 0x20,又不是方向键,所以
  第⑥条直接返回 `PKR_UNUSED`——任何游戏都收不到。Ctrl+回车、Ctrl+空格同理。
- **Shift + 鼠标点击等于普通点击。** 第⑦条把 `MOD_SHFT` 剥掉,游戏收到的是干净的
  `LEFT_BUTTON`,无法区分。
- **修饰符只在两处活下来**:四个方向键(Shift / Ctrl / 两者)和 Tab(Untangle 用,
  2024 年 7 月为它开的口子)。
- `MOD_NUM_KEYPAD` 只在数字上活下来,所以「小键盘的 5」是 `MOD_NUM_KEYPAD | '5'`,
  而「小键盘的 Enter」就只是 `CURSOR_SELECT`,和主键盘的回车分不开。

### 1.4 `interpret_move()` 的四种返回值

游戏用返回值告诉 midend「这一下算什么」(`puzzles.h:849-863`):

| 返回 | 含义 | 后果 |
| --- | --- | --- |
| 走子字符串 | 真的走了一步 | 进撤销链,`execute_move` 执行,存进存档 |
| `MOVE_UI_UPDATE` | 只动了界面状态(光标移了、拖拽中) | 重画,**不进撤销链** |
| `MOVE_NO_EFFECT` | 认得这个键,但这次什么也没发生 | 什么都不做,**但算「认领了」** |
| `MOVE_UNUSED` | 完全不认识这个键 | **让给全局键** |
| `NULL` | 同 `MOVE_UNUSED` | **让给全局键** |

`MOVE_NO_EFFECT` 和 `MOVE_UNUSED` 的差别正是遮蔽的开关:前者把键吃掉了(全局键收不到),
后者放行。第三部分逐游戏标注了这个区别。

### 1.5 全局键,以及它们何时被遮蔽

只有当游戏返回 `NULL` 或 `MOVE_UNUSED` 时,这一层才轮得到(midend.c:1004-1043)。

| 动作 | 键 | 位置 |
| --- | --- | --- |
| 新局 | `N` `n`※ · `Ctrl+N`(`\x0E`) · `UI_NEWGAME` | midend.c:1005 |
| 撤销 | `U` `u`※ · `*` · `Ctrl+Z`(`\x1A`) · `Ctrl+_`(`\x1F`) · `UI_UNDO` | midend.c:1011 |
| 重做 | `R` `r`※ · `#` · `Ctrl+R`(`\x12`) · `Ctrl+Y`(`\x19`) · `Ctrl+Shift+Z` · `UI_REDO` | midend.c:1020 |
| 求解 | `Ctrl+S`(`\x13`) · `UI_SOLVE`,且游戏 `can_solve` | midend.c:1029 |
| 退出 | `Q` `q`※ · `Ctrl+Q`(`\x11`) · `UI_QUIT` | midend.c:1032 |

※ 打星号的**裸字母**受偏好设置 `one-key-shortcuts`(「Keyboard shortcuts without Ctrl」)
控制,默认**开**(midend.c:242、2954)。关掉之后只剩 Ctrl 组合和符号。
注意 `*` `#` 和 Ctrl 组合**不受**这个开关控制,永远有效。

上游把这条塞进**每个游戏**的偏好表(midend.c:2951),于是四十份互不相干的副本;
**本前端把它收成一个全局设置**(首页设置面板,`useShortcuts.ts`),开局压在每个游戏的
偏好存档上面,各游戏的偏好面板里那一行撤掉——见 keys.md 的「压顶的强制值」。

**求解没有裸字母**,只有 `Ctrl+S`——这是有意的,免得手滑把答案掀出来。

**哪些游戏遮蔽了全局键。** 逐个核对了四十个 `interpret_move` 里**对 `button` 做的每一次
比较**之后,答案是:遮蔽极少,而且都带条件。

| 游戏 | 键 | 何时被吃掉 | 何时仍是全局键 |
| --- | --- | --- | --- |
| Tents | **`N`**(大写) | 键盘光标显示中,且光标不在树上 → 把该格标成「不是帐篷」 | 光标没显示、或光标在树上;**小写 `n` 永远不受影响** |
| Solo | `n` `N` 等字母 | 有格子高亮,且棋盘大到该字母代表一个合法数值(`字母序号+10 ≤ cr`,`n` 是 23,即 25×25 数独) | 标准 9×9 / 16×16 一律不受影响;没有高亮时也不受影响 |
| Unequal | `n` `N` 等字母 | 同上,`c2n` 把字母折成 `序号+11`(`n` 是 24),需 `order ≥ 24` | 常规尺寸不受影响 |

**除此之外没有了。** 特别是下面这几条**不成立**,它们是「按字母 grep 源码」会得出的
错误结论——那些引号里的字母是**走子字符串**的内容,不是按键:

- Rect、Solo、Keen、Towers、Unequal 里的 `'R'` 是走子串里表示「填真值」的字母(如
  `solo.c:4769` 的 `sprintf(buf, "%c%d,%d,%d", 'P' 或 'R', …)`),不是按键。
- Pattern 里的 `'U'`、`'F'`、`'E'` 同理,是走子串的操作码(pattern.c:1391)。
- Loopy 里的 `'n'` `'u'` `'y'` 是边的三种状态字符(loopy.c:3082);**Loopy 根本不接受
  键盘输入**,源码原话是 "I think it's only possible to play this game with mouse
  clicks, sorry"(loopy.c:3070)。

所以四十个游戏里,`u`(撤销)、`r`(重做)、`q`(退出)在常规尺寸下**从来没有被任何
游戏遮蔽过**;`n`(新局)只在 Tents 的大写形态和两个巨型拉丁方棋盘上会被抢走。

### 1.6 游戏的 `flags` 字段

每个游戏的 `thegame` 结构末尾一个 int(`puzzles.h:79-90`),声明它对输入设备的要求:

| flag | 含义 | 谁带 |
| --- | --- | --- |
| `REQUIRE_RBUTTON` | 必须有右键才能玩 | Blackbox · Bridges · Dominosa · Galaxies · Keen · Magnets · Map · Mines · Palisade · Pattern · Signpost · Singles · Solo · Tents · Towers · Unequal · Untangle |
| `REQUIRE_NUMPAD` | 必须能输数字 | Filling · Keen · Solo · Towers · Unequal |
| `STYLUS_SUPPORT` | 触摸和鼠标要区别对待 | Net · Pattern · Lightup · Loopy · Tents |
| `BUTTON_BEATS(x,y)` | 按钮优先级 | **只有 Mines**:`BUTTON_BEATS(LEFT, RIGHT)` |
| `SOLVE_ANIMATES` | 求解要放动画 | **只有 Untangle** |

`REQUIRE_RBUTTON` / `REQUIRE_NUMPAD` 是给没有这些设备的移植端看的提示(注释里写的是
Pocket PC),不改变行为。`gtk.c:1964` 会据此决定是否显示模拟右键的工具条。

**Mines 的按钮优先级是唯一一处真的改行为的**:左右键同时按下时,后按的那个被丢弃,
只当作左键——为的是和其他扫雷实现的习惯一致(midend.c:1213 的注释)。

### 1.7 触摸与触控笔

**上游有一套专门的触摸接口,而且是活的。** 它由三样东西组成,三样都要分清:

**① `MOD_STYLUS` 修饰符。** 前端在事件来自触摸而非鼠标时给按钮或上这一位。
`gtk.c` 里的实现是真实、在编的(守卫是 `#if GTK_CHECK_VERSION(3,14,0)`,普通版本判断,
不是什么休眠开关):

| 真实手势 | 送出的按钮 | 位置 |
| --- | --- | --- |
| 触摸开始 | 记下 sequence,先不送按钮 | gtk.c:1819 |
| 长按 | `RIGHT_BUTTON \| MOD_STYLUS`(左右手互换时为 LEFT) | gtk.c:1872 |
| 长按被取消(变成了点或拖) | `LEFT_BUTTON \| MOD_STYLUS` | gtk.c:1884 |
| 触摸移动 | 当前按钮的 `_DRAG`,`MOD_STYLUS` 跟着 | gtk.c:1832-1837 |
| 触摸结束且还没送过按钮 | `LEFT_BUTTON \| MOD_STYLUS`,随即 RELEASE | gtk.c:1843 |

**长按 = 右键**,这就是上游给触摸设备的右键方案。

**② `STYLUS_SUPPORT` 标志。** midend 只对带这个标志的游戏保留 `MOD_STYLUS`,其余一律
剥掉(midend.c:987-995)。所以**只有 Net、Pattern、Lightup、Loopy、Tents 这五个游戏
能感知到「这一下是触摸」**,别的游戏收到的触摸和鼠标完全一样。这五个都在
`interpret_move` 里读了这一位(net.c:2152、pattern.c:1300、lightup.c:1963、
loopy.c:3056、tents.c:1568),各自的行为见第三部分。

**③ `STYLUS_BASED` 编译开关。** 这是给 Palm / PocketPC 那类**只有触控笔、没有鼠标**的
平台准备的。开启后:midend 会给**所有**鼠标事件都加上 `MOD_STYLUS`(midend.c:991),
Net 会换成一套「转动拖拽」界面(`USE_DRAGGING`,net.c:31),gtk 永远显示键盘条
(gtk.c:1894)。

**这个开关在当前上游树里没有任何构建定义它**——那些移植端已经不在了。所以
`net.c` 里那一整套 `USE_DRAGGING` 拖拽旋转界面是**死代码**,本文档第三部分照实标注,
不写进 Net 的主表。但 ①② 两条是活的,触摸长按在五个游戏里确实能变出右键行为。

### 1.8 游戏自报的键:`request_keys` 与 `current_key_label`

两个都是「游戏告诉前端该画什么按钮」的接口,方向和 `interpret_move` 相反。

**`request_keys(params, &nkeys)`** 返回一张 `{label, button}` 表,前端照着画一排按钮,
按下就等于送出那个 `button`(`puzzles.h:234-241`)。**只有六个游戏实现了它**:
Filling、Solo、Keen、Towers、Unequal、Undead。其余三十四个返回空,前端不画。
`label` 为 NULL 时 midend 用 `button2label()` 生成通用文字(misc.c),它只认
字母数字、四个方向、`CURSOR_SELECT`("Select")和 `\b`("Clear"),别的会 `fatal()`。

**`current_key_label(ui, state, button)`** 只对 `CURSOR_SELECT` / `CURSOR_SELECT2`
提问,返回**当前这一刻**这个键该叫什么(midend.c:`midend_current_key_label`,断言了
`IS_CURSOR_SELECT`)。**三十五个游戏实现了它**,返回 `""` 表示此刻这个键没用。

**这个函数本身就是「一个输入多种能力」的证据**,而且是上游自己承认的那份:Net 的
`CURSOR_SELECT2` 在未锁定的格子上叫 "Lock"、在锁定的格子上叫 "Unlock"(net.c:2124);
Sixteen 的两个确认键在网格边缘叫 "Slide"/"Back"、在网格内部叫 "Lock tile"/"Lock pos"
(sixteen.c:593)。第三部分逐个记录了这些标签及其条件。

### 1.9 光标的共有行为

三十一个游戏用同一个助手 `move_cursor()`(misc.c)移动键盘光标,它的约定是共有的:

- 只认四个方向键,别的返回 `MOVE_UNUSED`。
- `wrap` 为真时越界绕回,为假时**夹在边界上**(不是拒绝,是停住)。
- 传了 `visible` 指针且光标当时是隐藏的:**这一下只负责让光标现身,不移动**,
  返回 `MOVE_UI_UPDATE`。所以在光标隐藏时按方向键,第一下是「显示光标」,第二下才走。
- 真的移动了返回 `MOVE_UI_UPDATE`,被夹住没动返回 `MOVE_NO_EFFECT`。

**光标初始是否可见由环境变量 `PUZZLES_SHOW_CURSOR` 决定**,默认关
(三十五个游戏在 `new_ui` 里读它)。这是上游给测试用的开关,不是玩家设置。

大部分游戏还有一条共有的默契:**鼠标一点,键盘光标就隐藏**。这条不在共有代码里,
是各游戏自己写的(`ui->cur_visible = false`),所以第三部分逐个标注了谁有谁没有。

## 二、总览矩阵

四十行 × 输入列,按上游收录顺序。**空格表示这个游戏不接受这个输入**;有功能的格子写一个
最短的说法,完整条件见[第三部分](#三逐游戏详表)对应那一节。

列的含义按[第一部分](#13-游戏看到它之前midend-会改写)的口径:「Enter」是 `CURSOR_SELECT`
(回车、小键盘回车都归它),「Space」是 `CURSOR_SELECT2`。**「⇧方向」「⌃方向」只有方向键
这一列存在**——别处的修饰符在 midend 那层就被剥掉或拒绝了。「触摸」列指
`MOD_STYLUS`,只有带 `STYLUS_SUPPORT` 的五个游戏能感知。

| # | 游戏 | 左键 | 左拖 | 中键 | 右键 | 右拖 | 方向 | ⇧方向 | ⌃方向 | Enter | Space | 数字 | 字母 | ⌫ | Esc | 小键盘 | 触摸 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 1 | Net | 逆转 | | 锁定 | 顺转 | | 移光标 | 移原点 | 移源点 | 逆转 | 锁定 | | `ASDF` 转/锁·`J` 打乱 | | | | 右键改锁定 |

### 从矩阵里能直接读出来的几件事

- **中键分两种有用法。** 五个游戏**明写**了 `MIDDLE_BUTTON` 分支,给它一个独有的功能:
  Net(锁定)、Pattern(擦成 UNKNOWN)、Mines(连开)、Loopy(擦)、Unruly(清空)。
  另外八个游戏用 `IS_MOUSE_DOWN` 把三个键一起收下,中键于是**搭上了左键或右键那一档**:
  Untangle、Tracks(同左键),Signpost、Pearl(同右键——它们判的是 `== LEFT_BUTTON`,
  中键落进 else),Unequal、Singles(只在特定位置有效),Range(只挪内部位置)。
  其余二十七个游戏中键完全没用。
- **只有三个游戏用小键盘的斜向键**:Cube、Twiddle、Inertia——`7 9 1 3` 是四个斜方向或
  四个角块。另有三个游戏收小键盘数字但只当普通数字用:Sixteen、Dominosa、Filling。
- **`Esc` 只有三个游戏认**:Rect、Filling、Pearl,而且都是同一个用途——取消一个
  半成品状态(半截的拖拽、没提交的选择)。
- **`Tab` 只有 Untangle 认**,而 midend 为它在修饰符剥离规则上开了唯一的例外。
- **⇧/⌃+方向键有十个游戏用**:Net、Sixteen、Pattern、Tents、Bridges、Unequal、Towers、
  Range、Pearl、Palisade。全部是「移动的同时顺手改棋盘」或「改变移动的含义」。
- **完全不接受键盘的只有 Loopy**;**完全没有键盘光标的有三个**:Cube、Fifteen、Inertia
  ——它们的方向键直接就是走子。
- **能分辨触摸的只有五个**:Net、Pattern、Light Up、Loopy、Tents。共同点是触摸让某个键
  从「单向操作」变成「三态循环」,因为触摸设备上右键不好按。

## 三、逐游戏详表

| `CURSOR_SELECT2` · `\b` | 有高亮 | 清空该格(值 0) | solo.c:4725 |

一共 `cr+1` 个键。

**`current_key_label`**(solo.c:4635):有高亮时 `CURSOR_SELECT` 显示 "Pencil" 或 "Ink"
(取决于当前在哪一档),否则空。
