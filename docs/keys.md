# 按键适配

四十个谜题的屏幕按键:每个游戏读哪些键、给了什么按钮、还差什么。改动落地时同步改这里
——**这不是生成物**,没有脚本会替你更新它。设计过程、被否决的方案、测量记录都在 git 历史里,
这份文件只记现状、判据和坑。

代码的归属一句话:**一个游戏 = 一个文件**。逐游戏的键盘、色表、观察全部住在
`src/games/<name>.ts`;跨游戏的机器(标签推导、键构造器、拼装)在 `src/games/util/`,
那里看不见任何游戏名。宿主(PuzzleHost)只消费接口。

## 判据

三条,先后关系不能颠倒。

**一、`entry` 键:一个键值得做成按钮,当且仅当它做的那件事没有任何手势能做到。**
不是「有用」,不是「常用」,是「够不着」。

- 「够不着」有两个来源:上游没有那条路,和**我们没把那条路转发出去**(`usePuzzlePointer`)。
  第二种读上游读不出来——它不在 `interpret_move` 里。
- 判「够不着」之前把 `interpret_move` **整个**读完:键盘那半边、鼠标那半边、拖拽的松手分支、
  `switch` 掉下去的地方。历史上四次错判,三次那条够得着的路就在同一个函数里。
- 读到带条件的拒绝,先问那个条件什么时候不成立;「读不到」不等于「办不到」——`move_cursor`
  夹边不绕回,连按若干次就能把光标推到已知位置,推导可以代替读取。
- 上膛键该不该给,问「这一排还有没有别的路」,不是「上游有没有这个修饰键」(pearl 的画线不给:
  拖拽到得了,按压更少;打叉给:拖拽产生不出 `M`)。

**二、`arrow` 和 `pick`:判「方向键开着时,这套自己成不成立」。** 没有它们
方向键就是装饰,所以和方向键同一个开关。棋盘上多一条手势不会让这一排里的键变多余
——「够不着」问的是有没有人能做,这一条问的是这套输入自己讲不讲得通,两个问题不互相抵扣。

**三、`arrow` 跟着上游的光标走,不把光标赶到我们挑的地方去。** 图标说的是「这个键现在
是什么」,不是「按下去会怎样」;这一侧答不出来的量(方向、位置)一点都不能出现在图标里——
画错比不画糟。加字形之前先把 `src/ui/Icon.tsx` 里已占的形状普查一遍,撞脸没有任何检查会报;
候选按实际渲染尺寸(20px 亮、20px 暗、56px)并排看过再定;方向键旁边的图标不能长得像箭头。

## 五类按钮 · 两个区域

**用名字称呼,不要用编号。** 编号在这份文档里出现过三套互相冲突的版本,加一类就得
把后面全部往后挪一位——名字不会。接口的定义在 `src/games/game.ts`,那是 SSOT:上方三类
叫 `entry` / `pick` / `assist`,`act` 和 `arrow` 由结构决定、不入类型。DOM 的
`data-kind` 写的就是接口词,全项目一套词汇;localStorage 的 `puzzles.aid` 是唯一的
旧词残留——键名已发布,改名等于清掉用户的设置。

底部分两个区域:**上方区域**是 `.keypad`(棋盘正下方,按游戏发牌),**下方区域**是
`.puzzle-actions`(位置固定,一辈子长一个样)。

| 名字 | 谁 | 在哪 | 什么时候在 | 长什么样 |
| --- | --- | --- | --- | --- |
| `act` | Undo / Redo / Type / Menu | 下方 `.puzzle-acts` | 总在 | 扁平,只剩图标 |
| `entry` | 数字、`⌫`、Undead 的三个怪物 | 上方 `.keypad` | 总在 | 实心键面,无边框 |
| `arrow` | 方向键本体、`Enter`/`Space` 伴生键、slant 那种绝对键 | 下方 `.puzzle-arrows` | `puzzles.arrows` | 白键面 + 边框,正圆,整簇坐在底板上 |
| `pick` | Map 的四个区域色、Guess 的颜色钉 | 上方 `.keypad` | `puzzles.arrows` | 同 `arrow`:一样的键面、一样的正圆 |
| `assist` | 提示、`M` 铺标记、`J` 重排、Dominosa 的高亮数字 | 上方 `.keypad` | `puzzles.aid` | 键面同 `arrow`,形状是圆角矩形,字色淡一档 |

**布局。** 下方两块位置写死(`act` 在左、`arrow` 在右),上方按 **`entry` → `pick` →
`assist`** 排。这个顺序是结构不是约定:宿主在出口按组稳定排序,每个游戏 `keypad()` 返回值
内部的次序原样保留,所以游戏文件里写乱了也排得对。

**`pick` 为什么不跟 `arrow` 住一起。** 它和 `arrow` 是一伙的——同一个开关、同一套键面、
同样的正圆——但方向键块封死在 3×3,Guess 最多十种颜色装不下(见「现在的形状」)。所以
它挤在上方区域里,和邻座的 `entry`、`assist` 靠**圆**分开:那两类都是圆角矩形。

**只有两种键面**:有边框的填 `--surface`(`arrow` / `pick` / `assist`),没边框的填
`--surface-2`(`act` / `entry`)。白在 `--bg` 上只差 2%,所以 `assist` 读出「这是个键」
靠的是那圈边框,不是填充;真正分开 `entry` 和 `assist` 的也是边框。

**`entry` 和 `assist` 的分界是「没有它这一局玩不完」**,不是「常不常用」:Dominosa 的数字只
高亮不落子,`M` 铺的是铅笔标记,一局不写标记照样能填完——都是 `assist`。这条判据在
`2802d6c` 收紧过一次(Pattern 的灰键从 `entry` 改判成方向键方案的一部分,理由是解完的
棋盘上没有灰)。

**两个开关。** `puzzles.arrows`(见 `useArrows.ts`)关掉时 `arrow` 和 `pick` 一起不画:
整块 `.puzzle-arrows` 不渲染,上方区域把 `pick` 组滤掉。Map 因此关了方向键就
没有上方区域(它的键全是 `pick`),Guess 只剩一个提示键。

`puzzles.aid`(见 `useAssist.ts`)管 `assist`,**默认关**,和方向键一样是选进来的:提示、铺标记
这些一局不用照样玩得完(就是 `entry`/`assist` 那条判据),所以默认的键盘只留必要键。整排都是
`assist` 的八个游戏(net、guess、dominosa、galaxies、fifteen、bridges、range、pearl)因此
默认没有上方区域,棋盘多一行。

## 现在的形状

方向键是**一个全局设置**,默认关,开关在首页的设置面板里(`puzzles.arrows`,见 `useArrows.ts`)。
开启后棋盘下方出现一排键:**固定键那四个在左,方向键在右**,位置固定,没有偏好可调。

方向键块**最多 3×3**。格子号从下往上、每行从左到右——**和屏幕的自上而下反着**;
没人注册的格子是个洞,没人注册的行整行不画,块就矮一截:

```
 7  8  9
 4  5  6
 1  2  3
```

**九格对四十个游戏够用**,前提是 Map 和 Guess 的颜色键不在这儿(它们是 `pick`,排在
上方区域,见「五类按钮」)。今天用到第三行的只有 pattern、slant、inertia、bridges 四个,一个都不
超过 9。**别为了塞下什么再往这儿加第十格**:上一版为了装 Guess 的十种颜色把它扩到过
13 格,代价是顶行要能从 3 格长到 7 格、满格那档还得把键窄成 36、缝减半成 2,触摸节距
从 44 掉到 38,而且那一行和下面两行对不齐。把颜色键挪出去之后这些全部消失。

**整块宽度 268**:

```
rim + 128 + 2×gap + 128 + rim = 6×tap-w + 7×gap = 268
方向键块和固定键块各 128(3×40+2×4 = 2×62+4),中间隔两道缝
```

两块**等宽**是 `--act-w`(`1.5×tap-w + gap/2` = 62)这个定义的全部用处;它们之间隔的是
**两道缝**(8),比键与键之间宽一倍——两块才读得出是两块。键 40、缝 4,**节距 44**,
全场只有这一档(Apple 那条线正好够)。底板 rim 是半道缝(2):撑满一道就和固定键贴上了。

每个游戏在自己的 `games/<name>.ts` 里把键钉死在格子号上,**四个方向键也逐个游戏写全**
(`cross()` 是默认落位 左=1 下=2 右=3 上=5 的速记),伴生键从 4、6 起往上排。

一格可以住两个键(同 slot 注册两条),谁的 `face()` 活着就是谁——Pearl 的 6 号格画线时是
「打叉」、收得回来时是「取消」,靠的就是这个。八向的游戏(只有 Inertia)把八个方向摆满一圈,
中间的 5 号格正好留给它的「一直滑到底」,所以**八向和伴生键不再互斥**。

Map 和 Guess 的方向键块里剩下什么:

- **Map** 1/2/3/5 四个方向 + `4` 是「可能」模式、`6` 是清空。四个区域色在上方区域。
- **Guess** **只有左右**(1、3),2 号格空着:上下在上游是选颜色的,那件事被上方区域
  那排圆键顶替了。`4` 保留、`5` 删除、`6` 看结果,全是上游自己的键,判据见下。

| mosaic | ✅ | 两个开关:黑 · 白 ✅(和 unruly 逐字同一套)· 解完之后两个一起灰(上游自己不报了) | —— |

⭕ = 碰棋盘就能做到,按判据一不该做成按钮。

## 遗留问题

四十个游戏走完之后剩下的账,一处集中。「还没做」「审计过决定不做」「做了但有代价」「以后会
安静地坏掉」是四件不同的事。每条都写卡在哪——一条没有卡点的遗留问题其实是没做,应该直接做掉。

### 一、还没做

| 谁 | 什么 | 卡在哪 |
| --- | --- | --- |
| 修饰键组合 | net 移原点/源、unequal 和 towers 划线索、palisade 画墙 | 机制已有(粘滞如 pattern 的刷、一次性如 bridges),剩「一个一个铺」。铺之前先分清是够不着还是只是快一点,再翻一遍上游手册——sixteen 那种上游自带的粘滞版本比造一个便宜 |
| signpost 的 `X` | 拆整条链 | 要一次右键拖拽,长按变拖拽的路已通;探过一次没写出走子,没查清是拖错了地方还是真不通 |
| map 的 `l` | 显示区域编号 | 偏好设置里已经有(`show-numbers`),剩下的只是「要不要再给一个按钮」 |

### 二、审计过,决定不补(2026-08-14,前提是上游 `3c36322`)

四十个游戏逐个对照过上游全部输入(输入表见 `docs/inputs.md`,每条带源码行号):
**真够不着的只有 3 处,没有一处会改棋盘**——

- **Untangle** 反向循环顶点(`Shift+Tab`):只是绕远,正向 `Space` 在。
- **Net** 平移视野/移动信号源(`Shift`/`Ctrl`+方向):纯显示,不改解答。
- **Filling** 取消整个选区(`Esc`):我们根本不给选区键,这个状态进不去(见全表 filling)。

另有两处能做到但藏得深(Singles 点棋盘外切换黑格数字、Undead 长按计数区换样式):显示开关,
不值一个键位。快捷方式类(上游更快的入口,同一件事换个方式到得了)按定义不补。
**重新打开任何一条,得先有一条能改棋盘的**;这些决定只对这个上游 commit 成立。

### 三、明知有代价,选择了不修

| 谁 | 代价 | 为什么不修 |
| --- | --- | --- |
| blackbox 角上的「检查」 | 摆够球、走到角上、撤销一枚后,按钮亮着按下去无事(上游标签比行为宽一格:`current_key_label` 在角上无条件报 Check,干活的分支查 `CAN_REVEAL`) | 两条修法一条引入「读状态栏散文」的新依赖、一条是拉丁方读盘量级的自己数球;撞上的代价只是白按一下 |
| netslide / sixteen 的边框 | 光标在边框上时四个方向键只有两个活,看起来像 bug | 上游键盘本来就这样;标签整圈报同一个词,分不出光标在哪条边,没有依据置灰 |
| mines 的 `Enter` | 亮 ≠ 安全:旗插错了照样亮,按下去踩雷 | 风险是这步棋本身的,点数字承担的完全相同;但记住,一个亮着的按钮比一次点击更像背书 |
| 上游的 `Shift+Ctrl+Z` 重做 | 到不了引擎:`usePuzzleKeys` 把 Ctrl + 单字符整类挡在外面 | 浏览器的快捷键全长在这一类上,上游又会认领 `Ctrl+R`(任何单字符都连 MOD_CTRL 交给 midend,emcc.c:402),放行等于吞掉刷新;重做另有 `r` 和撤销区的键,少的只是一个入口。Ctrl+方向不在此列,照旧放行 |

### 四、会安静地坏掉的

坏的时候没有任何东西报错,`npm run build` 照样绿。

1. **`key()` 的返回值只对拼作 `Backspace` 的键有意义**(emcc.c 给 KaiOS 的照顾)。guess 的 `⌫`
   靠它向后删;上游删掉那个分支,这个键悄悄退回上游语义。
2. **`lsk === csk` 的抹空还压在生成物里**:已发布的胶水两键同词时把第一个抹成空串,宿主按
   `upstream.echoes` 复原。每加一个两键可能同词的游戏,先把它 `current_key_label` 的所有
   分支列一遍、同词的词写进 `echoes`——漏了不报错,只会让一个按钮在那一态整格灰掉
   (dominosa 在旧机制下现过形)。重生成引擎改双传后这一条整个消失。
3. **按钮死活没有提交进仓库的自动检查**:构建期的注册表对账(`games/util/verify.ts`)只管
   申报的形,正确性是「按钮的死活和后端对不对得上」,只有真跑引擎才验得了(check 脚本之外
   的验证都是临时搭的)。改这一块别只信 build 绿。

这份文档自己也是第五处:手写的,只能手写着改。教训两条——grep 不是阅读(可见性标志十种拼法、
`IS_CURSOR_SELECT` 宏、fallthrough 都数不出来);读到带条件的拒绝,先问条件什么时候不成立。

## 机制

跨游戏的机器全在 `src/games/util/`:上方区域的构造器在 `util/keys.ts`,方向键那块的
标签推导和拼装在 `util/pad.ts`;逐游戏的取值全在各自的 `games/<name>.ts`。下面记每个机制
「是什么 + 不知道会用错的那一句」。

**标签通道。** `current_key_label` 按光标位置返回两个词,经 `onKeyLabels` 进来,这是这一侧
唯一能知道的关于光标的事(`midend_get_cursor_location` 没被 emcc.c 导出)。`post_move` 是
同步的:`api.key()` 一返回标签就已更新,但 React 还没渲染——**press 里要读 `board.view()`,
不能读渲染时抓的那份**。

**抹空与 `echoes`。** midend 本给两词,但已发布的 wasm 胶水(`public/engine/**`,生成物)
在两词相同时把 lsk 抹成空串。宿主在边界按 `upstream.echoes`(每游戏「两键可能同时报出的
词」)复原,接口内部只见双词;「两个键干的事不同」在双词上就是 `enter !== space`。现在两个
游戏申报:rect(拖拽没动过两键同报 Cancel)、signpost(拖拽中三个词都可能成对)。下次
重生成引擎把胶水改成原样双传,`echoes` 整个删除。

**`faces`(换脸键)。** 同一个键在一局里换工作,脸跟着标签走(`ActSpec.faces`)。置灰规则
比普通键强:**当前词不在脸谱里就灰**,哪怕按下去真会发生什么;灰的时候戴自己的默认脸,不是
别人的脸。多张脸成立的判据是「同一份工作在不同地方的样子」(blackbox 四张脸都是「把脚下这格
该做的事做掉」),samegame 的「取消选中」不是这个键的工作,所以走第二层另开一键。标签之外
还要看事实才知道是哪张脸的游戏(rect 的拖拽记账、pearl 的走没走过格),用 `word` 钩子注入
哨兵词、哨兵脸写进脸谱。

**`does` + `instead`(按结果命名)。** 按钮的名字是结果,由标签反查此刻哪个键给出它——
pattern 用它把两个循环键翻成三个位置钉死的颜色键,samegame 用它让「取消」自己知道何时该灭。
`instead`:要不到自己那个词时改要「清空」,「没有人提供我要的词」恰好等于「这一格已经是它」。
**tracks 是反例**:它的 `Clear` 两个键都报、含义不同(清轨/清叉),`does` 会擦错东西,只能用
`faces`。

**`lit` / `mute` / 两词俱空。** 置灰的判决(`util/pad.ts` 的 `wouldSend`)带原因:
`asleep` 镜像光标睡着、`already` 幂等、`blank` 当前词无脸、`idle` 第二层待命、`silent`
两词俱空(上游此刻不认确认键)。`lit` 是 pattern 三个颜色键的幂等例外(全 app 唯一:
刷到一半按钮不许在拇指底下熄灭),只豁免 `already`,别的原因照灭。`mute` 给上游注册
NULL 却每条分支都干活的键(untangle):恒可按,不看标签。

**`layer`(两层菜单)。** 这一排是「当前这一层的菜单」,不是固定清单。`layer: 2` 的键只在
第二层出现;判层是游戏文件里的 `arrows.layer` 函数,`layerByWords(words, second)` 按标签里
出没的词判(现在四家:samegame、inertia、flood、pearl)。**second 词表必须对两个键都只属于
第二层**(flood 的 Advance 只在 `Space` 上,只读 `Enter` 的词曾让它永远消失)。第二层的语义
是「光标正站在待定物上」,不是「有一个待定物存在」——前者是标签的纯函数,后者要记状态;镜像
光标睡着时不算在层里(`layerByWordsAwake`)。排版不数这些:格子号是注册时钉死的,同层换人
的两个键注册在同一格,常在的键永不挪位。

**上膛键(`arm`)。** 按下去不落子,下一个方向键带修饰键发出去;上膛时这一排只显示它,再按
一次退出。**只在真落了子之后才消耗**——上游在移动失败时不清 `dragging`(bridges 撞边界那一按
什么都不写却把引擎留在拖拽里),所以 `walk` 看存档字节判断落没落。被藏起来的键留在 DOM 里用
`visibility` 藏(iOS 上卸载再插回会画成残片)。

**粘滞模式(`latch`)。** pattern 的刷、map 的「可能」:按下亮着(宿主只记亮灭,含义由读它
的键定义),亮着时方向键/颜色键带上修饰。模式改的是**别的键**的行为,所以那些键要自己换脸
(箭头尾巴加填实格、名字变「向上涂」);选中的笔刷用环标记,**环只在有一支以上笔刷时画**
(tents/range 只有一支,环会长得像一个按不动的选择)。光标不在的空档:方向键裸发(第一下只
唤醒)、模式键灭而位留着。

**替换(对方记号上一按)。** lightup/tracks/palisade/singles:先发对方的键擦掉,再发自己的,
一按两条走子、撤销要两次。lightup 的第二下**必然**落得下(能挡它的只有黑格,而黑格上邻居
一个字不报);tracks 保证不了(边的出口可能已占满),所以发完要**重读一次标签**,落不下就
`undo` 撤回——代价是那次撤回会点亮重做键。

**观察(`observe`,标签之外的一切事实)。** 默认是零:这一侧的东西全是推导,不是记录。
每个游戏的自留状态收在它自己的事实类型 `F` 里,由 `observe.next` 这一个 reducer 喂,事件
闭集四种(发牌、走子后的存档、这一侧发出的键、一帧画面)。加一份自留状态要过三条,缺一不加
——上游确实没有接口;输入面是封闭的(每一次按键、触摸都经这一侧);失效自纠正(猜错一两步内
自己回正轨,这条拉丁方读盘过不了,所以那边是「拒绝」不是「记」)。现状:

- **光标镜像(一个 bit)六个游戏**:net、samegame、flip、dominosa、flood、map——四十个的
  `current_key_label` 逐个读过,只有这六个实现了却不查自己的可见性标志(标志有十种拼法,
  grep 数不出来,只能读)。这是唯一由宿主代管的镜像(`upstream.cursor: mirrored` + 唤醒键
  名单),清灭接在 `onPermalinks` 上,新游戏/换预设/手打 id/读档一行全盖;存档门里的载入
  不清。有镜像的游戏,按钮睡着时戴默认脸。
- **flood 的 `Advance` 带 `offCursor`**:它不在光标那儿干活,镜像的门是按键开的,不是按游戏。
- **rect / signpost 的 `opened`(哪个键开的拖拽)**:四个状态里三个标签自己说得清,只有
  「开了没动」靠记,猜错免费(那一格两个键本来都是放弃)。
- **pearl 的 `walked`**(起笔后走没走过格):标签说不出,存档不带;错的那个角(贴边起笔按
  朝外)代价是勾亮着按下去等于旁边的叉。
- **tents 的 `under` / cube 的 `rolls`**:从存档推(只读半边,见「存档门」)。
- **map 的 `spot`**(唯一一份坐标):调色板要往光标那格落色。敢记是因为 `midend_deserialise`
  每次重建 `game_ui`、光标回原点,**每按一次调色板副本就重新对齐一次**。
- **palisade 的 `stand`**:从每帧画面读(`observe.frames`),见下。

**`mute`(豁免,不伪造)。** untangle、palisade 的 `current_key_label` 是 `NULL`,照字面读
两个按钮会整局灰着。untangle 的两个键申报 `mute` 直接放行,免费(它的 `Enter` 每条分支都
做事);palisade 的键从每帧画面里读死活(自己文件里的 `readStand`),Full-grid 模式下一个
按钮都不给——修饰键发不出去,两个永远无效的亮键不如没有,所以它的 face 读偏好、偏好申报
volatile。

**存档门(`gate`)。** `midend_deserialise` 把走子直交 `execute_move`,不经 `interpret_move`
——键说不出的动作从这里写。map 的四个颜色键走这扇门(上游没有任何键能说出一个颜色,走子是
`<颜色>:<区域>`);区域编号**问引擎,不算几何**——第一版重写了 map.c 的几何,错在对角线格子
依赖 SHA-1 洗牌的访问顺序,一局约 1% 的格子错、错得很安静。现在先把每个区域刷上颜色再让
引擎自己说(全涂色让「沉默」只剩「这是线索」一个意思)。代价每按一次 70–120ms。门内发生的
一切不喂观察器,门关上补一个存档事件。

**存档门的只读半边。** tents 的「脚下是什么」(标签分不出帐篷和草)从走子表读(它文件里的
`squareAt`,按 `STATEPOS` 截到当前位置);数字键角标的「还剩几个」同理(`util/latin` 的
`remaining`)。只读不写:`game_ui` 不重建、光标不丢、照闪。

**`touch.hold` 只管长按,鼠标一律照上游。** 只有 net 申报中键(长按=锁定):手指只有两下,
鼠标有三键加修饰,两者只在硬件不一致的那一处不一致。往申报里写和默认值相同的记录,申报就
开始说谎。

**guess 只自己造了一样东西:一键选色。** 别的全部照上游,一个按钮对应上游自己的一个键,
脸和死活一律读 `current_key_label`。唯一的替换是那排圆的颜色钉:**一按 = 上下顶到那个颜色
+ `Enter`**,正是上游「上下选色、确认落子」那条路缩成一个键(`move_cursor` 夹边不绕回,
连按 `ncolours` 次「上」必到第一格——推导,不是记忆;取近的那一头顶)。所以落完光标**不动**,
和上游的 `CURSOR_SELECT` 一致。

上游另有一条路是数字键(落色**并前进一格**,`guess.c` 自己的注释就这么写),我们不用它:
两条路混着走会让「按一下到底动了什么」说不清。这里踩过一次:上一版把数字键、我们自造的
退格(`ArrowLeft` + `Backspace`)、一个自己数的 `typed` 计数器和提交后补的 `ArrowLeft`
拼在一起,结果是保留的钉子够提交时光标赖在「看结果」位、整排颜色键变哑弹,pad 上没有出路。
**拼接越多,参数一变就越容易出这种洞**——现在的规矩是不拼。

三个功能键的死活全由光标在哪定,一张表说完(`current_key_label` 报什么就是什么):

| 光标 | `labels.enter` / `.space` | 保留 | 删除 | 看结果 | 颜色钉 |
| --- | --- | --- | --- | --- | --- |
| 在钉子上 | `Place` / `Hold` | 亮 | 亮 | 灰 | 亮 |
| 在「看结果」位 | `Submit` / `""` | 灰 | 灰 | 亮 | 灰 |
| 解出来了 | `""` / `""` | 灰 | 灰 | 灰 | 灰 |

`Enter` 落在钉子上时上游是「放下调色板光标指着的那个颜色」,**这半边我们不给按钮**:
上方区域每个圆键都做同一件事(而且说得出是哪个颜色),按判据一它够得着。所以这个键
只剩「看结果」一张脸,光标不在那一位就是灰的。

颜色钉在「看结果」位一起置灰:那时候 `Enter` 是提交,不灰就成了「按颜色变成交卷」。按下去
之前还会再问一次 `labelsNow()`(上下只动调色板光标,钉子光标没动,所以顶完再问照样准),
挡的是状态刚变、按钮还没重画完那一瞬间的点击。颜色数超过 10 或者 id 认不出来时整排不画,
和别处一样——显示错的比不显示糟。

## 坑

- **cube 不是八向**:方向是每个格子自己声明的,正方形网格四个斜向全是 0,三角网格斜向是别名。
  inertia 才是真八向。
- **cube 的置灰分界**:棋盘自己会说的(顶到边界),我们不说;棋盘盖住了的(三角朝向被多面体
  压住),我们说。netslide/sixteen 的边框半活不置灰,理由相同的另一半——光标就摆在那儿。
  实现是推导不是副本(`games/cube.ts`,整数坐标),**升级上游后必须跑 `scripts/check-cube.mjs`**:
  模型漂了会把能按的键灰掉,错灰和该灰长得一模一样,读者报不上来。
- **死代码像功能**:tracks 的 `h` 在 `#if 0` 里,signpost 的 `h` 整段被注释掉。别照着加。
- **guess 的删除键在「看结果」位会越界**:`peg_cur` 的取值是 `0..npegs`,多出来的
  `npegs` 是「看结果」位,而 `curr_pegs->pegs` 只分配了 `npegs` 个。上游对这一位置
  防了 `CURSOR_SELECT` 和 `CURSOR_SELECT2`,**唯独 `'D'/'d'/'\b'` 那一支没防**——
  它会读 `pegs[npegs]`,读出来非零还会往那儿写个 0。`vendor/` 不能改,所以那一位
  必须把删除键灰掉,这是唯一一道拦;`labels.enter !== 'Place'` 就是那个传感器。
  写过一次实验:连按八次退格,四颗钉子一颗没变(正好反证打的是数组外面),没崩、
  没报错——内存错误的常态是看不见,看得见的时候在别处。
- **guess 提交完光标不会自己归位**:`game_changed_state` 只在「提交不了」时把光标从
  「看结果」位拉回来,保留的钉子本身够提交时它就赖在那儿。这不是死路——左方向键一按
  就出来,那是上游的走法;**别为此在提交后补 `ArrowLeft`**,那是我们替上游做决定。
- **一个按钮只有一份工作**:上游在某个局面拿同一个键干别的,按钮置灰而不是改行(samegame 的
  「选中」在孤立格上安静下来);但 sixteen 的边框推行不是别的工作——「工作」由上游这个键在
  这个位置上的意思定,不由我们定。
- **写用例的三条**:禁用的按钮仍戴默认脸,判死活问 `disabled` 不问文案;blackbox 按完「检查」
  光标自己跑回场地;pegs 点空孔不收光标(十字盘正中恰好是唯一的空孔)。
- **金丝雀**:只剩 cube 和 fifteen 没有光标键,而且是因为它们没有光标——用例里反着断言这一条。
- **物理键盘不认焦点**:通路是挂在 window 上的 `usePuzzleKeys`,判据是「这一刻谜题该不该吃
  这一按」——覆盖层盖着就不吃,焦点坐在真控件上就只让出 Space / Enter。**别改回 canvas 的
  `onKeyDown`**:焦点一旦承重,每加一个会抢焦点的部件就得记得把焦点还回来,漏了不报错、
  build 照样绿,而症状是「玩着玩着键盘就没反应了」。屏幕上的键区和方向键块走的是
  `board.send`,从头到尾不经过焦点,所以这条只坑用物理键盘的人——桌面上试,手机上试不出来。

七个 check 脚本(`check-cube` / `check-map` / `check-clues` / `check-palisade` /
`check-keys` / `check-solved` / `check-focus`)何时跑、守什么,见各脚本和被测文件的头部注释。
