# 按键适配

四十个谜题的屏幕按键:每个游戏读哪些键、给了什么按钮、还差什么。改动落地时同步改这里
——**这不是生成物**,没有脚本会替你更新它。设计过程、被否决的方案、测量记录都在 git 历史里,
这份文件只记现状、判据和坑。

## 判据

三条,先后关系不能颠倒。

**一、第 2 类键(独立键):一个键值得做成按钮,当且仅当它做的那件事没有任何手势能做到。**
不是「有用」,不是「常用」,是「够不着」。

- 「够不着」有两个来源:上游没有那条路,和**我们没把那条路转发出去**(`usePuzzlePointer`)。
  第二种读上游读不出来——它不在 `interpret_move` 里。
- 判「够不着」之前把 `interpret_move` **整个**读完:键盘那半边、鼠标那半边、拖拽的松手分支、
  `switch` 掉下去的地方。历史上四次错判,三次那条够得着的路就在同一个函数里。
- 读到带条件的拒绝,先问那个条件什么时候不成立;「读不到」不等于「办不到」——`move_cursor`
  夹边不绕回,连按若干次就能把光标推到已知位置,推导可以代替读取。
- 上膛键该不该给,问「这一排还有没有别的路」,不是「上游有没有这个修饰键」(pearl 的画线不给:
  拖拽到得了,按压更少;打叉给:拖拽产生不出 `M`)。

**二、第 1 类键(光标伴生,`Enter`/`Space`):判「方向键开着时,这套自己成不成立」。** 没有它们
方向键就是装饰,所以和方向键同一个块、同一个开关。棋盘上多一条手势不会让这一排里的键变多余
——「够不着」问的是有没有人能做,这一条问的是这套输入自己讲不讲得通,两个问题不互相抵扣。

**三、第 1 类的键跟着上游的光标走,不把光标赶到我们挑的地方去。** 图标说的是「这个键现在
是什么」,不是「按下去会怎样」;这一侧答不出来的量(方向、位置)一点都不能出现在图标里——
画错比不画糟。加字形之前先把 `Icon.tsx` 里已占的形状普查一遍,撞脸没有任何检查会报;
候选按实际渲染尺寸(20px 亮、20px 暗、56px)并排看过再定;方向键旁边的图标不能长得像箭头。

## 四类按钮

底部分两区,四类。类别写在 `KeyLabel.kind` 上(区域 A)或由结构决定(区域 B),
样式只看类别,`src/index.css` 的选择器一一对应。

| 类 | 谁 | 在哪 | 长什么样 |
| --- | --- | --- | --- |
| 一类 | Undo / Redo / Type / Menu | 区域 B `.play-acts` | 扁平,只剩图标 |
| 二类 `need` | 数字、⌫、Undead 的三个怪物 | 区域 A `.keypad` | 实心键面,无边框 |
| 三类 | 方向键本体和它的伴生键,连 Map 的色板、Guess 的整排 | 区域 B `.play-arrows` | 和别的键同一个圆角,整簇坐在一块底板上 |
| 四类 `aid` | 提示、`M` 铺标记、三个标记键、`J` 重排、Dominosa 的高亮数字 | 区域 A `.keypad` | 同样实心,多一圈边框、字色淡一档 |

二类和四类的分界是**「没有它这一局玩不完」**,不是「常不常用」:Dominosa 的数字只
高亮不落子,`M` 铺的是铅笔标记,一局不写标记照样能填完——都是四类。这条判据在
`2802d6c` 收紧过一次(Pattern 的灰键从必要改判成方向键方案的一部分,理由是解完的
棋盘上没有灰)。

关方向键时**只藏三类**——现在这句话是结构性的:三类一个都不在区域 A 了,关掉方向键
就是整块 `.play-arrows` 不画,区域 A 一个字节都不用过滤。Map 因此没有区域 A(它的键
全是三类),Guess 只剩一个提示键。`KeyKind` 也因此只剩 `need` / `aid` 两个值。

四类另有一个开关(`puzzles.aid`,见 `useAid.ts`),**默认关**,和方向键一样是选进来的:
提示、铺标记这些一局不用照样玩得完(就是二类/四类那条判据),所以默认的键盘只留必要键。
整排都是四类的八个游戏(net、guess、dominosa、galaxies、fifteen、bridges、range、
pearl)因此默认没有区域 A,棋盘多一行。

## 现在的形状

方向键是**一个全局设置**,默认关,开关在首页的设置面板里(`puzzles.arrows`,见 `useArrows.ts`)。
开启后棋盘下方出现一排键:**左边方向键、右边那四个固定键**。格子号从下往上、每行
从左到右——**和屏幕的自上而下反着**。底行和中行是死的三格宽,顶行 3 到 7 格、左对齐、
往右长,长过三格就长到固定键的上方:

```
 7  8  9 10 11 12 13     顶行,多出来的往右长
 4  5  6
 1  2  3
```

**整块宽度恒定 268**,两种排法必须算出同一个数:

```
下两行  rim + 128 + 2×gap + 128 + rim = 6×tap-w + 7×gap = 268
        方向键块和固定键块各 128(3×40+2×4 = 2×62+4),中间隔两道缝
满七格  7×(tap-w − gap) + 8×rim      = 7×tap-w − 3×gap = 268
```

两式相等要求 **`--tap-w` 恰是 `--key-gap` 的 10 倍**(40 : 4)。这条写在 `index.css`
的 `--keys-w` 上,动其中一个就得连着动另一个,否则满 13 格的 guess 会比别的游戏宽出去
一截——而且只有那一个游戏、那一种参数才看得见。

两块**等宽**是 `--act-w`(`1.5×tap-w + gap/2` = 62)这个定义的全部用处;它们之间隔的是
**两道缝**(8),比键与键之间宽一倍——两块才读得出是两块。

常规档键 40、缝 4,**节距 44**,顶行沿用它。注意顶行是按这个节距一路排下去的,不认
中间那两道缝,所以第 4 格起会和固定键错开 4px:顶行第 4 格在 134,第一个固定键在 138。
满七格是唯一的例外档:键窄一道缝(36)、缝减半(2),**节距 38**,省出来的
正好够第七个键,代价是那一行只有第一格和下面对齐,而且触摸节距掉到 38(别处是 44,
正好够 Apple 那条线)。六格那档 264,右边比 268 短 4,是允许的。

底板 rim 是半道缝(2):撑满一道就和固定键贴上了,留 2px 净空。底板两块——核心那块
永远有,顶行自己带一块,长过三格时两块拼成一个 Γ(顶行盖在核心上面,同色,接缝
看不出来,所以顶行的右下角圆、左下角直)。

每个游戏在 `pad.ts` 的 `PAD` 里把自己的键钉死在格子号上,**四个方向键也逐个游戏写全**:
默认 左=1 下=2 右=3 上=5,伴生键从 4、6 起往上排。没人注册的行整行不画,块就矮一截。

一格可以有两个租客(写成数组),谁的 `face()` 活着就是谁——Pearl 的 6 号格画线时是「打叉」、
收得回来时是「取消」,靠的就是这个。八向的游戏(只有 Inertia)把八个方向摆满一圈,
中间的 5 号格正好留给它的「一直滑到底」,所以**八向和伴生键不再互斥**。

两个用到顶行的:

- **Map** 四个区域色占 7–10,前三个在核心上方、第四个长到固定键上方;`4` 是「可能」
  模式、`6` 是清空。
- **Guess** n 种颜色顺着占 `1..n`,保留 / 退格 / 确定紧跟其后。这三个必须同行相邻,
  而底行中行是死的三格宽,所以剩不下三格就整体让到上一行。10 色时 13 格填满,是今天的
  上限,也是唯一会走压缩档的情形。**左对齐是为它挑的**:数字 7 因此压在数字 4、1 的
  正上方,十个颜色连成一组;右对齐时它们会被那三个功能键劈成两半。

## 遗留问题

四十个游戏走完之后剩下的账,一处集中。「还没做」「审计过决定不做」「做了但有代价」「以后会
安静地坏掉」是四件不同的事。每条都写卡在哪——一条没有卡点的遗留问题其实是没做,应该直接做掉。

### 一、还没做

| 谁 | 什么 | 卡在哪 |
| --- | --- | --- |
| 修饰键组合 | net 移原点/源、unequal 和 towers 划线索、palisade 画墙 | 机制已有(粘滞如 pattern 的刷、一次性如 bridges),剩「一个一个铺」。铺之前先分清是够不着还是只是快一点,再翻一遍上游手册——sixteen 那种上游自带的粘滞版本比造一个便宜 |
| signpost 的 `X` | 拆整条链 | 要一次右键拖拽,长按变拖拽的路已通;探过一次没写出走子,没查清是拖错了地方还是真不通 |
| map 的 `l` | 显示区域编号 | 偏好设置里已经有(`show-numbers`),剩下的只是「要不要再给一个按钮」 |
| `wouldSend` 的返回类型 | 把「为什么不发」说出来 | null 有四个来源(`gated && !awake`、`does` 无人提供、`faces` 无脸、`doesNothing`),一个 bit 盖不住,已让 pattern 的 `lit` 出过一次「没光标也全亮」的 bug。修法是返回带原因的联合类型,`lit` 变成「already 时仍然亮」 |

逐游戏推进看不见机制缺陷:每个 entry 单独看都对,只有问「这个 null 到底什么意思」才看得见。
表是数据,逐游戏加是对的;**机制不是数据,不会因为多加一个游戏而被复查。**

### 二、审计过,决定不补(2026-08-14,前提是上游 `3c36322`)

四十个游戏逐个对照过上游全部输入(输入表见 `docs/inputs.md`,每条带源码行号):
**真够不着的只有 3 处,没有一处会改棋盘**——

- **Untangle** 反向循环顶点(`Shift+Tab`):只是绕远,正向 `Space` 在。
- **Net** 平移视野/移动信号源(`Shift`/`Ctrl`+方向):纯显示,不改解答。
- **Filling** 取消整个选区(`Esc`):我们根本不给选区键,这个状态进不去(见全表 filling)。

另有两处能做到但藏得深(Singles 点棋盘外切换黑格数字、Undead 长按计数区换样式):显示开关,
不值一个键位。快捷方式类(上游更快的入口,同一件事换个方式到得了)按定义不补。
**重新打开任何一条,得先有一条能改棋盘的**;这些决定只对这个上游 commit 成立。

### 三、明知有代价,选择了不修

| 谁 | 代价 | 为什么不修 |
| --- | --- | --- |
| blackbox 角上的「检查」 | 摆够球、走到角上、撤销一枚后,按钮亮着按下去无事(上游标签比行为宽一格:`current_key_label` 在角上无条件报 Check,干活的分支查 `CAN_REVEAL`) | 两条修法一条引入「读状态栏散文」的新依赖、一条是 `engine/marks` 量级的自己数球;撞上的代价只是白按一下 |

### 四、会安静地坏掉的

坏的时候没有任何东西报错,`npm run build` 照样绿。

1. **`key()` 的返回值只对拼作 `Backspace` 的键有意义**(emcc.c 给 KaiOS 的照顾)。guess 的 `⌫`
   靠它向后删;上游删掉那个分支,这个键悄悄退回上游语义。
2. **`lsk === csk` 的抹空**:两键同词时第一个被抹成空串,「空」和「被抹掉的」分不出来。`BOTH`
   是唯一的解药,而它是手写的——每加一个用 `faces` 的游戏,先把它 `current_key_label` 的所有
   分支列一遍。漏了不报错,只会让一个按钮承诺它做不到的事(dominosa 现过形)。
3. **这一块没有提交进仓库的自动检查**:正确性是「按钮的死活和后端对不对得上」,只有真跑引擎
   才验得了(check 脚本之外的验证都是临时搭的)。改这一块别只信 build 绿。
4. **`BOTH.bridges` 疑似已无消费者**:`BOTH` 只服务 `faces`,而 bridges 现在没有 `faces` 键。
   删之前核实一遍。

这份文档自己也是第五处:手写的,只能手写着改。教训两条——grep 不是阅读(可见性标志十种拼法、
`IS_CURSOR_SELECT` 宏、fallthrough 都数不出来);读到带条件的拒绝,先问条件什么时候不成立。

## 机制

跨游戏的机制分两处:区域 A 那排在 `keys.ts`,方向键那块在 `pad.ts`。下面记每个机制
「是什么 + 不知道会用错的那一句」。

**标签通道。** `current_key_label` 按光标位置返回两个词,经 `onKeyLabels` 进来,这是这一侧
唯一能知道的关于光标的事(`midend_get_cursor_location` 没被 emcc.c 导出)。`post_move` 是
同步的:`api.key()` 一返回标签就已更新,但 React 还没渲染——**要读 ref,不能读 state**。

**抹空与 `BOTH`。** 两键同词时上游把第一个抹成空串,所以 `labels.space !== ''` 恰好等于
「两个键干的事不同」——第二个按钮值不值得给,这一条白送。被抹掉的词由 `BOTH`(每游戏「两键
可能同时报出的词」)还原,现在三条:rect、bridges、signpost。`BOTH` 只服务 `faces`。

**`faces`(换脸键)。** 同一个键在一局里换工作,脸跟着标签走。置灰规则比普通键强:**当前词
不在脸谱里就灰**,哪怕按下去真会发生什么;灰的时候戴自己的默认脸,不是别人的脸。多张脸成立
的判据是「同一份工作在不同地方的样子」(blackbox 四张脸都是「把脚下这格该做的事做掉」),
samegame 的「取消选中」不是这个键的工作,所以走 `SECOND` 另开一层。

**`does` + `instead`(按结果命名)。** 按钮的名字是结果,由标签反查此刻哪个键给出它——
pattern 用它把两个循环键翻成三个位置钉死的颜色键,samegame 用它让「取消」自己知道何时该灭。
`instead`:要不到自己那个词时改要「清空」,「没有人提供我要的词」恰好等于「这一格已经是它」。
**tracks 是反例**:它的 `Clear` 两个键都报、含义不同(清轨/清叉),`does` 会擦错东西,只能用
`faces`。

**`lit` / `silent` / `doesNothing`。** `doesNothing`(两词皆空)是标准置灰;`lit` 是 pattern
三个颜色键的幂等例外(全 app 唯一:刷到一半按钮不许在拇指底下熄灭),`silent`(两词皆空 =
光标没显示)把「幂等」和「没光标」分开——`lit` 只豁免前者。

**`SECOND` / `level`(两层菜单)。** 这一排是「当前这一层的菜单」,不是固定清单。`level: 2`
的格位只在第二层出现;`SECOND` 声明哪些词表示第二层开着,现在四条(samegame、inertia、flood、
pearl)。**写进去的词必须对两个键都只属于第二层**(flood 的 Advance 只在 `Space` 上,只读
`Enter` 的词曾让它永远消失)。第二层的语义是「光标正站在待定物上」,不是「有一个待定物存在」
——前者是标签的纯函数,后者要记状态;光标睡着时不算在层里。排版不数这些:格子号是注册时钉死的
(`pad.ts`),同层换人的两个键注册在同一格,常在的键永不挪位。

**上膛键。** 按下去不落子,下一个方向键带修饰键发出去;上膛时这一排只显示它,再按一次退出。
**只在真落了子之后才消耗**——上游在移动失败时不清 `dragging`(bridges 撞边界那一按什么都不写
却把引擎留在拖拽里),所以要看存档字节判断落没落。被藏起来的键留在 DOM 里用 `visibility`
藏(iOS 上卸载再插回会画成残片)。

**粘滞模式。** pattern 的刷、map 的「可能」:按下亮着,亮着时方向键/颜色键带上修饰。模式改
的是**别的键**的行为,所以那些键要自己换脸(箭头尾巴加填实格、名字变「向上涂」);选中的
笔刷用环标记,**环只在有一支以上笔刷时画**(tents/range 只有一支,环会长得像一个按不动的
选择)。光标不在的空档:方向键裸发(第一下只唤醒)、模式键灭而位留着。

**替换(对方记号上一按)。** lightup/tracks/palisade/singles:先发对方的键擦掉,再发自己的,
一按两条走子、撤销要两次。lightup 的第二下**必然**落得下(能挡它的只有黑格,而黑格上邻居
一个字不报);tracks 保证不了(边的出口可能已占满),所以发完要**重读一次标签**,落不下就
`undo` 撤回——代价是那次撤回会点亮重做键。

**光标副本(`awake` 等)。** 默认是零:这一侧的东西全是推导,不是记录。加一份自留状态要过
三条,缺一不加——上游确实没有接口;输入面是封闭的(每一次按键、触摸都经这一侧);失效自纠正
(猜错一两步内自己回正轨,这条 `marks/` 过不了,所以那边是「拒绝」不是「记」)。现状:

- **`awake`(一个 bit)六个游戏**:net、samegame、flip、guess、dominosa、flood——四十个的
  `current_key_label` 逐个读过,只有这六个实现了却不查自己的可见性标志(标志有十种拼法,
  grep 数不出来,只能读)。清灭接在 `game_id_change_notify`(即 `onPermalinks`)上,新游戏/
  换预设/手打 id/读档/标记键 loadGame 一行全盖。有副本的游戏,按钮睡着时戴默认脸。
- **flood 的 `Advance` 带 `offCursor`**:它不在光标那儿干活,副本的门是按键开的,不是按游戏。
- **rect 的 `opened`(哪个键开的拖拽)**:四个状态里三个标签自己说得清,只有「开了没动」靠记,
  猜错免费(那一格两个键本来都是放弃)。
- **pearl 的一位**(起笔后走没走过格):标签说不出,存档不带;错的那个角(贴边起笔按朝外)
  代价是勾亮着按下去等于旁边的叉。
- **guess 的 `typed`**(这一行打了几枚):`⌫` 永远先退一格再删,数到 0 置灰;提交/撤销/点棋盘
  归零,最多漂一行。
- **map 的光标坐标**(唯一一份坐标):调色板要往光标那格落色。敢记是因为 `midend_deserialise`
  每次重建 `game_ui`、光标回原点,**每按一次调色板副本就重新对齐一次**。

**SILENT(豁免,不伪造)。** untangle、palisade 的 `current_key_label` 是 `NULL`,照字面读
两个按钮会整局灰着,所以 `wouldSend` 见到这两个名字直接放行。untangle 免费(它的 `Enter`
每条分支都做事);palisade 的键从每帧画面里读死活(`engine/palisade`),Full-grid 模式下
一个按钮都不给——修饰键发不出去,两个永远无效的亮键不如没有,所以它在 `READS_PREFS` 里。

**map 走存档门。** 上游没有任何键能说出一个颜色,四个颜色键从存档门写走子(`<颜色>:<区域>`)。
区域编号**问引擎,不算几何**——第一版重写了 map.c 的几何,错在对角线格子依赖 SHA-1 洗牌的
访问顺序,一局约 1% 的格子错、错得很安静。现在先把每个区域刷上颜色再让引擎自己说(全涂色
让「沉默」只剩「这是线索」一个意思)。代价每按一次 70–120ms。

**存档门的只读半边。** tents 的「脚下是什么」(标签分不出帐篷和草)从走子表读(`engine/tents`,
按 `STATEPOS` 截到当前位置);数字键角标的「还剩几个」同理(`marks/remaining`)。只读不写:
`game_ui` 不重建、光标不丢、照闪。

**`HOLD_BUTTON` 只管长按,鼠标一律照上游。** 名单里只有 net(长按=锁定):手指只有两下,鼠标
有三键加修饰,两者只在硬件不一致的那一处不一致。往名单里写和默认值相同的记录,名单就开始说谎。

**guess 的键盘排。** 颜色键发的是上游自己的数字键;按下前先用夹边走位把棋盘上的颜色圈瞄准
自己(`move_cursor` 夹住不绕回,连按 `ncolours` 次「上」必到第一格——推导,不是记忆)。这一排
坐在方向键那块里(`pad.ts` 的 `guessPad`),但**一个方向键都不画**:半个十字是一维菜单
(颜色条),另半个被顺序输入取代。颜色数超过 10 或者 id 认不出来时整块不画,和别处一样——
显示错的比不显示糟。

## 坑

- **cube 不是八向**:方向是每个格子自己声明的,正方形网格四个斜向全是 0,三角网格斜向是别名。
  inertia 才是真八向。
- **cube 的置灰分界**:棋盘自己会说的(顶到边界),我们不说;棋盘盖住了的(三角朝向被多面体
  压住),我们说。netslide/sixteen 的边框半活不置灰,理由相同的另一半——光标就摆在那儿。
  实现是推导不是副本(`engine/cube`,整数坐标),**升级上游后必须跑 `scripts/check-cube.mjs`**:
  模型漂了会把能按的键灰掉,错灰和该灰长得一模一样,读者报不上来。
- **死代码像功能**:tracks 的 `h` 在 `#if 0` 里,signpost 的 `h` 整段被注释掉。别照着加。
- **一个按钮只有一份工作**:上游在某个局面拿同一个键干别的,按钮置灰而不是改行(samegame 的
  「选中」在孤立格上安静下来);但 sixteen 的边框推行不是别的工作——「工作」由上游这个键在
  这个位置上的意思定,不由我们定。
- **写用例的三条**:禁用的按钮仍戴默认脸,判死活问 `disabled` 不问文案;blackbox 按完「检查」
  光标自己跑回场地;pegs 点空孔不收光标(十字盘正中恰好是唯一的空孔)。
- **金丝雀**:只剩 cube 和 fifteen 没有光标键,而且是因为它们没有光标——用例里反着断言这一条。

六个 check 脚本(`check-cube` / `check-map` / `check-clues` / `check-palisade` /
`check-keys` / `check-solved`)何时跑、守什么,见各脚本和被测文件的头部注释。
