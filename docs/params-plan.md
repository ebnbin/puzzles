# 自定义参数的设计计划

阶段性的工作文档,手写。记的是 owner 定下的目标、已经拿到的数据和还没定的事,供后续会话
接着做;做完并入 `params.md` 后删除。现状(范围模型、滑块、契约测试)见 `params.md`。

## 目标

让自定义参数像一个**设计过的游戏选项**,不是把上游允许的一切摆出来让人自己试。下游(React
这一层)有一份自己的、显式的参数契约:先把上游规则读透,在它之上设计我们要的规则;契约只受
一条约束——不能比上游宽——定下来之后运行时不再参考上游,上游只是引擎,我们喂给它的每个组合
都是挑选过、验证过的。

每个游戏一份**有限的、显式的参数菜单**,在每一种下拉/开关组合下,string 控件能取的值是一张
张表,表与表之间有依赖。菜单要同时满足:

1. 菜单 ⊆ 上游放行(硬)。
2. 预设 ⊆ 菜单(硬):上游给过 30×30 的预设,我们就不能把上限定在 30 以下。
3. 菜单里每个组合都在预算内生成得出来(硬):边界实测,中间靠成本模型(多数游戏的耗时随参数
   平滑变化,读生成器就能知道驱动量是面积、长边还是窄度)。
4. 默认外框:边 ≤ 50,长边 ≤ 2 × 短边。100×2 这种棋盘容易生成失败也没有玩的价值;例外按游戏
   单独给理由(玩法本身适合窄条或大盘的)。
5. 粒度按游戏定阶梯,不是逐整数:47×29 和 50×30 没有区别。Pattern 已是 5 的倍数,是范本。
6. 上限按难度/模式分档。
7. 派生参数(雷数、球数、区域大小、颜色数、打乱步数、障碍概率)也是阶梯,用有语义的单位。

已决定不做的:把上游 `validate_params` 逐条转写成 JSON/TS 的「上游规则 SSOT」。调研做过原型
(逐点对 oracle 等价、含文案、full 两种模式全过),但在上面这套定位下它只是设计期工具,而
现有的 gcc oracle(`scripts/lib/params-oracle.*`)已经能回答「上游收不收」,不值得再维护一份。

## 地形(2026-09-13,本机 4 核 2.8 GHz Xeon,比 owner 的机器慢两三倍)

**预设**:40 个游戏没有一个预设的长宽比超过 2(最大正好 2.00,Same Game 10×5),2:1 与预设
零冲突。边长超过 20 的预设只有 Mosaic 50×50、Mines 30×16、Map 30×25、Pattern 30×30,Mosaic
因此必须给到 50。

**阶梯大小**(2:1 之内的宽高组合数):步长 5 的 5..50 是 10 档 60 组;10 以内逐整数、再
12/14/16/18/20/25/30/35/40/45/50 是 19 档 163 组;逐整数 3..50 是 1292 组;现状 2..100 不限
比例是 9801 组。

## 做法

- **契约的表达**:沿用 `types.params`(滑块按表下标走,表可任意稀疏,界面不用改),在
  `util/params.ts` 加共享词汇:`ladder` 给阶梯,`grid` 把宽高绑成一对并带比例和上限,难度分档用
  `r.pick('Difficulty')`,派生参数用密度/占比阶梯换算成上游要的原值。
- **每个游戏五步**:读生成器找成本驱动量 → 提阶梯和分档上限 → 核对预设都在菜单里 → 边界组合
  多种子实测对预算 → 写进游戏文件(注释只留驱动量一两句),数据进 docs。
- **工具**:`check-params` 改成契约核对(菜单每格上游放行、预设都在菜单里;删掉
  `EXPECTED_NARROWER` 和「表外一格被拒」那一半);新增生成计时工具扫菜单边界(各难度最大尺寸、
  最窄形状、派生参数两端,多种子,报最坏与中位);`params.md` 的生成器改成每游戏写菜单和依据。
- **分批**:纯宽高加难度的约二十个;宽高带派生参数的(Mines、Black Box、Palisade、Map、Flood、
  Same Game、Twiddle、Sixteen/Netslide、Net、Rect、Light Up);单数字的(Solo、Keen、Towers、
  Unequal、Untangle、Dominosa、Guess);特殊几何的(Cube、Loopy、Pegs、Unruly、Pattern)。先用
  Tents(成本封顶)、Mines(密度阶梯)、Palisade(约数型派生参数)三个把词汇和工具走通。

## 进度

- **Net(已定)**:宽高只给 3..49 的奇数,两根滑块档位都是全表,动一根另一根被推到 2:1 内
  最近的合法档(互推,像 min/max 联动滑块);Barrier probability 0、0.1 … 1 共 11 档,读数
  百分比,不附墙数(上游不显示);两个开关不动。代码规矩从这里起:可选值在游戏文件里逐个
  列出,是枚举不是规则。互推靠模型的两样新东西:参数可另申报「窗口」,settle 知道主动方。

## 待 owner 定(开始做具体游戏时再定)

1. 生成预算。建议本机中位 ≤ 1 秒、十个种子最坏 ≤ 3 秒。
2. 预设是否必须是滑块的一档(建议是:选中态才跟得上;阶梯因此按游戏含预设值)。
3. 默认阶梯形状(建议 10 以内逐整数,再 12/14/16/18/20/25/30/35/40/45/50;Pattern 保持 5 的倍数)。
4. 之前按 100 定的游戏(Net、Rect、Slant、Black Box、Map、Inertia、Mines、Cube、Untangle 100 点)
   是否全部回到 50 外框重定。
5. 换难度时尺寸表缩小、当前值被夹下去,是设计使然还是要避免。
