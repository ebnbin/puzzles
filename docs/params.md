# 自定义参数的取值范围

Simon Tatham's Portable Puzzle Collection 四十个游戏的自定义参数面板里,全部 91 个 string 控件(上游 C_STRING)的取值范围:每一个的语义、上游 validate_params 的每一条规则(带源码行号)、本仓库最终给它的表、它看哪些别的控件、上限从哪来。choices 和 boolean 控件不在范围内,它们在上游本来就不是输入框:choices 画成分段按钮(Bridges 那三个数值阶梯画成滑块),boolean 是勾选框,取值就是上游给的那几个。

**来源**:`vendor/sgtpuzzles/`,commit `3c3632259d298ab62aafa8a5858823569ab1af46`(2026-07-19)。全部规则直接读 C 源码得出;每条带 `文件:行号`,升级上游后照着重查。**代码是 SSOT**:范围写在各 `src/games/<game>.ts` 的 `types.params`,词汇在 `src/games/util/params.ts`;这份文档是索引和理由,不是第二份真相;它本身是生成物,手写源在 `scripts/lib/params-doc.mjs`,生成器 `scripts/build-params-doc.mjs`。两者是否一致由 `scripts/check-params.mjs` 对着上游源码验证(第七节)。

## 怎么读

分八节:**一、机制**是四十个游戏共有的那一层——值怎么进出 C、模型长什么样、控件怎么画、怎么把上游的量换成有语义的量;**二、总览**一张表横扫全部 91 个参数;**三、逐游戏详表**按上游收录序,每个游戏一节,列全该游戏的全部控件、每个 string 参数的语义与上游规则、本仓库的表、默认参数下模型算出的实际表、预设;**四、与上游的出入**;**五、被 CAP 封顶的参数**(还没定夺范围的清单);**六、已知问题**;**七、验证**;**八、实现**。

表里的「依赖」一栏写的是这个参数看谁:「主」= 不看别的数字参数;「看宽」= 表由宽算出,宽动了它可能被夹。

## 一、机制

### 1.1 参数从哪来、到哪去

类型面板一打开,宿主就向后端要一份 config box,参数列表常驻。C 侧 `game_configure` 给出一组控件,wasm 胶水(`engine/puzzle-lib.js`)只把三样交到 JS:英文 label、类型(string / choices / boolean)、当前值的字符串。没有 kw,也没有任何范围信息(`emcc.c:616-637`)。

提交时 JS 把每个控件的值原样交回(`dlg_return_sval`),C 侧 `custom_params` 用 atoi / atof / sscanf 解析成 `game_params`,再过 `validate_params(params, full)`。**自定义面板这条路 full 恒为 true**(`midend.c:2011`)——文中所有「full:」开头的规则都生效。不通过就把错误串回传显示成 Notice,box 保持打开;通过就开新局并重新要一次 box。

所以范围知识只能放在 JS 侧,而且只能按 label 认控件。

**预设与参数互相跟随**,两个方向都是上游算的:点一条预设时,C 侧只有一个 config box,所以宿主先让位(`dialogCancel`)、换参数(`selectPreset`)、再要一份——新的这份就是那条预设的值。反过来,每次参数落定后 `midend_set_config` 都会跟一次 `select_appropriate_preset`(`emcc.c:705`),它拿 `midend_which_preset` 按编码后的参数串逐个比对(`midend.c`),命中就报那条预设、不命中报 −1,界面照着它点亮「自定义」。所以选中态不是界面自己猜的。

常驻的这份 box 占着 C 侧唯一的那个位置:键区的偏好键要借同一个 box 用,借之前先让位、借完再要回来(`useConfigBox` 的 `borrowPrefs`),否则那一借会被静默丢掉。

### 1.2 范围模型

每个 string 控件在游戏文件里申报一条 `Param`:label、类型、一个函数 `allowed(read)`,输入其它控件的当前值,输出**升序的允许值表**。连续区间、偶数、约数、浮点等距取样、只有一个值(钉死)都是同一种东西:一张表。

**申报顺序即依赖顺序**:一张表只许看排在它前面的数字参数,以及任意 choices / boolean。排在前面的是「主」,后面的跟着让。所以宽高总是可以自由拉动,雷数、区域大小、旋转块边长这类派生量随之被夹。

**settle**:用户每动一个控件,宿主按申报顺序单趟走一遍:刚动的那个是主动方不夹,其余的值不在自己的窗口(没申报窗口就是表)里就吸到最近的一档(等距取大),然后提交。表是按「后面的参数一定还有解」写的,所以走完必定是上游放行的组合;这条不变量由第七节的契约测试验证。对等的两个参数(Net 的宽高)互为窗口:档位永远是全表,动一根另一根被推到 2:1 内最近的合法档。

当前值来自上游(预设、Game ID、旧存档),可能在表外(比如 Game ID 里输入过 200×200,或 full=false 才放行的 2×2 Range)。面板先照实显示,滑块停在最近的一档;用户第一次动任何控件时才会被 settle 夹进表。

### 1.3 控件

**整数与浮点**:一个滑块,按表的**下标**走(表不连续也每一档都合法),两侧各一个 −/+ 步进按钮做精确微调,旁边显示当前值;表只有一个值时禁用。松手(change)才提交,拖动中只更新读数——和 checkbox / 分段按钮的「每次 change 即落定」一致。

**区间「a-b」**(只有 Black Box 的球数):同一个 label 下两行滑块,最少 / 最多;两者相等时写回单个数,和上游回显格式一致。

**附注**:两种。短的跟在读数后面(Mines 的雷数旁边显示占比,顶替下线的「20%」写法);长的在轨道下面单独一行(Rectangles 那一档由枚举算出来的 e)。读数列的宽度按当前这张表最宽的一条现算——宽度跟着值变的话,拖到一半轨道就缩水,滑块会从手指底下跑掉。

**choices 与 boolean**:choices 画成分段按钮(外观同首页的语言切换,会换行),选项全部可见、一点即换,写回的仍是选项下标;申报了 `ordinal` 的 choices(Bridges 的桥数、岛占比、扩展因子,上游用下拉装的数值阶梯)画成滑块,一档一个选项。boolean 是勾选框。两类的取值就是上游给的,不进范围模型。「门」是下游自己加的开关,挂在一个 int 控件上(Sixteen 的打乱步数):关 = 写 0、滑块不画,开 = 写 1,状态从数字读出,没有上游控件。

**兜底**:没申报的 string 控件(比如模态对话框那条路)仍画成文本框;label 对不上上游时申报被忽略,同样回落到文本框。

**上游那条「自定义」不画**:参数列表常驻之后它没有动作可做。参数不落在任何预设上时一条都不选中,那就是自定义。

### 1.4 上限的规矩

上游自身有上限的用上游的。上游没有的:网格维度封顶 100(棋盘最多 100×100 格),其它计数类参数先同用 100。第五节列出还没逐个定夺的那些——它们是占位,按游戏一个个读上游 + 实测来定。

几处故意与上游不同(补上游漏查的、或按语义封顶),全部列在第四节;契约测试把它们登记为「预期的收窄」,再多一处就 FAIL。

### 1.5 语义参数:把上游的量换成有语义的量

有些上游参数不是玩家能理解的量。Rectangles 的「扩展因子 e」是个没有上限的实数,但生成只通过 `(base_w, base_h) = (⌊宽/(1+e)⌋, ⌊高/(1+e)⌋)` 这一对整数看见它(`rect.c:1165-1168`):**落在同一对 base 上的 e 是同一个输入**,同种子下局面逐字节相同;而同一个 e 在不同棋盘上又是完全不同的粒度。这种参数值得在界面上换成它背后那个离散量。

四步(以 Rectangles 为例):① **找出真正影响生成的量**——把这个参数在上游源码里的每一次出现数一遍(`expandfactor` 共 11 处,只有 1165、1167 参与生成),看它经过什么变换进入生成,变换的像就是语义量。② **把语义量枚举出来,分界点用公式算**:`⌊边/(1+e)⌋ = k` 成立于 `1+e ∈ (边/(k+1), 边/k]`,分界点就是 `边/k`,两维并起来即全部;扫描是猜,公式才是证明,而且顺手能给出「一共几档」的闭式。③ **每个语义值反算一个上游认的原值当代表,再用同一套算法验回去**——代表值必须真的产出这个语义值,不验就等于假设。④ **控件里存的仍是上游的原值**:存档、Game ID、C 的回显只认它,语义值只活在界面和表里。

三条硬约束,都是踩到过的:**回显精度**——上游把值写回参数框用的什么格式(Rectangles 是 `%g`,六位有效数字),代表值必须能原样回来;回不来,下一次 settle 就把它当表外值,用户的设置被悄悄改掉。**算术要学像**——上游用 `float` 就得 `Math.fround`,截尾就得 `Math.trunc`;差一个 ulp 就会显示一个和引擎不一样的语义值(18×6 在 e = 0.2 处 `(float)18/1.2 = 14.999999`,base 是 14×5 不是 15×5,真机 DESC 也确实不同)。**表外的落点**——值不在表里时是吸到最近一档(`snap`,默认)还是回第一档(`reset`),按语义选;Rectangles 选 reset,因为换了棋盘整套枚举都换了。

**SSOT 是上游的原值**:它是唯一被持久化的东西(存档的 CPARAMS、Game ID、C 侧的 `game_params`);语义量是每次由别的控件现算出来的一张表,不落盘。两个方向不对称——`原值 → 语义值` 是全函数、和引擎逐位一致,任何值都算得出来;`语义值 → 原值` 是一对多里挑一个代表,只对枚举得到的那些语义值有定义。所以 `语义值 → 原值 → 语义值` 是恒等(表里每一档都是这么验出来的),`原值 → 语义值 → 原值` **不是**恒等,是一次规范化。跨棋盘更没有稳定性可言,也不该有:同一个原值在别的棋盘上就是另一个语义值。

附带一条:**枚举的算法算持久化契约的一部分**。改了代表值的取法(精度、候选规则),老存档里的原值可能落到新表外面——当前那一局不受影响(局面由 DESC 定),但面板一动就会被 settle 挪走。

**什么时候别做**:上游参数本身就有语义(宽、高、雷数、打乱步数)就别加这一层,加了只会让 Game ID 和界面对不上。

### Net(`net.c`)

#### `Width`(整数)

- **本仓库的表**:3、5、7 … 49 全部奇数(24 档,逐个列出),滑块永远是全表;窗口 = 表里和当前高满足 长边 ≤ 短边 × 4 的档,动高时宽被推进窗口

#### `Height`(整数)

- **语义**:棋盘高(格)

#### `Barrier probability`(浮点)

- **语义**:解上没走线的边里,画成实心墙的比例(墙数 = (int)(比例 × 候选边数),1534;不环绕的候选边是 (w−1)(h−1) 条,环绕是 wh+1 条);上游文档把它写成提示旋钮
- **上游**(`net.c`):
  - ≥ 0(328)
  - ≤ 1(330)
  - atof 解析(314),%g 回显
- **本仓库的表**:0、0.1、0.2 … 1(11 档,逐个列出);读数显示百分比
- **依赖**:—;**上限来源**:本游戏自定;**控件**:滑块 + 步进
- **默认参数下的表**:0, 0.1, …, 1(步长 0.1,11 个)

> **定下来的**:宽高只给 3..49 的奇数、互锁在 4:1 内、概率 0.1 一档。全部是设计判断,不是耗时:生成分四步(长树 1146-1290、唯一解 1292-1345、打乱 1440-1520、放墙 1524-1561),树是 O(wh·log wh),求解器一遍摊下来接近线性,扰动循环和打乱循环各有一条「不再进步就整盘重来」的单调保护,没有随参数爆炸的环节。

> 奇数:电源在 (w/2, h/2),奇数边它才在正中;上游十条预设全是奇数。3 起:1×1 和环绕 + 唯一解下的 2 都是上游不收的,3×3 起就绕开了。49:每格线宽 (TILE+47)/48,格边 48 px 以下是 1 px 线,笔记本 760 px 的棋盘上 49 格是 15 px、1440p 上 26 px,再大只有 4K 能看;玩法上 49×49 = 2401 格已是最大预设 13×11 的 17 倍。

> 4:1 的界面是互推,不是互锁:两根滑块的档位都是全表,用户动一根,另一根若出了 4:1 就被推到最近的合法档(宽拉到 49,高从 5 被推到 13),像 min/max 联动滑块那样;推的幅度总是最小的。落定时刚动的那个是主动方不夹。Game ID 或旧存档送进来的表外组合没有主动方,先按高夹宽、再按新宽夹高,一趟落在合法组合上;对方的值远在表外(100×100)时窗口给全表,免得两边都空。

> 概率是单调的提示旋钮,只会变容易:一堵墙给相邻两格各去掉一些朝向,直线和 T 形一堵就锁死,拐角要两堵,端点要三堵;p = 1 时每格的开口就是答案。它顺带压制多解(另一种摆法必用到某条非解边)。唯一解是在没有墙的前提下保证的(生成时求解器传 NULL,1300),墙不改变解。小盘上档位会塌:3×3 不环绕只有 4 条候选边,0.1 和 0.2 都是 0 堵;上游自己不显示墙数,这里也不加。

> 「Ensure unique solution」只影响生成不影响判胜:判胜只看全连通(2482-2511),而树的接口总数正好 2(n−1),全连通必无环,所以任何一种全连通摆法都算赢;关掉它的代价是有的局部两种摆法都对、推不出来,不是会输。手册把它写成高手找全部解的玩法(puzzles.but:550-557),保留、默认开。

预设:5x5 `5x5`;7x7 `7x7`;9x9 `9x9`;11x11 `11x11`;13x11 `13x11`;5x5 wrapping `5x5w`;7x7 wrapping `7x7w`;9x9 wrapping `9x9w`;11x11 wrapping `11x11w`;13x11 wrapping `13x11w`。

- **本仓库的表**:2..min(宽, 高) 逐整数,再要求 2·长边 + 短边 ≥ 6(n − 1)
- **依赖**:看宽高;宽高缩小时被夹;**上限来源**:本游戏自定;**控件**:滑块 + 步进
- **默认参数下的表**:2

#### `Number of shuffling moves`(整数)

- **语义**:0 = 默认长打乱;N > 0 = 只做 N 次旋转,状态栏挂 target(语义同 Sixteen)
- **上游**(`twiddle.c`):
  - ≥ 0(222)
  - 无上限
- **本仓库的表**:0..w+h 逐整数。0 与非 0 由「限定打乱步数」这扇门切换(机制见 Sixteen):关 = 写 0、滑块不画,开 = 写 1
- **依赖**:上限看宽高之和;门看自己的值;**上限来源**:本游戏自定;**控件**:滑块 + 步进
- **默认参数下的表**:0..6(7 个)

> 每一局都可解:局面是从已解状态旋转出来的,倒着转回去就是解,上游没有求解器。默认打乱(m = 0)走 2·w·h·n² 次旋转、每次 do_rotate 是 O(n²)(twiddle.c:340),整体 O(w·h·n⁴):上限收到 16 之后最贵的组合也只是 10⁶ 量级的格子搬动,毫秒级,耗时不再是因素(原先 50×50 n=50 要 140 秒的问题随之消失)。

> 宽高上限 16 是独立判断过的,与 Fifteen / Sixteen 落在同一档:可点位置数 (宽−n+1)(高−n+1) 在 16×16 n=2 时已是 225 个、256 块;块的手感由 n 决定、与盘大小无关,盘再大只是一局更长,没有新玩法。

> 块边长上游只要求 2 ≤ n ≤ min(宽, 高),这里再要求 2·长边 + 短边 ≥ 6(n − 1):长边算两份、短边算一份的加权边长 (2L + s)/3 要放得下两个只重叠 2×2 角的块(2n − 2),正方形上就是 ⌊s/2⌋ + 1。判据是「人能背的只动三格步法存不存在」:一次旋转动 n² 格,人解题靠把两个块的旋转拼成 A、B、A⁻¹、B⁻¹,乱掉的只有两块重叠处附近(约重叠格数的 3 倍);重叠 1 格时这四步就是三循环,重叠 2×2 或一条线时要再和第三个块套一层(10–20 步),重叠更多就套不出来。有了三循环,逐格归位(送位、做步法、倒回送位)就是机械活,每格代价 = 步法长度 + 2×送位。

> 工具普查:旧全集(宽高 2–16、4:1、面积 ≥ 6、n ≤ min、正方形不含 n = 边长)649 个组合逐个跑确定性的构造(嵌套换位子,八层、单元素 ≤ 1024 步):456 个有工具(301 个 4 步、143 个 10–20 步、12 个 22–64 步),193 个造不出。这条规则放行 454 个:放行而无工具的只有 3×2 n2(120 个局面的玩具盘,穷举证明三循环不存在,4×3 n3 同理);有工具而不放行的只有 14×7 n7、16×8 n8(工具 38 步)和 16×9 n8(16 步);放行里工具 22–64 步的 10 个(10×5 n5、11×5 n5、12×5 n5、13×5 n5、12×6 n6、13×6 n6、14×6 n6、15×6 n6、15×7 n7、16×7 n7)是 owner 定的保留。「造不出」除两个玩具盘外不是数学上不存在(算过群阶的都达到守恒律天花板,三循环在群里),只是没有人能背的构造;6×4 n4 穷举所有走法到 13 步,最小扰动仍是 6 格。公式里的 6 = 3(三份加权)× 2(两个块);是在一族单一线性不等式里按普查挑出来的,权重 2:1 让一条直线同时贴近「两块并排」(L ≥ 2n)和「三块成串」(L ≥ 3n − 2)两种长条盘构造。

> 通用解法(换位子造三循环、逐格归位,当时会话 scratchpad 的 human.c)实测每格代价只随工具长度分档:工具 4 步时每格 9–12 步,10–20 步时 13–21,34–38 步时 35–44;总步数再乘面积。16×16 上 n = 2..8 每格都是 9–12、n = 9 是 17;同一个 n = 8 在 16×16 每格 11、在 16×8 每格 44——难度不跟 n 也不跟面积,跟两块能重叠多薄。

> 下限 2 在所有尺寸上都是最温和的一档:16×16 n=2 全部 256! ≈ 10^507 种排列可达(2×2 旋转是奇置换,群是整个 S₂₅₆),通用解法约 2950 步、每格 11.5 步,与 Sixteen 16×16 同量级、比 Fifteen 短;两行窄条(2×4、2×8)没有四步三循环、要 10 步工具,但每格仍只要 6–8 步;2×3 共 120 个局面、最远 7 步。每格步数从 3×3 的 4.3 涨到 16×16 的 11.5,总步数随面积近似线性(39 → 88 → 245 → 527 → 1464 → 2955)。

> 可达局面数的规律(不带朝向,sympy Schreier–Sims 算精确群阶):n ≡ 2 (mod 4) 时旋转是奇置换,全部 N! 可达;n ≡ 0 (mod 4) 时只到偶置换 N!/2;n 为奇数时黑白格各自封闭,每色 (n²−1)/8 个 4-循环,它是偶数时两色各自只到偶置换。8×8 的 n=2..7 与 12×12 n=11 都精确达到各自的天花板;只有 2×3 n2(120 / 720)和 4×3 n3(720)这类玩具盘差得远。

> 打乱步数上限 w+h 的依据同 Sixteen:把上游 N 步打乱的局面对照全状态 BFS 的真实最优解(用上游 do_rotate 逐步重放),3×4 n=2 在 N = 7 时最优仍等于 N 的占 95%、N = 9 时 70%、N = 12 时 7%;4×3 n=3 在 N = 7 时 89%、N = 8 时 32%、N = 10 起 0%。N 一过宽高之和就塌下去。

预设:3x3 rows only `3x3n2r`;3x3 normal `3x3n2`;3x3 orientable `3x3n2o`;4x4 normal `4x4n2`;4x4 orientable `4x4n2o`;4x4, rotating 3x3 blocks `4x4n3`;5x5, rotating 3x3 blocks `5x5n3`;6x6, rotating 4x4 blocks `6x6n4`。

> 宽高从 2 起是**避崩**,不是调优:上游只查 w·h ≥ 2,放行 1×n;但钳位那句写的是 `if (bw < 2 && w >= 2)`,宽是 1 时不触发,base 边长留在 0,扩展因子一动就死——真机上 1×7 往上加一档即 wasm abort(random.c:275 `bits < 32` 断言),之后连 midend_serialise 都断言失败。两维都 ≥ 2 时 base 必 ≥ 2×2,294 组抽样生成全过。

> 扩展因子的行为已逐条实测清楚:矩形个数只由 **base 面积**决定,与 base 形状无关(面积 16 时 4×4 出 7.1 个、8×2 出 7.6 个、16×1 出 6.8 个);e 只通过 base_w / base_h 两个整数影响生成(expandfactor 在 rect.c 里只出现在 1165、1167 两行),所以同一对 base + 同种子 = 逐字节相同的局面。跨棋盘对齐粒度的公式:想要 base b1×b2,则 e ∈ ( max(w/(b1+1), h/(b2+1)) − 1 , min(w/b1, h/b2) − 1 ],base 为 2 的那一维不参与上界(钳位让它到 +∞)。验证过 base 6×6 在 6×6 / 12×12 / 24×24 / 48×48 上矩形数都是 11.0–11.2。

> base 缩到最小(2×2)之后 e 再大也逐字节相同,那一点是 e > max(宽, 高)/3 − 1(边长掉到 2 需要 边/(1+e) < 3),100 宽的棋盘是 32.3。**e 因此是个跟着棋盘变的量**:同一个 e 在 7×7 上已经到底,在 100×100 上才走了 1/16。而且 e 只通过那一对 base 影响生成,**落在同一对 base 上的 e 是同一个输入**——真机验过:7×7 种子 #1,e = 0.2173 / 0.3 / 0.39 / 0.4 的 DESC 逐字节相同,e = 0.41 跨到 base 4×4 才换局面。上游自己也把 e 归为不持久的参数(encode_params 只在 full 时写它),等于承认它在 new_desc() 之后不再有意义。

> 所以面板上枚举的就是 **base 对**,一对一档,不再有连续的 e。档数由公式给出:`N = 宽 + 高 − 3 − C`,`C = max(0, gcd − j + 1)`,`j` 看 `min(宽/gcd, 高/gcd)`:等于 1 取 3、等于 2 取 2、≥ 3 取 1。(推导:`⌊边/s⌋ = k` 成立于 `s ∈ (边/(k+1), 边/k]`,所以一维的分界点是 `s = 边/k, k = 3..边`;`宽/k = 高/m` 当且仅当 `k = j·宽'`、`m = j·高'`。)短边整除长边(含正方形)时 N = 长边 − 1;互质且短边 ≥ 3 时 N = 宽 + 高 − 4。100×100 以内:最少 1(2×2)、最多 **195(100×99,唯一)**、平均 95.6,44% 的棋盘超过一百档。

> 每一档的 e 是算出来的不是扫出来的:两维的分界点 `1+e = 边/k` 并起来,每个分界点取到它下面最近的可表示值(区间左开右闭,往下取才落在里面;分界点本身和它下面一格都试,因为单精度除法正好落在分界点上时往哪边倒说不准),再按 e 递增对 base 对去重。全部 4950 块棋盘对过账:**没有一块比公式少**,19 块比公式多一档——那是上游单精度除法多切出来的一级,真机上确实是另一个局面(18×6 在 e = 0.2 处 `(float)18/1.2 = 14.999999`,base 14×5,DESC 与左右两档都不同)。另抽 398 块棋盘与密扫对账:不漏、严格递增、六位有效数字、无重复。

> **这一档的 SSOT 是 e**:存档的 CPARAMS、Game ID、C 侧的 `game_params` 里只有它;base 对是每次由宽高现算的一张表,不落盘。`e → base` 是全函数、和引擎逐位一致;`base → e` 是从一对多里挑代表。所以 `base → e → base` 是恒等(表里每一档都是这么验出来的),`e → base → e` 不是——`7x7e0.3` 落在 base 5×5 的区间里,而那一档的代表是 0.399998。今天连这一步规范化都不做:表外的 e 直接回第一档。要保住 Game ID 的意图,规则得改成「先按 base 对认,认不到再回第一档」。

> e 只能带六位有效数字:上游用 `%g` 把它回显进参数框(196),多了回来就变样,再落定时会被当成表外值。整数部分占几位小数就少几位,所以档位代表值最多六位小数。

> base 面积 ≥ 6 的下限:一局的题目内容就是 base 那块板的题,最终尺寸只决定矩形画多大、数字乘多少倍,矩形数只看 base 面积(2×2 → 2 个、3×2 → 2.9、3×3 → 3.7、4×4 → 7.2、7×7 → 14)。base 2×2 永远是整盘切两半,上游手册也说 e 太高 the game becomes trivial,所以棋盘的最低线也管 base。不给 base 套 4:1:base 的比例本来跟着棋盘走,只是下整除偶尔多出一点(最大 5.5:1,全部 46 575 档里 723 档、都夹在合法档中间),硬套会在 101 块盘的滑块中间挖洞。

> 换棋盘时表外的 e 一律回到第一档(e = 0,base 就是棋盘本身),不吸到最近的一档——整套枚举都换了,旧的 e 落在新表哪一档都没有意义。注意只改短边时,如果那个 e 在新表里仍然是某一档(长边的分界点没变),它会留在原地:范围模型只看得见「值在不在表里」,看不见「谁变了」。

> 耗时全部来自唯一解求解器,失败会把整局作废重生成,尾巴很长:原生 30 个种子,50×50 平均 0.28 秒最坏 0.75 秒,70×70 平均 1.84 最坏 6.29,100×100 五个种子平均 10.5 最坏 15.0。关掉「Ensure unique solution」后 100×100 只要 0.027 秒。

预设:7x7 `7x7`;9x9 `9x9`;11x11 `11x11`;13x13 `13x13`;15x15 `15x15`;17x17 `17x17`;19x19 `19x19`。

> **定下来的**:宽高 2..16 逐整数、4:1 互推、面积 ≥ 6,同 Sixteen;墙的比例 0.1 一档,同 Net;打乱步数 0..w+h−2,门复用 Sixteen 的;「Walls wrap around」原样。上游没有别的约束,生成毫秒级(见下),全部是设计判断。

> 上限 16 是按「复原步骤数的规律」定的,不是照抄 Sixteen:操作方式与 Sixteen 相同(整行整列环形滚动,逐行解法照搬,中心行列钉死只是多个绕法),但每格代价不一样。Sixteen 每块只有一个家,路程 ≈ (w+h)/4,总步数 ∝ wh(w+h);Netslide 的管子只有 14 种形状(生成器不出十字,355),同形可互换,目标格拿最近的一根就行——密度 ρ ≈ 1/14 时最近一根的期望距离 ≈ 0.63/√ρ ≈ 2.5 格,与棋盘大小无关,加上逐行法每块固定的两步绕行,每格 ≈ 5 次滑动,总数 ∝ wh,是 Net 的线性规律、七倍的常数:16×16 约 1300 次、25×25 约 3100、49×49 约 12000。owner 看过这组数定 16。

> Sixteen 没有的一项:判胜只看「全部格子从中心连通」(1181-1196),不要求回到原排列;接口总数恰是 2(wh−1),全连通摆法必是一棵生成树。b = 1 时没墙的邻边正好是原树的边,目标排列唯一,游戏退化成目标已知的 Sixteen;b = 0 时玩家要自己先想出一种用得完手里这堆管子的摆法,棋盘越大末尾越难凑——这是思考量,不进步数,也算不出来。上游预设里 b=1 是 easy、b=0 是 medium、b=0 加环绕是 hard(166-176)。

> 偶数边放行(4×4 是上游预设):中心格取 (宽/2, 高/2),偶数边时偏右下一格,上游本来就这样。下限用上游的 2,没有跟 Net 抬到 3:Net 那个 3 是因为上游最小是 1、1×n 退化成一根直管;这里 2×n 钉死中心列后还有 w−1 列可滑,成题。

> `Barrier probability` 背后是个**整数墙数**:候选边 = 生成树用不到的边,而格子恒是一棵生成树(`宽×高−1` 条边),所以候选数是定值——不环绕 `(宽−1)(高−1)`,环绕 `宽×高+1`。公式推的,实测七组逐个对上(5×5=16、10×7=54、2×2=1、20×13=228;环绕 5×5=26、10×7=71、2×2=5)。小盘上档位会塌(3×3 不环绕只有 4 条候选边,0.1 和 0.2 都是 0 堵),和 Net 一样不附墙数。上游还特意让墙的选取「加量不换旧的」:同种子下把 b 调大,新墙是旧墙的超集(616-624)。**墙越多越简单**。

> 打乱步数上限 w+h−2 = 能滑的行列数,原则同 Sixteen 的 w+h(行列总数),这里中心那一行一列钉死。核对过:把上游 N 步打乱出来的局面对照全状态 BFS 的真实最优解(解 = 任意全连通局面),N = w+h−2 时最优仍等于 N 的占 3×3 70%、4×3 74%、4×4 77%、5×2 63%,与 Sixteen 在 w+h 时的 58% 同一档;N = w+h 时分别 36%、49%、62%、44%;3×3 从 9 步起 0%。b=1 与 b=0 的曲线在 3×3 上几乎重合(满墙下全连通摆法只有原来那一种)。

> **耗时完全不是约束**:没有求解器,生成 = 造一棵生成树 + 随机滑几下。原生每组 10 个种子:100×100 默认(打乱 19602 步)25 ms,100×100 环绕 + 满墙 27 ms,100×100 打乱一百万步 0.56 秒。

> 打乱程度实测(错位比例,20 个种子;约 90% 是随机基准——管形只有十几种,随机排列也会撞上一成):5×5 在 m=20 已到 81%、m=50 到 86%(默认 32 步是 86%);10×10 m=50 到 86%(默认 162 步 90%)。比 Sixteen 混得快得多——一次滑动就动一整行/列。

> 小盘不出事:2×2 只有一行一列可动,上游那个「被拒就重抽」的打乱循环在这种盘上照样终止(异侧方向的移动永远不会被判成撤销或重复);2×2 / 2×3 / 3×2 各自加环绕、加满墙、m=1,15 组 × 10 个种子全部正常返回(2×2 已在面积 ≥ 6 之外)。上游**没有** Net 那条「环绕 + 宽或高为 2 就拒」的检查(那是 Net 唯一解求解器的要求,Netslide 没有求解器)。

> Game ID 里 `wrapping` 和 `movetarget` 是持久参数(不带 full 也编码,251-254),`barrier_probability` 只在 full 时写(249)——和 Rectangles 的 e 同一待遇:上游认为墙的比例只在生成时有意义。

预设:3x3 easy `3x3b1`;3x3 medium `3x3`;3x3 hard `3x3w`;4x4 easy `4x4b1`;4x4 medium `4x4`;4x4 hard `4x4w`;5x5 easy `5x5b1`;5x5 medium `5x5`;5x5 hard `5x5w`。

> 操作数和难度都是线性的,不构成上限:判胜只比对黑格(1493-1503),点可选,一次拖动涂一段,操作数 ≈ 黑段数;生成是「随机数 → 3×3 平均 → 中位数阈值」,黑白各半、成片成块,一行黑段约 (w+1)/8,整盘 ≈ wh/8,把点也涂上翻倍到 wh/4(15×15 约 30–60、30×30 约 110–225、45×45 约 250–500)。题目按构造只靠单行单列推理就能唯一确定(不猜不回溯),人也是逐行扫,每行的推理量随行长和段数涨但没有指数环节,难度 ≈ 面积 × 扫的趟数。

> 生成是**拒绝采样**(`generate_soluble`,667-726),一轮三步,任何一步不过就整轮重来、没有修补、没有次数上限:① 造图(`generate`,251-343):每格一个随机数 → 一次 3×3 邻域平均 → 取**中位数**当阈值,正好一半格子涂黑;② **不许有整行或整列纯色**(686-713),但该维 ≤ 2 时跳过,上游注释:「otherwise nothing will ever be successfully generated」;③ **只靠单行单列推理就要能唯一确定**(`solve_puzzle`,510-665):反复调 `do_row` 推到不再变化,还剩一个 UNKNOWN 就算失败,不猜不回溯。每轮成本很小——造图 O(wh·log wh),`do_recurse` 用 minpos/maxpos 两组区间做了记忆化、一行 O(段数 × 长度²),整张传播到不动点毫秒级(40×40 每轮约 0.5 ms)——所以耗时 ≈ 尝试次数 = 1 ÷ 通过率,**两头各有一条判据会塌**。

> **失效方式一:短边小 → 死在第 ② 步。** 一行 w 格整行纯色的概率 q 实测:w=3 → 0.60、4 → 0.42、5 → 0.30、6 → 0.21、8 → 0.11、10 → 0.056、15 → 0.010、20 → 0.0017、≥25 → ~0。整盘要**每一行都不纯色**,概率 ≈ (1−q_短边)^长边:**底数由短边定、指数是长边,与面积无关**。3×30 只有 90 格,概率 5×10⁻¹³,跑满 300 秒不出结果;10×100 有 1000 格,概率 3×10⁻³,只要 0.1–0.5 秒。q 为什么这么大:一行 3 格若是独立抛硬币纯色概率只有 0.25,是那次 3×3 平均(上游**故意**抹出成片黑白块)加上中位数阈值把它抬到 0.60 的。上游的 `w > 2` 守卫等于承认这个问题,只是门槛定低了。(纯色行彼此不独立:每盘纯色行数的方差是二项分布的 1.4–1.6 倍,所以真实接受率比 (1−q)^h 高 3–200 倍,越稀有差得越多。)5 宽的长条就踩在这条悬崖上:5×30 = 0.17 秒、5×50 = 11 秒(6×50 只要 1 秒);套上 4:1 之后 5 宽只到 5×20,这一档自然消失。

> **失效方式二:面积大 → 死在第 ③ 步。** 通过率随**面积**指数衰减:图上任何一处局部歧义(典型是 2×2 开关,`#.`/`.#` 与 `.#`/`#.` 的行列线索完全一样,单行推理分不出)就让整张作废,这种局部事件近似独立、数量 ∝ 面积,所以 P(全图没有一处卡住) ≈ e^(−c·面积),行越长线索越松 c 还略涨。实测 20×20 43%、30×30 10%、35×35 2.7%、40×40 0.27%、44×44 0.067%、≥46×46 一千五百轮零通过,**面积每多约 115 格通过率减半、耗时翻倍**。尝试次数是几何分布,同尺寸不同种子差几十倍,超过两倍均值的概率恒为 e⁻² ≈ 14%,尾巴无上界。

> 第二轮的计时(本机原生,每格 6 个种子,四个进程并行各占一核;owner 的机器快两三倍、浏览器里 wasm 慢一半到一倍,两下抵消):40×50 均值 3.0 秒 / 最坏 4.4;50×40 1.7 / 4.2;**45×45 3.8 / 10.0**(2.6、8.7、10.0、0.5、0.5、0.6);45×50 17.6 / 39.2(0.7 到 39);50×45 17.9 / 30.8;50×50 83.2 / 124.7(58.8、112.8、16.7、96.3、90.1、124.7)。第一轮的旧数同一量级:44×44 = 2.0、46×46 = 8.4、47×47 = 13.4、48×48 = 44.7。45 以内没有一格均值过 5 秒;45×45 那条尾巴(约每七局一局超过 8 秒)是 owner 接受的。

> 下限 5 也是踩着悬崖定的:6×50 要 0.9–1.2 秒,5×50 要 11 秒(差十倍),4×50 与 3×30 直接跑不出来。可读性:线索是文字,画出来是 `1.2×长边 + 4` 格(线索区 `TLBORDER(d) = d/5 + 2`,35、42-43),长边 45 时 1440×900 桌面上每格约 15 px、线索字约 9 px(50 时 14 px / 8 px);长边 100 那种长条虽然生成只要 0.1 秒,每格只有 7 px、字 4 px。

> **Jigsaw 与 r = 1 是同一件事**:勾选框没有自己的字段,状态就是 `params->r == 1`(471);勾上时 C 侧把 c := c·r、r := 1(503);生成器只在 r == 1 时切不规则块(3698);存档串 r > 1 写 `CxR`、r == 1 写 `Nj`(416),题面还多带一段块结构(3395、3404),读档、判胜、画线同样按 r == 1 分叉(4104、4174、5042)。所以行数不给 1 这一档:勾着 Jigsaw 时钉死 1、整行不画,勾掉时从 2 起。注意是**行数**不是列数——列数 = 1 本身是非法的(516),只有勾着 Jigsaw 时因为先做了乘法才存在。

> **勾选与取消都不动列数**,只有当它落在新表外时才被吸到最近的一档(并列取大):4×2 勾上 → 4 Jigsaw,勾掉 → 4×2,列数一直是 4;3×2 勾上时 3 不在 Jigsaw 的 4..12 里,被吸到 4;9 Jigsaw 勾掉 → 行数先取最小的 2,9×2 = 18 阶在范围内,列数就保持 9;若当前的阶数上限放不下,列数会先被夹小再配行数 2。勾掉时列数的表上限是 ⌊阶数上限/2⌋,所以行数的表永远不会空。这一下本来就不可逆(3×3 → 4 Jigsaw → 4×2),是 owner 定的:规则一致比往返一致重要。

> 「整行不画」是范围模型新加的 `hide`:上游已经拿别的控件表达了同一件事时,这一行不给第二个入口。不能靠「表空」来隐藏——空表会退回文本框(check-custom 第一条);隐藏时表只剩一档,值照旧由 settle 钉住。Sixteen 那扇「门」是下游自己造的开关,这里的开关是上游自己的,所以不用新控件也不用新文案。

> **列数与行数走互推**,和 Net / Fifteen 那几个一样:两个数对调只是把棋盘转置,约束又是乘积 c·r ≤ 上限,所以它们是对等的两根滑块——档位都是「配得上某个合法对手」的全表(没勾 Jigsaw 时 2..⌊上限/2⌋),动一根,另一根被推到乘积不超上限的最近一档;窗口空了(对方是 Game ID 带进来的表外值)就回落到全表,否则两边都推不动,会留下一个上游不收的组合。勾了 Jigsaw 不是另一套机制,只是行数多了一条限制(钉死 1),于是列数的全表变成阶数本身。

> **Killer 时对称被钉死**:`symmetries()` 全文件只有一处调用(3823),而 Killer 分支在 3743 就 `break`/`continue` 了,所以勾了 Killer 时生成一次都不读对称。范围模型为此加了 choices 控件的 `pin`:给出数字就把值写死并整行不画,给 null 就是普通的分段按钮。钉的值是 0(无对称),与上游 Killer 预设一致(324),这样参数串是 `3x3ka…`,预设那一栏能正常高亮。

> **面板顺序**:Solo 是第一个申报 `types.order` 的游戏,把 Jigsaw 画到列数上面(决定行数画不画的开关,得排在它管的东西前面),其余四个照上游。`order` 只换画的顺序:controls 是与 C 共享的活对象,提交是按下标回填的(`engine/deal.worker.ts:93`),数组本身换位会让值整体串位。没列到的控件排在最后,好让上游将来新增的控件不会凭空消失;check-params 顺手验 label 认不认得到、有没有重复或遗漏。

> **阶数上限按难度分档**(非 Jigsaw):Trivial / Basic 30、Intermediate / Advanced 25、Extreme / Unreasonable 16,勾了 Killer 一律取小的 9。依据是验收那一行要求难度**恰好等于**所选档(3864),而不是「不超过」:档越高,每次试解越贵,验收不过整轮作废的机会也越大。Advanced 加的集合消元要枚举一个区域里数字的全部子集,组合数是 2 的阶数次方——阶数每加一翻一倍,与面积无关;Extreme 的强制链是 O(n⁵);Unreasonable 靠递归猜测,没有上界。Trivial / Basic 那两档只随盘面平缓变慢(主项 ≈ n⁷/8,来自删提示循环:调用次数 ≈ 面积/轨道大小,每次全扫 O(n³)),所以不另设上限,30 就是两个因子都 ≥ 2 时乘积的天花板(31 是质数)。

> **Jigsaw 阶数 4..12,不分难度**。它的耗时由「切法重试」主导:每一轮都要重切一次块(`divvy_rectangle`),而 `divvy` 只保证等大连通,不保证存在满足行列块三重约束的填法;一次填盘失败要烧掉 `面积² = n⁴` 步、每步 O(n³),约等于同阶删提示全过程的十二倍,而且失败会连块结构一起作废重来。难度只作用在删提示那一小部分,所以在 Jigsaw 上几乎失去杠杆——13 阶起无论哪一档都是分钟级,12 阶各档都还行。下限 4:2 阶的盘只有 4 格,过不了全局的「面积 ≥ 6」;3 阶被上游强制降成 Trivial(3672)。2 阶顺带吸收掉两条原本要单列的禁忌——2 阶 Jigsaw 配 4 向旋转 / 4 向镜像 / 8 向镜像(四个格并成一个轨道,提示恒是满盘,题面 11 字符、预算 10,断言必停)和 2 阶 Killer(笼子和零信息必然多解)。

> **2×2 只在「无对称」和「2 向旋转」下给**。断言够得着的只有阶数 ≤ 5:面积 ≤ 26 时预算是 `面积 + 1`,而每个提示要占两个字符(数字 + 分隔符);阶数 ≥ 6 起 `count ≥ 2`,预算翻倍就够了。所以能不能越界只取决于终局还剩几个提示:4×4 的盘留 6 个是 13 字符(安全),留 8 个就是 17 字符,正好等于预算,而断言要求**严格小于**。删提示是按对称轨道整组删的,于是分水岭在轨道形状:轨道 1 格(无对称)或 2 格且两格不共行不共列(2 向旋转、2 向对角镜像)时能一格一格啃到 4–6 个提示;轨道 4 格或 8 格时一刀太大,删到剩 8 个之后下一刀会剩 4 个或 0 个,4×4 的题在只有块内消元时撑不住那么少的提示,于是停在 8 个;左右镜像虽然也是 2 格,但两格在同一行,那一行的排除力一下子掉两成、块内消元推不动,同样停在 8 个。这条是穷举证过的,不是采样:288 张 4×4 完整盘 × 八种对称 × 所有删除顺序,判定用上游自己的 `solver` 和 `encode_grid`,安全那三档的最长题面是 13 字符、留了 4 个字符余量。2 向对角镜像穷举下来也安全,一并去掉是**从简**——上游预设清一色 2 向旋转,没必要为它放宽。

> 2×2 与 3 阶以下的 Jigsaw 上游会把难度强制降为 Trivial(3672),面板上仍能选别的难度,拿到的是 Trivial;Jigsaw 的下限 4 已经把后一半排除掉了,2×2 还在。

预设:2x2 Trivial `2x2`;2x3 Basic `2x3db`;3x3 Trivial `3x3`;3x3 Basic `3x3db`;3x3 Basic X `3x3xdb`;3x3 Intermediate `3x3di`;3x3 Advanced `3x3da`;3x3 Advanced X `3x3xda`;3x3 Extreme `3x3de`;3x3 Unreasonable `3x3du`;3x3 Killer `3x3ka`;9 Jigsaw Basic `9jdb`;9 Jigsaw Basic X `9jxdb`;9 Jigsaw Advanced `9jda`;3x4 Basic `3x4db`;4x4 Basic `4x4db`。

- **上游**(`mines.c`):
  - ≥ 1(305-308)
  - ≤ 宽×高 − 9(309)
- **本仓库的表**:⌈10%·面积⌉ .. min(⌊50%·面积⌋, 面积−9) 逐整数——密度 10%–50% 换算成绝对数,两头向内取整,实际密度恒在区间内;面积 18 以下上游的「面积−9」更紧,取小的那个。读数是个数,旁边附占比
- **依赖**:看宽高;缩小棋盘时被夹;**上限来源**:本游戏自定;**控件**:滑块 + 步进
- **默认参数下的表**:9..40(32 个)

> **这一轮定下来的(宽高)**:3..50 逐整数、4:1 互推、面积 ≥ 12,一共 1903 个宽高组合,六个预设全在里面。下限是上游自己夹出来的:勾着唯一解时两维都要 > 2(290),而雷数 ≤ 面积 − 9(309)又要求面积 ≥ 10,面积 10 是 2×5、11 是质数,两维都 ≥ 3 凑不出来,所以最小的合法盘只有 **3×4 / 4×3**;「面积 ≥ 12」这条在这里只去掉 3×3 一格。上一轮的下限是 4,理由之一是「3×n 高密度时唯一解修不出来」——那条只对**长条**成立(例子是 3×100 撒 30%),而 4:1 把 3 宽卡在 3×12 以内:3×4..3×10 的每一个合法雷数各跑 10 个种子共 1590 局,全部完成、零超时、最慢 0.005 秒,所以 3 放得回来。**雷数另见下条**。

> **雷数按密度定**:下限 ⌈10%·面积⌉、上限 ⌊50%·面积⌋,两头向内取整,所以实际密度恒在 10%–50%(面积 101 是 11..50,面积 100 是 10..50);面积 18 以下上游的「≤ 面积−9」比 50% 更紧(0.5a ≤ a−9 ⟺ a ≥ 18),取小的那个,3×4 因此只有 2..3 两档。六个预设全在范围内,最低的 9x9n10 是 12.3%。

> **10% 这个下限是渗流算出来的,不是手感**:零格(自己安全且八邻全空)占全盘 (1−p)⁹,而八邻(Moore)格点的座渗流阈值约 0.407,解 (1−p)⁹ = 0.407 得 p = 9.5%。低于这条线零格会连成一片贯穿全盘,**第一次点击就掀开大半个盘**,那不是一局游戏是一次点击。这个数还偏保守:相邻两格共享 5 个邻居,零格之间强正相关,正相关让集团更容易形成,真实临界点比独立模型算的更高。上游最低的预设 12.3% 正压在这条线上方。

> **50% 这个上限的依据是一击判定率回升**:一格翻开就把邻域全定死的概率是 F(p) = (1−p)⁸ + p⁸(就是 846 那条廉价推理在 k = 8 时的命中率),它关于 p ↔ 1−p **严格对称**——求解器的每条局部规则都是「某子集全雷」或「全空」,雷↔空互换把这一族映到自己身上——最小值 F(0.5) = 2·2⁻⁸ = 0.78%。过了 50% F 开始回升(55% 已经和 45% 一样),说明游戏在变容易;同时能翻开的格子只剩 (1−p),玩法从「翻开」翻转成「插旗」。按 F = 10% 分界(p = 25% 与 75%),10%–50% 这条带正好分成两段,而上游的两组预设各落一段:12.3 / 15.6 / 20.6(Windows 的初中高级)在 10%–25%,35.4 / 38.7 / 43.2(上游自己加的三个)在 25%–50%。

> **这条规则不解决耗时**。生成成本的峰在 42%,正落在范围内:50×50 配 1050 颗雷本机中位 8.20 秒(8 个种子,CPU 上限给到 120 秒,零超时),而且卡在**第一次点击之后**。细扫:30% 0.08 秒、34% 3.38、36% 6.44、38% 7.81、40% 8.06、**42% 8.20**、44% 7.28、46% 5.69、48% 3.67、50% 1.86、54% 1.24。峰是钝的不是尖的(36–44% 整段都在 6–10 秒),同一格 8 个种子最快到最坏只差 1.1–1.3 倍。要压得按**面积**分档,不能全局一刀切——一条全局的 34% 会同时砍掉上游那三个硬预设。这一条还没定。

> **下限与勾选框无关**:上游只有一条限制看 `unique`——`mines.c:290` 的「两维 > 2」,而且只在 `full = true` 时。穷举验过(1..12 见方 × 雷数 0..40 × 勾/不勾共 8182 组):勾与不勾结论不同的 140 组,理由全是这一条,涉及的 22 个形状全部满足 min(宽,高) ≤ 2;反方向(不勾被拒、勾上放行)0 组。所以不勾时上游能到 2×5 / 1×10(面积 ≥ 10 即可),套上 4:1 之后比我们的菜单多出 8 个 2 宽短条。没让下限跟着勾选框变:上游自己的注释说 2×n 根本造不出唯一解(那 8 个盘天生只能猜),而这要多一条规则加一次联动(手上是 2×5 时去勾唯一解,宽高得被推走),1903 → 1911 不值当。

> **耗时不落在「新游戏」上,落在第一次点击**:interactive 模式下 `new_game_desc` 只把随机种子编码进 desc(2065-2072),真正的布雷发生在点开第一格的时候(那一格决定安全区)。四十个游戏里只有这一个是这样。

> **成本 100% 来自「Ensure solubility」**:`minegen` 里勾着才走求解器 + 扰动 + 重开那条路,不勾就是随机撒雷一轮结束(1968)。实测同一组参数:100×100 撒 3500 / 4000 颗雷,勾着 >30 秒,关掉 **0.000 秒**;70×70、50×50 同样。

> **耗时是一条驼峰,峰在 40%**(不是密度越高越慢)。细扫:50×50 在 30% 是 0.059 秒、34% 4.19、38% 9.60、**40% 10.65**、44% 8.80、48% 3.96、54% 1.28;30×30 的峰也在 40%(1.56 秒)。满雷(面积−9)反而是瞬间的。按棋盘看:30×30 整条都安全(峰值 1.6 秒),50×50 峰值 10.6 秒,70×70 与 100×100 的 34–48% 段 >30 秒。

> 驼峰的成因在代码里读得出来,三条叠加:① 廉价推理只在「集合被填满或清空」时命中(`s->mines == 0 || == bitcount16(s->mask)`,846),一个有 k 个未知格的集合被一击判掉的概率是 `(1−p)^k + p^k`,k = 8 时 p = 0.2 或 0.8 都是 16.8%、p = 0.5 只有 0.78%,**中间最难**;② 开局的展开是低密度独有的红利——一格是 0 的概率 `(1−p)⁹`,10% 时 38.7%(点一下开半个盘)、40% 时只剩 1.0%,**这条只帮低密度**;③ 最强的全局雷数推理(937)有两级,`minesleft == 0 || == squaresleft`(1003)只在极端密度附近成立,而穷举所有集合不相交并那条被上游自己封在 `nsets <= lenof(setused)`、`setused[10]`(1026)——**集合超过 10 个就整条跳过**,大盘中密度时前沿很长、集合远多于 10,于是这条最强的推理根本不执行,高密度时反而跑得起来。②③ 都不对称,所以峰落在 40% 而不是 50%。推理断了就随机挑一个集合让 `mineperturb` 填满或清空(1220 附近),改不动就整盘重来(`do…while(!success)`,1865/1970,没有次数上限;试满 100 次后才允许大改,1946)。

> **100×100 配 30–50% 的雷是明知的代价**:本机 >30 秒,owner 的机器十几秒起,而且卡在**第一次点击**上。owner 看过上面这张表之后仍选择上限保持 100、雷数不设上限。要收的话最省事的一条是「长边 ≤ 50 时不限,长边 > 50 时雷数 ≤ 25% 面积」——50×50 的峰值(10.6 秒)正好卡在预算上,所以「长边封 50」等价于「雷数完全不用管」。

> 最小棋盘:勾着唯一解时是 **4×4**(本仓库的下限);上游自己允许到 3×4(面积 ≥ 10、两维 > 2),不勾时到 1×10 / 2×5。3×3 上游也拒——面积 9 时雷数上限成了 0,和「≥ 1」冲突。

> 百分比写法随文本框一起下线:滑块只出绝对数,旁边附「占比」读数;同样的雷数都能达到。上游那条 `custom_params`(266)只做换算不做钳位:9×9 输 `100%` 会被算成 81 颗然后被 `validate_params` 拒掉,不会自动降到上限 72;而 `90%` 因为整数除法截尾正好算成 72,反而放行。滑块没有这个坑。

预设:9x9, 10 mines `9x9n10`;9x9, 35 mines `9x9n35`;16x16, 40 mines `16x16n40`;16x16, 99 mines `16x16n99`;30x16, 99 mines `30x16n99`;30x16, 170 mines `30x16n170`。

> **定下来的**:宽高 2..50 逐整数、4:1 互推、面积 ≥ 6(1916 个组合,五个预设都在);色数上限统一封到 ⌊面积/2⌋;勾着「Ensure solubility」且宽 > 20 时色数下限抬到 4。「Scoring system」和「Ensure solubility」两个开关都留着,一个都不删。上一轮的宽高是 2..100 且不套比例,这一轮按全局外框(边 ≤ 50、长边 ≤ 4 × 短边、面积 ≥ 6)重定;面积 ≥ 6 在这里只去掉 2×2 一格。三色的尺寸上限仍是上一轮实测定的「宽 > 20」,这一轮没动。

> **宽高从 2 起**不是避崩:上游只查面积,1×n 能生成也不崩、还是瞬时。理由是机制退化——消完的复位是「先各列下落、再把空列整体左移」(`sg_snuggle`,1214),宽 1 永远没有列可移、高 1 永远没有格可落,两种都塌成同一个一维消除游戏。两维都 ≥ 2 之后面积恒 ≥ 4,不勾时那条「面积 ≥ 2×色数 ⇒ ≥ 4」自动满足,高的表也不用再看宽和开关了。

> **色数上限 ⌊面积/2⌋ 在勾着的时候同样成立,而且可证**:保证可解的生成器每次插两格(奇数面积开头有一次三格,24-26),所以整盘的块数恰好 ⌊面积/2⌋,能出现的颜色不可能比块多。实测在小盘上正好取等,一格不差(9 色、每格 3 个种子,数 desc 里的不同值):1×2 用 1 色、2×2 用 2、3×3 用 4、4×4 用 7、6×6 用 8–9、10×10 用 9。也就是说上游放行的那些高色数档在小盘上是死档,拖过去生成的还是同一种局面。

> **只有「三色 + 保证可解」会爆,其余整个 100×100 都是免费的。** 堵色那句是 `if (nwrong == nc) continue`(528),`nwrong` 是去重后的正交邻居颜色数,一格最多 4 个邻居 ⇒ **五色及以上永远堵不住,这是鸽笼不是统计**。实测:五色沿宽 = 100 那条边扫高 1..100,重来次数 ≤ 0.2;四色同样扫法 ≤ 8.5,整盒最坏出现在 100×100,0.21 秒(浏览器实测 0.17)。堵色概率也能算出来:邻居颜色独立均匀时,三色要 4 个邻居覆盖 3 个值 = 36/81 = 0.444,四色要 4 个邻居两两不同 = 24/256 = 0.094,五色起为 0(空格 0 也算一种「错色」,所以前沿更容易堵)。

> **三色的耗时有闭式**,两条律子相乘。① 重来是无记忆的:一轮里所有候选点都失败就 `n < 0` 整盘作废(837),`while (!ok)` 从空盘重开(864),不带任何状态 ⇒ `E[重来] = 1/P − 1` 是恒等式,上游自带的 `COUNT_FAILURES` 正好把它打出来。② 宽是唯一的指数轴,高不是:奇偶约束的条数 = 未满列的连续段数 ≤ **列数**(619-647 的扫描是 `for (i = 0; i < w; i++)`),与高无关。于是 `ln(E[重来]+1) = a·宽 + b`——高 20 时 a = 0.552、b = −1.111、**R² = 0.99935**(12 个点,宽 4..22,E 从 2.0 跨到 68302);高 100 时 a = 0.511、b = −1.245、R² = 0.995。**每加一列 ×1.7**。③ 单次尝试是 Θ(面积²)(每试一个候选点都 `memcpy` 整盘,438;轮数 Θ(面积)),实测 **1.22×10⁻⁹ × 面积² 秒**,九个点(面积 2500..10000)误差 5% 以内,且只看面积(100×20 和 20×100 同值)。合起来 `T = (1 + e^(a·宽+b)) × 1.22×10⁻⁹ × 面积²`,和独立测的墙钟对得上:高 100 时宽 12/14/15/16 预测 0.23/0.89/1.70/3.22,实测 0.24/0.84/1.59/3.19,浏览器(wasm)0.37/0.81/1.14/5.93 —— wasm 和原生同量级。四色的同一条律子 a 只有 0.022(高 10),差 25 倍,这就是三色和四色的分水岭。

> **宽 20 是 owner 定的,明知代价**:三色宽 20 的实测(每点 5 个种子,本机比 owner 的机器慢 2–3 倍)——20×15 平均 3.4 秒、20×20 4.5、20×30 7.0(最坏 25.8)、20×40 15.8(最坏 37.4)、20×50 38.1(**最坏 111**)、20×75 9.1、20×100 16.7。重来次数服从几何分布,尾巴很长,单局波动比这张表大。要收的话按公式解出来的曲线是:高 ≤ 20 给到宽 20、高 50 给到 17、高 100 给到 16,那样任何组合都在 5 秒内;owner 选了平的 20,接受高盘慢。15 那个值另有一条好处:正好保住上游最大的三色预设 15×10c3。

> **可读性**:这个游戏没有数字也没有网格线,唯一的视觉分隔是块间那道缝,而缝宽 `tilegap = (格边长 + 8) / 16` 是整除(1360)——**格边长 < 8 px 时缝宽变 0,块的边界直接不画**。实测每格像素:1440×900 上 30×30 是 24.7、50×50 是 14.3、80×80 是 9.1、100×100 只有 **7.1(无缝)**;2560×1440 上 100×100 是 12.1(有缝);390×844 手机上 50×50 就 7.1 了。按「大屏桌面为准」100 仍然过关,但笔记本屏上的 100×100 会掉到没有缝那一档;真要对得起小屏,临界点是 90。

> **「Ensure solubility」是两种玩法,不是一个生成质量开关**(所以留着)。勾着 = 谜题:目标是清空(`game_status` 只在 `complete` 时判胜,1638),盘面碎;不勾 = 街机(原版 Chain Shot):`gen_grid_random`(893)一遍撒完,块大一倍。实测(每格 30 个种子,先 400 次随机试走证「能清空」,再穷举证「不能」):10×10c3 平均最大块 5.4 对 11.0、贪心得分 168 对 472;**五色起随机盘基本清不空**——5×5c5 只有 4/30、8×8c8 是 0/30(14 局证否,贪心打完平均还剩 30.7 / 64 格),而保证可解那侧「证否」恒为 0。街机模式还是 2 色唯一的去处(勾着时上游硬性要求 ≥ 3)。

> **「Scoring system」只作用于记分**(所以也留着):`scoresub` 唯一的使用点是 `npoints`(129),只被 `execute_move`(1343)和状态栏(1596)调用;两个生成器一次都没读过它。实测同种子换计分法,desc 逐字节相同。区别只在最小的那一步:`(n-2)²` 下消两格得 0 分,而出题机器的解全程都是两格步 ⇒ **机器的解正好得 0 分**(奇数面积得 1,那一次三格步),玩家的分数字面上就是「比机器强多少」——上游注释 33-37 就是这么说的,实测限制只走两格步,5×5c3 十五个种子全部清空得 1 分、6×6c3 与 6×6c4 全部得 0 分。`(n-1)²` 没有这个零点(机器的解就能白拿 面积÷2 分),而且**分辨力更差**:同一批盘面,「200 次试走里最好的一条」比「随机走一条」拉开的倍数,`(n-2)²` 是 2.86/3.27/3.32/2.89(10×10 的 3/5/9 色、15×10c3),`(n-1)²` 只有 2.33/2.07/1.70/2.38 —— 它给每一步都加底分,把好坏差距摊薄了。顺带:每次都消最大的块得分反而更低(10×10c3 贪心 168、随机 237),这个分数是有本事含量的。

预设:5x5, 3 colours `5x5c3s2`;10x5, 3 colours `10x5c3s2`;15x10, 3 colours `15x10c3s2`;15x10, 4 colours `15x10c4s2`;20x15, 4 colours `20x15c4s2`。

> **这个游戏的成本是面积的平方,而且只看面积。** 矩阵是 `wh × wh` 字节(365),而 `new_game_desc` 把它整个 hex 编进描述(596-600,两种模式都编),所以 **DESC 长度 = ⌈面积²/4⌉ + ⌈面积/4⌉ + 2** 个字符,里面没有宽高单独出现的位置。实测面积 400 的七种形状(20×20 / 10×40 / 40×10 / 8×50 / 50×8 / 4×100 / 100×4)DESC 全是 40 102 字符,一字不差;Crosses 的耗时同理只看面积(面积 2500 的 50×50 / 25×100 / 100×25 是 0.018 / 0.017 / 0.018 秒)。

> **DESC 落在三个地方**:存档(`puzzles.save.flip`)、菜单里那行「游戏 ID」(直接渲进 DOM)、React state。对比同样 50×50:Mines 的 DESC 是个随机种子(二十来字符)、Same Game 是每格一个颜色号(5 000 字符)、**Flip 是 1 563 127 字符**。浏览器给一个站的 localStorage 约 5 MB 且全 app 共用,而 `writeSave` 是静默吞异常的——超了不报错,只是这一局重开就没了。实测:面积 3200(64×50,256 万字符)写得进但正好吃光配额,面积 3364(58×58)起 QuotaExceededError。菜单打开耗时:面积 900 是 76 ms、2500 是 398 ms、3600 是 1 228 ms、10000 是 **9 559 ms**。

> **Random 模式的生成耗时随面积指数涨**,Crosses 不涨。Crosses 是纯 Θ(面积²):浏览器里面积 1600 只要 57 ms、面积 10000 也只要 1 291 ms。Random 是拒绝采样——加完格子后要求「没有两行完全相同」,否则整个重来,没有次数上限(508-524,上游注释自己预测了这个 scalability 问题)。合起来 **T ≈ 4.3×10⁻⁷ × 面积² × e^(0.00345×面积) 秒**,两个系数只用面积 400 和 900 两点定,其余全是留出来验证的,原生实测(多种子平均):面积 100 → 0.012、200 → 0.031、400 → 0.22、600 → 0.95、800 → 4.8(最坏 11.8)、900 → 5.6(最坏 14.5)、1000 → 14.8(最坏 42.5)、1200 → 50.9(最坏 150)、1400 → 93.5(最坏 271)、1600 → 231.8。公式在这些点上偏差 ≤ 1.7 倍。同面积 1600 时 Crosses 是 57 ms,**差 4 万倍**。

> **形状只在极瘦时才有影响,幅度远小于面积项。** 面积 400 的实测(20 个种子):20×20 0.26、40×10 0.23、50×8 0.29、80×5 0.45、100×4 0.79、200×2 >30 秒、**400×1 只要 0.004 秒**。机制:Random 要加 `4×面积 − 2(宽+高)` 个格子,可加的候选有 `(3宽−2)(3高−2) − 面积` 个,两者一减正好是 **余量 = 4×(宽−1)×(高−1)**——这是生成器的自由度。余量占「要加的量」的比例:20×20 是 95%、100×4 是 85%、200×2 是 66%、1×n 是 **0**。余量越薄越容易撞上重复行;而短边 = 1 反过来最快,因为余量归零、矩阵被完全钉死,没得选也就没得拒。定下来的范围里最瘦的 40×2 只要 0.07 秒。

> **宽高从 2 起是避挂,不是调优。** 1×n 的余量正好是 0 ⇒ 矩阵被钉死,加出来必然就是十字矩阵(实测 1×3 / 1×4 / 1×5 / 1×8 / 1×20 / 5×1 换种子都和 Crosses 逐字节相同,**1×n 的 Random 根本不随机**);而 1×2 的十字矩阵两行相同,撞上「不许两行相同」⇒ **永远重来,死循环**。四个种子基各跑 15 秒都不出,与种子无关。宽高 1..8 的 48 个组合全扫过,只有 1×2 和 2×1 会挂;抬到 2 之后又把宽高 2..12 的 121 种棋盘 × 两种模式 × 各 2 个种子(242 组)跑了一遍,零出错。

> **上限 50 / 面积 1000 是 owner 定的,明知代价**:面积 1000 时 Random 平均 14.8 秒、最坏 42.5 秒,浏览器里抽到过 59.7 秒(这个分布尾巴极长,均值和单局体感差很远)。我的建议是面积 800(平均 4.8 秒)。存档那头面积 1000 只占 5 MB 配额的 10%,很宽裕——Crosses 单独看其实能到面积 1600–2500,owner 选了两种模式同一套。

> **格子里有信息,32 px 以下就糊了**:每格要画一张小图标出「按下去翻哪几格」(1152-1170),小图的格边长 `td = TILE_SIZE / 16`(不足 1 取 1),**td = 1 时退化成一坨 2 px 方块**。td ≥ 2 需要格边长 ≥ 32 px:2560×1440 上边长 ≤ 38、1440×900 上 ≤ 21、390×844 手机上 ≤ 11。Crosses 模式这张图是废话(永远是十字),Random 模式它是唯一能知道一次点击做什么的信息。边长封 50 没有卡在这条上——面积 1000 时方盘只有 31×31。

预设:3x3 Crosses `3x3c`;4x4 Crosses `4x4c`;5x5 Crosses `5x5c`;3x3 Random `3x3r`;4x4 Random `4x4r`;5x5 Random `5x5r`。

> **这个游戏没有生成成本,也没有任何危险组合。** `new_game_desc` 是 O(钉数) 一遍过;唯一的重挑发生在不勾「Allow duplicates」时(`goto newcol`),而那时上游保证颜色数 ≥ 钉数(227),期望次数是 n·H(n)——10 钉也才 29 次。真机极端组合 **10 色 / 100 钉 / 100 次:落定加画完 614 ms,零报错**;最小 2 色 / 2 钉 / 1 次同样正常。所以上限完全是可读性和游戏性的事。

> **要几次才猜得出来:99 个格子实测。** 两套独立解法互相对过表——空间 ≤ 130 万时枚举全部密码跑「随机一致」和「最小最大(Knuth)」两种策略(6 色 4 钉上强玩法平均 4.5 / 最坏 6,和文献已知最优平均 4.476 / 最坏 5 对得上);空间更大时用局部搜索找一个与全部历史反馈相符的密码来猜,在 6 色 4 钉和 10 色 6 钉上与枚举法一致。**「随机一致」的平均次数**(色数 × 钉数):2 色:钉 4 → 2.9、10 → 5.4、20 → 9.1、**50 → 17.3**;6 色:4 → 4.7、10 → 8.0、20 → 14.3;10 色:4 → 6.1、10 → 9.9、20 → **16.0**。不勾「Allow duplicates」时 10 色 10 钉是 11.0(最坏 14)。

> **次数的公式**(99 个实测点,R² = 0.978,最大偏差 2.0 次):`平均次数 ≈ 0.1 + 0.96×log₂(颜色数) + 钉数 × (0.24 + 0.12×log₂(颜色数))`——每多一个钉子加 (0.24 + 0.12·log₂色) 次,2 色时每钉 0.36、10 色时每钉 0.65。外推到 50 钉验证过一次:2 色 50 钉公式 19.3、**实测 17.3**(最坏 18)。按它算 10 色 50 钉要 **36 次**、6 色 50 钉 31 次。顺带:信息下界(⌈钉×log₂色 / log₂((钉+1)(钉+2)/2−1)⌉)完全不能当参考——它说 2 色 20 钉只要 3 次,实测 9 次;10 色 20 钉它说 9 次,实测 16 次。反馈分布远不均匀,那个上界拿不到。

> **上游预设给的次数约是平均值的 2 倍**:6 色 4 钉平均 4.7、上游给 10;8 色 5 钉平均 5.9、上游给 12。按这个手感,10 色 20 钉要 32 次、10 色 50 钉要 70 次。

> **50 / 50 是 owner 定的,明知代价**。可解性上没问题:10 色 50 钉平均 36 次,50 次给到 1.4 倍富余,而且钉数越多分布越窄(平均与十来局里最坏的差:6 色 20 钉 1.7、10 色 20 钉 1.0、2 色 50 钉 0.7),最坏大概落在 40 上下。代价在可读性:**50 钉 × 50 次时钉边长只有 12.3 px、数字 6.1 px、提示点 4.3 px**,而提示点是这个游戏唯一的信息来源(右边是 25 列 × 2 行的点阵)。另外一局要点约 1800 下(36 手 × 50 个钉子)。我的建议是钉 20 / 次数 30(钉边长 20 px、提示点 7 px,最难的角落仍有 1.9 倍富余)。

> **Random 是拒绝采样,而且拒绝的理由是几何的。** `pegs_generate` 从中心一颗棋子反向走子长出一片,然后要求这片**四条边都够到**(`extremes == 15`),否则整盘重来,**没有次数上限**。把 `pegs_genmoves` 单独抠出来跑(把 pegs.c 整个 include 进一个探针,不动 vendor 一行)量出三件事:① 那一片的**面积恒是盘面的 57%**——`nmoves < 面积/2` 之后就不再接受代价 2 的走子(1148),实测从 10×10 到 100×100、从方盘到细条全是 57%;② 它是**团状**的(生成器优先走代价 0 的子,紧凑铺开,不长细胳膊);③ 于是细长盘上它很快把短边顶满,之后只能横着长成带子,带宽 ≈ 0.57×面积 ÷ (0.87×短边) = **0.66×长边**——**永远够不到两头**。包围盒实测(每格 200 次):100×100 是 94.9×95.4(长边 95%);20×10 是 17.4×**10.0**(87%);30×10 是 24.1×10.0(80%);100×10 是 66.2×**10.0**(**66%**);100×50 是 77.4×50.0(77%)。短边那一列永远顶满,长边永远差一截。

> **要走多少步 = 面积 ÷ 2。** 反向每走一步净加一颗棋子(拿掉 1 颗、放上 2 颗),而生成停在 面积/2 步附近,所以棋子数 ≈ 面积/2 + 1;胜利条件是「场上只剩一颗」(1039-1045),于是步数 = 棋子数 − 1。真机实测:7×7 Cross 32 颗 / **31 步**(这就是经典孔明棋)、10×10 51 颗、20×20 202 颗 / 201 步、30×30 453 颗 / **452 步**、50×50 1252 颗、100×100 5001 颗 / **5000 步**。上游自己的 Random 预设最大只到 9×9。30 这个上限对应 452 步,已经是经典孔明棋的 15 倍。

> **外层的「恰好是这个难度」只在小盘上要重来,而且不会不终止**:Hard 要求「Easy 解不出来」,否则整盘重造。200 个种子实测的平均轮数:2×2 是 1.77(最多 11)、3×3 是 1.38、5×5 是 1.04、**8×8 及以上恒为 1**。另对 2×2 / 3×3 / 2×100 / 100×2 各跑 2000 个种子,全部瞬间返回。

> **耗时是边长的五次方多一点**。拟合(用 50 与 100 两点定,回代验证,40..100 之间误差 ≤ 16%):`T_easy ≈ 208 × (边长/100)^5.69` 秒、`T_hard ≈ 324 × (边长/100)^5.13` 秒。本机单种子实测(秒)——Easy:20 = 0.04、30 = 0.31、40 = 1.18、50 = 4.02、60 = 12.5、70 = 30.6、75 = 38.5、80 = 60.9、90 = 108、**100 = 208**;Hard:20 = 0.13、30 = 1.03、40 = 3.45、50 = 9.26、60 = 24.5、70 = 56.3、75 = 70.2、80 = 123、**100 = 324**。**边长翻倍,耗时乘 35–52 倍**;结构上说得通:调用次数 ∝ 面积,每次调用的成本自己也随面积长(每次 solve 从 20×20 的 77 µs 涨到 60×60 的 1676 µs),两个一乘就是面积的 2.6–2.9 次方。

> **形状几乎不影响,只看面积**:面积都约 5600 的四种形状,Easy 是 75×75 = 38.5、100×56 = 36.9、56×100 = 30.0、90×62 = 37.1 秒,Hard 是 75×75 = 70.2、100×56 = 65.8 秒——方盘略微最贵,差别 1.3 倍以内。所以要收就按面积收,别按边长:100×10 只要 0.32 秒,不该被误伤。

> **可读性**:线索是画在格点上的单个数字 0..4(永远一位),字号 = 格边长的一半(1762),外面套半径 = 格边长 1/3 的圈;画布 (边长+2) 格(BORDER = 一整格,1760)。实测字号:2560×1440 上 60 是 10.0 px、70 是 8.6 px;1440×900 上 30 是 10.5、**40 正好 8.0**、50 是 6.5;390×844 手机上 20 是 8.5、30 是 6.0。按「大屏字号 ≥ 8 px」那条线是 **75**。

> **要收的话(记着,没用上)**:`面积 ≤ 5625`(= 75 见方顶格)同时满足两条互不相干的判据——大屏可读性的 75,以及顶格 Hard 70 秒(owner 的机器约 23 秒)。更保守的一档是 `面积 ≤ 3600`(60 见方,Hard 24.5 秒)。Hard 比 Easy 贵约 1.8 倍,也可以像 Dominosa 那样按难度分(Easy ≤ 6800、Hard ≤ 5625),只换来 Easy 多七格边长。

> **栽的是哪一关,数出来了**:把 `lightup.c` include 进探针复刻内层一轮,固定时间预算里计数——卡住的组合里「唯一解」那一关几乎 100% 通过,栽的全是「低一档解不出来」(1598)。2×2 在 90% 黑格上 10 秒试了 **1234 万个布局:全部够好,一个都不够难**;20×2 2-way mirror Hard 是 167 万个,同样一个都不够难。一句话:**盘子太窄,Easy 的推理就解完了一切,更难的推理根本没有用武之地**(和 Slant 上游注释里「边长 1 做不出 Hard」是同一回事,只是 Light Up 没在 validate_params 里挡)。定下限这一轮又数了七组(90% 黑格,8 秒):3×3 的 None / 2镜 / 4镜 Tricky 分别 334 / 398 / 419 万个布局,4×4 None Hard 152 万、5×4 None Hard 121 万、5×5 2镜 Hard 106 万、5×5 4镜 Hard 158 万——**够格的都是 0 个**。唯一的反例是 4×4 4镜 Tricky:只有 15 个布局,里头就有 1 个够格,所以它反而稳。也就是说「掉到 90 档」等于真死循环,两个千分之三的种子单独跑满 10 分钟确实没回来。

> **它是一条概率带,不是一条线**:爬升路上一共只有 15 档 × 20 次 = 300 次机会,全空就掉到 90 那一档永远转。所以挂率 = 各档 (1 − 该档命中率) 的 20 次方连乘,**只要命中率不是 1 就永远大于 0**——下限只能是挑一个可接受的挂率,不存在一条干净的线。黑格 20%,按「短边」逐条数(挂数/种子数)。**短边比下限小一格**:Tricky 的 3×3 4镜 5/5、3×3 4旋 5/5、3×3 2镜 11/300、3×3 2旋 5/100;Hard 的 4×4 4镜 5/5、4×4 4旋 5/5、4×4 2旋 3/30、4×4 2镜 1/30、3×3 None 3/30、3×6 None 1/30。**踩在下限上**:Tricky 五种对称整条(短边固定、长边 s / s+1 / s+3 / s+7 / s+15 / 30 / 50 / 80,两个朝向)全 0,近方格加到 300 种子也全 0;Hard 只剩 None 的 5×4 1/300 和 4镜的 6×5 1/300,5×5 各模式各跑 1000 种子,2镜和 4镜的 Hard 各中 1 次,其余十三组全 0。**Easy 一个都没挂过**(五种对称的短边 2 那一条,近方格 300 种子全 0)。

> **为什么对称只贵一格,不是翻倍**:按基本盘(set_blacks 594-631:2-way 是 宽 × ⌈高/2⌉、4-way mirror 是 ⌈宽/2⌉ × ⌈高/2⌉、4-way rotational 是 ⌊宽/2⌋ × ⌈高/2⌉ 加中心格)推,「基本盘自己得够大」会给出 2k−1 / 2k,Tricky 要 5~6、Hard 要 7~8,和实测的 4 / 5 差得远。原因是难度判定跑在**整盘**上,不在基本盘上:整盘面积决定「够格的谜题存不存在」,基本盘只决定「可抽的黑格布局有多少个」。3×3 的可抽布局是 None 510 / 2-way 62 / 4镜 15 / 4旋 3,对应挂率 0 / 4~5% / 必挂 / 必挂;到 4×4 面积够了,4镜同样只有 15 个布局却是 0/300。

> **定下来的**:宽高都 3..100。config box 只有这两个控件——没有 choices、没有 boolean,是四十个游戏里最简单的一档。上游「面积 ≥ 6」那条自己写了理由(199-218):宝石数按格数的 1/5 算,至少得有一颗 ⇒ 面积 ≥ 5;面积 5 已被 `w,h ≥ 2` 排掉,所以实际下限是 6。下限抬到 3 之后面积恒 ≥ 9,那条永远触发不了,宽和高之间不再互相依赖。

> **生成器有两道门,只有一道有逃生门**(`gengrid` 452-580):`while(1) { 洗牌铺格 → `possgems = find_gem_candidates()` → **门一:候选格 < 面积/5 就重来** → BFS 求「任一格到最近候选格的最大距离」→ **门二:超过阈值就重来** }`。门二每失败 50 次把阈值 +1,**而且没有封顶**(Light Up 封在 90、Map 只在窗口里开),所以它一定过得去。**门一既不计数也不放宽**,是唯一的风险点——而它正是窄条慢的根子。

> **一格都不挂**:宽高 2..12 的全矩阵(120 格 × 10 种子 = 1200 次)全过,2.5 秒跑完。窄条也不是死循环:2×100 单独给十分钟,两个种子分别 169 / 173 秒**回来了**。

> **机制**:门一要的候选格是球滑行能停住的位置;条带越窄球的活动越受限,候选格越稀。一条长 L 的窄带上每一小段都得独立凑够候选格,概率大致是 p^(L/k),对长边指数衰减;而门一没有逃生门,所以耗时就是 1/概率。上游自己的三个预设(10×8、15×12、20×16)全是 4:3 上下,一个窄条都没有。

## 六、已知问题

- 本文档里的耗时数字全部测自一台共享的 2.8 GHz Xeon(开发容器),比现代桌面 CPU 慢两三倍——同一组参数 owner 在自己机器上实测能快到三分之一。逐个游戏定范围时按这台机器的数字取,偏保守。
- 生成已经不在主线程上了:`src/engine/dealer.ts` + `deal.worker.ts` 把三条会走到 `midend_new_game` 的路(New Game、选预设、自定义参数)全部交给一个镜像 worker,主线程那一局在镜像算完之前一动不动,超过 0.4 秒弹一个可取消的对话框。所以「参数大」现在是转圈等,不是页面变砖;取消即原地不动,连 undo 栈都在。还没定夺范围的游戏只记录,不为耗时调低上限。已知最慢的几处:Loopy(尤其 Penrose / Hats / Spectres 网格)、Solo 高阶(31 阶 Unreasonable 几乎不会结束)、Slant 100×100 Hard(本机 324 秒)、Untangle 100 点、Map 大盘多区域、Bridges / Tracks / Galaxies 100×100。
- **Mines 是唯一一处镜像盖不到的卡顿**:布雷不在「新游戏」里,而在**第一次点击**(要保证第一格不是雷),走的是 `midend_process_key`,不经过镜像那三扇门。真机实测 100×100:3000 雷(30%)卡住主线程约 4 秒、5000 雷(50%)超过 33 秒,全程没有转圈对话框。owner 看过实测后仍选择上限 100、雷数不设上限——那一下卡的是点击,不是开局。
- **已定夺的游戏里最慢的两个是 Pattern 和 Slant**,两个都是 owner 看过逐档实测后选择不设上限的:Pattern 顶格 50×50 本机平均 >70 秒(要收的话「面积 ≤ 2100」正好只砍掉 45×50 和 50×50 两格);Slant 顶格 100×100 是 Easy 208 秒、Hard 324 秒(要收的话「面积 ≤ 5625」= 75 见方,和大屏字号 8 px 那条线重合)。两个现在都由镜像扛着,卡的是等待不是页面。
- 发牌期间存档不会写坏:镜像算的时候主线程那一局没被碰过,取消或失败都只是「什么都不做」;重开页面恢复的也是上一局(存档按序列化的局面存,不重新生成)。Mines 那一下仍是主线程,卡住时同理不写坏。
- 每次松手都开一局:在滑块上用方向键连按,每按一下都生成一局。
- 另一类不是「大」而是「小到无解」的不终止:Galaxies 3×3 Unreasonable、Solo 2×2 Killer + X,上游生成器死循环重试(galaxies.c:1456)。这几处上游放行、表也放行,还没定夺的先只记录;二阶 Solo 配对称 / Killer 与 Penrose 最小尺寸那几处因为一碰就死,已按第四节收窄。Light Up 那一片按第四节的下限收过了,但 owner 取的 2/3/4 仍留着 4-way 对称的几处:Tricky 的 3×3(必挂)、3×4(9/30),Hard 的 4×4(必挂)、5×4(2/30)、6×4(6/30);黑格比例 70 以上也还有一到三成会挂。要清干净的补丁写在 Light Up 那一节。
- Solo 勾了 Jigsaw 之后,行数滑块每拉一档阶数就翻倍(上游语义,C 侧把两数相乘)。表允许,因为上游允许;要不要在界面上钉住行数,等定 Solo 的范围时再说。

## 八、实现

范围模型落地为控件,动到的文件:

- `src/pages/puzzle/ParamField.tsx`:范围模型驱动的数字行。滑块按表的下标走,两侧 −/+ 单步,读数在行尾;区间型两行(最少 / 最多)。拖动只改读数,原生 change 才落定,方向键每按一下落定一次。
- `src/pages/puzzle/ConfigFields.tsx`:拿到范围模型后,有申报且表非空的 string 控件交给 ParamField;choices 控件画成分段按钮、申报了 ordinal 的画成滑块;每次落定(滑块、步进、checkbox、分段按钮、回落的文本框)先 `settle` 再提交。没给模型的调用方(偏好面板、模态对话框)行为不变,仍是下拉。
- `src/pages/puzzle/PuzzleTypes.tsx` / `PuzzleHost.tsx`:把当前游戏的 `types.params` 传进面板;参数列表常驻,选中态只认引擎报的那条预设(不命中就一条都不选),点预设走「让位、换参数、再要一份」三步。
- `src/ui/Dock.tsx` / `useMedia.ts`:够宽的桌面上类型面板停靠成右侧栏(360px),棋盘让出宽度而不是被盖住;非模态,面板开着照样能走子。
- `src/index.css`:`.sheet-custom .dialog-param*`,颜色全部走 tokens,两种主题同一套规则。
- `src/i18n/en.json` / `zh.json`:`types.min` / `max` / `decrease` / `increase` 四个键(区间小标与步进按钮的读法)。
- `scripts/check-custom.mjs`:playwright 走真实链路——四十个游戏的自定义面板没有文本框、动一档即开新局、Mines 缩到最小雷数被夹、Twiddle 短边缩小时旋转块跟着降、Black Box 最少拉过最多时最多跟上、Mines 翻 Ensure solubility 时宽从 1 回到 3、步进按钮加一,全程不出错误 Notice。
- `scripts/build-params-doc.mjs`:本文档的生成器,手写源在 `scripts/lib/params-doc.mjs`;第七节的结果表每次生成时当场跑 check-params 得到。
