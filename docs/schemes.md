# 三套交互方案，以及每个屏幕按键属于哪一套

这份文档是下一阶段的地基：把「交互方式」做成一个游戏级的设置之前，先得知道**每一个屏幕按键
到底为谁而存在**。它做两件事——

1. 逐条核对**键鼠**那一套有没有被我们挡住或改掉（第一部分）；
2. 把**全部 315 个屏幕按键**分成四类，一个不漏（第二、三部分）。

上游事实以 `vendor/sgtpuzzles` 的 `3c36322` 为准，输入表见 `docs/inputs.md`，每个游戏现有的
入口见 `docs/coverage.md`。

---

## 〇、三套是什么，以及「必需」怎么判

| | 是什么 | 占屏幕吗 | 可关吗 |
| --- | --- | --- | --- |
| **A 键鼠** | 鼠标点棋盘 + 真键盘。上游原本的那一套 | **不占**——一个屏幕按键都不画也能全玩 | 不可关 |
| **B 基础触摸** | 棋盘手势（点击＝左键、长按＝右键、长按后拖＝右键拖拽）+ 手势够不着的那些按键 | 占 | 可关 |
| **C 方向键** | 屏幕内的方向键 + 旁边的功能键 | 占 | 可关 |

**C 存在的理由不是「B 做不到」，是「B 会点错」**——复杂棋盘上格子只有几毫米，手指戳得到但戳
不准。所以 C 必须**自成一套**：不碰棋盘也能把一局玩完。这条假设决定了下面每一个「方」的判定。

### 「必需」的判据

一个按钮是**必需**的，当且仅当：**没有它，某个上游允许的棋盘状态就到不了。**

一个按钮是**辅助**的，当且仅当：**它做的每一件事，你都能用别的按钮或手势一步步做到**，它只是
更快。提示（`h`）、自动补候选（`M`）、我们那三个铅笔键、求解器重放、dominosa 的高亮数字，全部
落在这一边——它们都不产生「否则到不了的状态」。

按这条判据分四类：

| 记号 | 意思 |
| --- | --- |
| **触** | 只有 B 需要它 |
| **方** | 只有 C 需要它 |
| **两** | B 和 C 都需要它（同时出现在上面两类里） |
| **辅** | 两套都不是非有不可 |

**「两」这一类是这份文档最要紧的产物**：它们必须在「只开 B」和「只开 C」两种设置下都显示，
只有两套全关才收起来。

## 一、键鼠：上游的能力有没有被我们挡住或改掉

结论：**没有。三处差异，都不减能力**，逐条列在下面。

### 键盘通道

我们的画布把按键原样转给后端，参数和上游 `emccpre.js:405-409` 一一对应：

| 上游发什么 | 我们发什么 | 差在哪 |
| --- | --- | --- |
| `event.keyCode` | 同 | — |
| `event.key` | 同 | — |
| `event.char` | **空串** | `event.char` 是早就从浏览器里删掉的属性，现代浏览器一律 `undefined`，所以上游发的也是空。而 `emcc.c` 只在 `key` 全部匹配失败之后才去看 `chr`（`emcc.c:434`），那是给旧浏览器留的后路，`key` 现在能认全 |
| `event.location` | 同 | 小键盘数字因此仍然带 `MOD_NUM_KEYPAD`，cube 和 inertia 的八个方向没丢 |
| `shiftKey` / `ctrlKey` | 同 | 所有带修饰键的能力都在：net 的移原点/移信号源、pattern 的三色刷、range 的沿途标白、tents 的 `Ctrl` 打叉、sixteen 的两档滑、palisade 的画墙、bridges 的一按架桥、`Ctrl+Shift+Z` 重做 |

画布带 `tabIndex={0}` 拿得到焦点，右键菜单被 `onContextMenu` 挡掉（和上游
`emccpre.js:332` 同一件事），所以右键、中键都到得了后端。

**我们多加了一条，不是少了一条**：`u`／`r`／`n` 在**窗口**上也监听一次，这样焦点不在棋盘上时
这三个快捷键照样有效。它先看 `e.defaultPrevented`——棋盘已经处理过就不再处理，否则一次 `u` 会
撤销两步（实测过）。而且它是把**按键**交给后端，不是替后端决定动作，所以在把这三个字母另作他
用的游戏里，它说的话和棋盘上说的一样。

**`Escape` 只在有 sheet 打开时被截走**，而那时棋盘本来就不在操作中；没有 sheet 时它照常送到
后端，所以 filling 的「取消整个选择」在键盘上是通的。

### 鼠标通道

我们走 pointer 事件（触摸和鼠标共用一条路），`pointerType === 'mouse'` 那一支的按钮映射和上游
`emccpre.js:363-367` 逐字一致：

```
button = e.shiftKey ? 1 : e.ctrlKey ? 2 : e.button      // Shift→中键，Ctrl→右键
if (e.button >= 3) return                                // 第四第五个键不管
```

**唯一一处真差异：同时按住两个鼠标键。** 上游按**物理按键**记三个槽（`button_phys2log[3]`），
拖动时把所有按下的键**或**在一起；我们按 `pointerId` 记，而一个鼠标只有一个 `pointerId`，所以
先按左键再按右键会覆盖前一个。四十个游戏的 `interpret_move` 全部是对**单个**按钮常量做判断，
没有一个读「两个键同时按着」，所以能力上没有损失——但这是一处真差异，记在这里免得下次当成
bug 去查。

### 不是我们的账

**`Tab` / `Shift+Tab` 在任何 web 构建里都到不了后端**：`emcc.c:363-405` 那一长串判断里没有
`Tab` 这一条，而它也不是单个 ASCII 字符。所以 untangle 的「反向循环顶点」在上游自己的网页版
上同样够不着。同理还有 KaiOS 的两个软键。

### wasm 那一侧

`build-games.sh` 换掉的是 `emccpre.js`／`emcclib.js` 这层 JS 外壳，并且用 `cmp` 校验两次构建的
`.wasm` **逐字节相同**——换外壳绝不能影响二进制。所以 C 那一侧接受的输入集合，和上游一模一样。

### 不属于任何一套：底下那四个固定按钮

**撤销 · 重做 · 类型 · 菜单**是 app 的外壳，不是某一套游戏交互。撤销和重做在键盘上是 `u`／`r`，
类型和菜单对应上游工具栏上的按钮。**三种设置下都留着**——把它们跟着 B/C 收起来，等于让「只用
键鼠」的读者没有办法换一局。

## 三、四类清点

一共 **315** 个按钮：方向键本身 156（40 个游戏里 38 个有方向键，其中 inertia 是八向：37×4 + 8），
方向键旁的功能键 65（含 4 个只在第二层出现的），键盘那一排 90，底下固定 4 个。

| 类 | 数量 | 是哪些 |
| --- | --- | --- |
| **触**（只 B 需要） | **0** | 一个都没有。凡是手势够不着的，方向键那套同样够不着，所以全部落在「两」 |
| **方**（只 C 需要） | **221** | 方向键 156，方向键旁的功能键 61（65 个里除掉 pattern 的灰、pattern 的刷、inertia 和 flood 的求解器重放），加 map 那 4 个 `aimed` 的颜色键 |
| **两**（两套都要） | **43** | pattern 的灰 1；填数字那六个游戏的数字键和清空——solo 9+1、filling 9+1、keen 6+1、towers 5+1、unequal 4+1、undead 3+1 |
| **辅** | **47** | 提示 ×7、`M` ×5、我们的三个标记键 ×15、guess 的另外 9 个、dominosa 的 7 个、net 的打乱、pattern 的刷、两个求解器重放 |

`43 + 221 + 47 + 4 = 315`，对得上。数字键的条数随棋盘大小变，上表按各游戏的**默认预设**数——
solo 是 9、keen 6、towers 5、unequal 4、filling 恒定 9、undead 恒定 3。换一个更大的预设，「两」
这一类只会变多。

**「触」是空的，这件事本身是结论**：不存在「手指点棋盘做不到、但方向键做得到」的能力。方向键
那套是**叠加**在触摸之上的第二条路，而不是补它的洞。所以：

> **凡是必需的键盘键，一定是「两」。** 判定一个键属不属于「两」，只要问一句：*有没有任何手势
> 能做到这件事？* 没有，它就是「两」。

## 四、显示规则，以及三个洞

### 显示规则

| 设置 | 棋盘 | 方向键那一排 | 键盘那一排 | 固定四键 |
| --- | --- | --- | --- | --- |
| 只有键鼠 | 收触摸 | 全收 | 全收 | 留 |
| 只有 B | 吃触摸 | 全收 | **只留「两」** | 留 |
| 只有 C | 收触摸 | 全出 | **留「两」+ map 的四个颜色键** | 留 |
| B + C | 吃触摸 | 全出 | 全出 | 留 |

两处要小心：

1. **map 的四个颜色键画在键盘那一排，但属于 C。** 「只有 B」时它们要收起来，「只有 C」时要留下
   ——这是唯一一处「排」和「套」不一致的地方。
2. **辅助键归谁？** 它们两套都不必需，但也不能在两套都开着的时候没有落点。最简单的规则是
   **跟着「有没有任何一套触摸开着」走**：只要 B 或 C 开着就显示，两套都关（只有键鼠）才收
   ——因为键鼠有键盘，`h`、`M` 直接敲。

### 洞一：guess 玩不了 C

它的方向键被整块撤掉了（`PAD_ONLY`），键盘那一排就是它的全部。所以选「只有 C」的读者打开
guess 会**什么都没有**。这是我们自己造成的，不是上游的。

### 洞二：loopy 两套都只剩手势

上游 `interpret_move` 只有三个鼠标分支，其余一律 `return NULL`，源码自己写着它不接受键盘输入。
所以 loopy 没有方向键、也没有任何按钮，选「只有 C」时它同样是空的。**这个洞是上游的**，除非
我们发明一套它没有的键。

### 洞三：C 够不着的那些能力

关掉 B 会丢掉这些——它们只有手势，方向键那套没有对应的键：

| 游戏 | 只有手势的能力 |
| --- | --- |
| netslide | 朝**外**滑（长按外圈） |
| blackbox | 揭晓（点左上角） |
| rect | 切换单独一条边（点边） |
| singles | 开关「黑格上显示数字」（点棋盘外面） |
| undead | 循环剩余计数的样式（长按上方那排计数） |
| towers · unequal · magnets · undead | 划掉外沿线索（点那个数字/符号） |
| signpost | 断开连接（拖出棋盘外） |
| filling | 拖拽累加多选 |
| tracks · mosaic · pattern | 沿整条路径刷（拖 / 长按后拖）——pattern 有「刷」模式顶上，另两个没有 |

**这份清单是「只有 C」这个选项的真实代价**，做设置之前该先看它一眼：要么接受，要么在动手做
设置的同时把其中几条补成键。

---

## 五、这份文档怎么维护

按钮清单是从**跑起来的 app 里逐个游戏 dump 出来的**（40 个游戏，读 `.keypad` 和 `.play-arrows`
里每一个 `button` 的 `aria-label`），不是从表里抄的——所以「不遗漏任何一个按键」这句话有据可依。
第二层的四个键（samegame 的取消选中、pearl 的放弃、inertia 和 flood 的求解器重放）dump 不到，
是从 `engine/keys.ts` 的 `level` 补上的。

**改了 `CURSOR_KEYS` 或 `RULES` 就要重新 dump 一遍**，和 `keys.md` 一样没有脚本会替你发现少了
一条。分类那一列则要在**升级 `vendor/sgtpuzzles` 之后**重过：上游给某个能力加一个手势，一条
「两」就会掉回「方」。
