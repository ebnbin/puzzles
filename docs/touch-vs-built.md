# `docs/touch.md` 和现在的实现对不上的地方

逐个游戏比对 `docs/touch.md`（触摸交互设计，8 月 7 日写的）和现在真正做出来的东西
（`src/engine/keys.ts`，以及 `docs/keys.md` 的全表）。

**先分清三件事**，混在一起看不出该动哪边：

- **一、被推翻的** —— 文档说 A，代码做了非 A，而且是想清楚之后反过来的。**要动的是文档。**
- **二、形状不同** —— 同一件能力，两套设计。文档给的是「跟着上游的循环键」，代码给的多半是
  「一个键一个绝对值」。**要拍板的是选哪个，不是谁写错了。**
- **三、文档设计了、还没做** —— 不是不一致，是欠账。列在这里因为它们和上面两类混在同一张
  表里，容易被当成已经做完。

`docs/inputs.md` 不在这次比对范围里，理由在最后一节。

---

## 一、被推翻的（6 处）

| 游戏 | `touch.md` 怎么写的 | 现在怎么做的 |
| --- | --- | --- |
| **Cube** | 「那个通不了的方向**不置灰**」，并给了三条理由（没有 `current_key_label`、`MOVE_NO_EFFECT` 和成功走子在返回值上一样、`midend_get_cursor_location` 没导出） | **置灰了**，而且是全集唯一一处。`src/engine/cube.ts` 在这一侧重写了上游的网格几何，`scripts/check-cube.mjs` 守着它 |
| **Map** | 「Map 没有调色板，颜色只能从别处拿，这是上游的设计……**不发明一个上游没有的调色板**」 | **发明了**：4 个颜色键 + 「可能」修饰键 + 清空，全是我们的；上游那两个「拿起颜色」的键因此取消了。理由是量出来的——最近的同色区域平均 5.6 步远 |
| **Guess** | 二类给「方向键 + 2 确认键 + 颜色键」 | **整块方向键不画**（`PAD_ONLY`）。键盘那一排就是全部：保留 · 颜色键 · `⌫` · 勾 |
| **Filling** | 二类给 2 个确认键（开关键盘拖拽 / 切换选中），三类给「取消选择」按钮 | **十字这边一个键都没有**。上游那三个管选区的键全不给——两条判据一条都不满足，而且三个里只有一个省按键 |
| **Netslide** | 确认 B 绑成「朝**外**滑」，并写明这是有意偏离上游 | **只给一个键**。反方向仍然只有右键／长按，键盘够不着 |
| **Palisade** | 「三档开关**只在 Full-grid 模式下**给」 | Full-grid 模式下**一个按钮都不给**（`cursorKeys` 直接返回空）。理由：那个模式下画墙要按修饰键，我们发不出，两个按钮会是纯谎话 |

另外一条不算推翻，但办法完全不同，值得单记：

- **Palisade 的置灰**：文档要求「光标停在格心或角上时两个键置灰」——**做到了**，但不是文档
  设想的办法。文档默认这一侧无从知道光标在哪；现在是**从每一帧画面里读**（光标框是长条还是
  方块）。文档里「文案由我们写死」那半句仍然成立。

## 二、形状不同（8 处）

文档一律照上游的「循环键」设计（点击正向、长按反向，两个确认键各管一个方向）。实现里这一族
后来全部改成了**绝对键**：一个键一个值，脚下已经是自己那个值时改成清空。

| 游戏 | `touch.md`：循环 | 现在：绝对 |
| --- | --- | --- |
| **Pattern** | 2 个循环确认键 + 笔刷三档开关 | **3 个颜色键（黑/白/灰）各自恒定** + 1 个「刷」模式键 |
| **Tents** | 2 个循环确认键 + 3 个直接设值键 + 沿途三档 | **2 个开关（帐篷 · 草）**，一格已经是自己那个值时改发清空 |
| **Range** | 2 个循环确认键 + 沿途标白开关 | **2 个开关（涂黑 · 打点）** |
| **Singles** | 2 个循环确认键 | **2 个开关（涂黑 · 画圈）**，圈↔黑一按（两条走子） |
| **Unruly** | 2 个循环确认键 + 3 个直接设值键 | **2 个开关（黑 · 白）**，六个转移每个一按 |
| **Mosaic** | 2 个循环确认键 | **2 个开关（黑 · 白）**，同 unruly |
| **Slant** | 2 个循环确认键 + 3 个直接键 | **只有 3 个直接键**，循环键不再给按钮 |
| **Pearl** | 2 个确认键（起止 / 取消）+ **直接画三档开关**（画线 / 画叉） | 两层各两个键：闲着「起笔 · 打叉」，画着「停笔 · 放弃」。打叉是**一次性上膛键**；`Ctrl` 画线**不给**（拖拽到得了同一条边，按压还更少） |

还有两处分类不同（做出来了，但归属和文档不一样）：

- **Inertia / Flood 的「重放求解器下一步」**：文档归三类（与位置无关的附加按钮），实现里放在
  **方向键那一排**（inertia 在九宫格正中心），并且只在按过求解之后**出现**。
- **Bridges**：文档给「2 确认键 + 跳岛数字键 + 直连三档」；实现是**三个键：岛完成了 · 架桥 ·
  没有桥**，而 `Enter` 那套拖拽整个不发了。

## 五、`docs/inputs.md`：没有发现不一致

它写的是**上游**接受哪些输入、每个输入做什么，全部带 `文件:行号`，不谈我们这一侧的按钮。
所以它和实现之间没有可对照的面——除非某条上游事实读错了，而它的 708 条引用有脚本逐条验过。

这一轮里我从源码读到的几件事和它不冲突：Signpost 的 `H` 被注释掉、Tracks 的在 `#if 0` 里、
Palisade 的修饰键只在 Full-grid 下有效，三条都和它一致。

**唯一要注意的是它的时效**：它以 `vendor/sgtpuzzles` 的 `3c36322` 为准。升级上游之后，它和
`docs/keys.md` 一样要重新过一遍，而它没有脚本能自动发现「行为变了但行号还在」。
