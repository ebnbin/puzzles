# 触摸交互设计

四十个谜题,在**完全没有键盘和鼠标**的设备上怎么玩。

## 这份文档是什么

上游给的是一套为键鼠设计的输入:三个鼠标键 × 按下/拖拽/松开,加上方向键、确认键和一堆
字母键。那一套在这个 app 里**原样保留**,有键鼠的读者拿到的就是上游的东西。

这份文档设计的是**另一套**,给只有手指的人。它不是键鼠那套的投影,也不受「上游把这个操作
绑在左键还是中键」的约束——上游的按钮分配是为鼠标做的决定,对手指没有约束力。

**基准是上游的能力,不是上游的键位。** 每个游戏能做哪些事,以 `vendor/sgtpuzzles/` 的
C 源码为准;能力清单来自 [`inputs.md`](inputs.md),那份文档逐条核对过源码行号。这里回答
的是另一个问题:这些能力,用手指怎么做到。

**这不是实现文档。** 它说的是「应该是什么形状」,不涉及组件、样式或事件代码。

## 三套交互,彼此独立

| | 输入 | 地位 |
| --- | --- | --- |
| **键鼠** | 上游原样 | 已完整,不在本文范围 |
| **触摸 · 基础** | 点击 + 长按 + 拖拽 + 一类按钮 | **必需**,没有开关 |
| **触摸 · 光标** | 屏幕方向键 + 光标 + 绑定的确认键 | **可选**,一个开关整组开关 |

三套可以混用,但**设计时的立场是「我完全没有键鼠」**——不给键盘留任何退路。

## 按钮分三类

| 类别 | 判据 | 开关 |
| --- | --- | --- |
| **一类 · 基础** | 拿掉它,**某个棋盘操作在纯触摸下无法做到** | 无,永远在 |
| **二类 · 光标** | 它的作用**取决于光标在哪** | 一个开关,整组同开同关 |
| **三类 · 附加** | 它的作用**与位置无关**(整盘、显示、提示) | 各自独立 |

**一类和三类的分界是位置相关性**,不是重要程度。Solo 的数字键作用在被选中的那一格,是一类;
Net 的打乱作用在整盘,是三类——尽管两者都是「没有就够不到」。

**同一个能力可以在一类和二类里各有一条通路,这不是重复。** Net 的锁定,在基础方案里是长按,
在光标方案里是光标格上的一个确认键。两套是并列的玩法,不是一套的两半。

### 二类内部的绑定关系是硬约束

方向键和它的确认键**同生同灭**:

- 只给方向键、不给确认键 → 光标能移到任何格子,到了之后什么也做不了,方向键是装饰。
- 只给确认键、不给方向键 → 确认键作用在动不了的光标上,按钮是装饰。

所以二类**必须整组开关**,不能拆着给。每一节的二类都会把这一组列全。

## 一、手势语言

手指只有三种天然表达。把它们钉死在这里,四十个游戏一律照办,读者换游戏不必重学。

### G1 · 点击 = 上游左键

最常用的那个操作。所有游戏一致。

### G2 · 长按 = 上游右键

第二常用。长按要有触觉/视觉回馈,否则读者不知道它触发了没有。

**长按的代价必须正视:它慢,而且不能连打。** 一个需要连续插二十面旗的扫雷玩家,不会愿意
长按二十次。所以凡是「右键操作和左键一样高频」的游戏,基础方案**额外给一个模式开关**
(见 B2),让点击临时改换语义。长按仍然保留,作为不换档时的一次性快捷。

### G3 · 长按后不抬手继续移动 = 上游右键拖拽

这一条把**右键拖拽**还给了触摸,而它在上游是一整类操作:Rect 的擦除框、Pattern 的整行叉、
Tents 的整行叉、Bridges 的「不能有桥」标记、Map 的铅笔、Galaxies 的箭头、Tracks 的打叉、
Pearl 的路径、Mosaic 的直线刷。没有这一条,这些全都够不到。

判定顺序:按下后先等长按计时;计时未到就移动 → 是 G4;计时到了还没抬手 → 进入 G3,
后续移动是右键拖拽。

### G4 · 拖拽 = 上游左键拖拽

按下后直接移动。**拖拽是稀缺资源**,不挪作他用:凡是上游用左键拖拽表达某个操作的游戏
(拉框、拉线、拖点、连笔),触摸的拖拽就只做那件事。

棋盘上的拖拽必须吃掉页面滚动,否则拉到一半页面跟着走。

### G5 · 中键没有手势

三个手势已经分完,不再发明第四种(双击、双指、边缘滑动都试探性太强,且和系统手势打架)。

上游中键真正有独立功能的只有五个游戏——Net(锁定)、Pattern(擦成未知)、Mines(连开)、
Loopy(擦)、Unruly(清空)。它们的去处**逐个判断,不套一个公式**:长按接得住的交给长按
(Net),接不住又够不到的补一类按钮(Pattern),点两下就到的不必补(Unruly、Loopy)。
各节交代。

### G6 · 循环用两个方向,不用两个动作

大量游戏的格子是**一个多态循环**(空 → A → B → 空)。上游左键正向、右键反向。
触摸沿用:**点击正向,长按反向**。

这条覆盖了三态、四态乃至更多,不需要为「第三态」发明任何东西。所以真正需要额外安排的,
只有**正交的动作**——不在同一个循环里的那种,比如 Net 的锁定之于旋转、Pattern 的整片擦
之于三态循环。它们要么占掉长按(Net),要么要一个一类按钮(Pattern)。

## 二、按钮语言

### B1 · 值键 —— 一类

把一个值放进被选中的格子。数独的数字、Undead 的怪物、Filling 的块大小、Dominosa 的高亮数字。

**没有它,这些游戏在触摸上归零**——手指表达不了「九个值里的第七个」。这是一类里最硬的一档,
也是「按钮是一等公民而不是补丁」最清楚的证明。

值键排一行,末尾跟一个清空键。值的个数由游戏参数定(数独 `c×r`,Towers/Keen 是 `w`)。

### B2 · 模式开关 —— 一类

**有状态**,改变点击的含义,按下去要看得出当前在哪一档。

两种情形要用它:

1. **补中键,而且长按腾不出来。** Pattern 的整片擦——上游绑在中键上,而长按已经被「沿直线
   刷成叉」占住了,没有第三格可放。
2. **高频右键。** Mines 的插旗、Solo 的铅笔——长按能做到,但频率高到让长按变成负担。

**先看长按能不能接住,接不住才上开关。** 开关是有状态的,读者每次点击前都要知道自己在哪一档;
这个成本会压在最高频的操作上。Net 的锁定就走了长按那条路(见第 1 节),Pattern 的整片擦走不了
——它的长按已经有正事。

**模式开关不取代长按,和它并存。** 开关管持久档位,长按管一次性。

### B3 · 光标组 —— 二类

一个整体,一个开关:

```
        ↑
    ←   ·   →          [ 确认 ] [ 次确认 ]
        ↓
```

- **方向键**:四向。Cube 和 Inertia 的斜向是八向(见各自那节)。
- **确认键**:一到三个,作用在光标格上。

**确认键的文案由上游实时给。** 三十五个游戏实现了 `current_key_label(ui, state, button)`,
它回答的正是「此刻这个键叫什么」——Net 的次确认在未锁定的格上是 "Lock"、在锁定的格上是
"Unlock";Blackbox 会按整行整列已锁过半没有报 "Lock" 或 "Unlock"。**照抄它**,不要自己
编一套文案:上游知道当前状态,我们不知道。它返回空字符串就把那个键置灰。

**没有实现它的正好五个:Cube、Fifteen、Untangle、Loopy、Palisade。** 前四个里有三个本来就
没有光标(Cube、Fifteen、Loopy),所以真正需要自己写文案的只有 **Untangle** 和 **Palisade**
两个,各在自己那一节里定死并说明理由。

### B4 · 附加键 —— 三类

与位置无关的整盘操作、显示开关、提示。各自独立开关,基础方案和光标方案下都可用。

它存在的唯一理由是**补全上游能力,不遗漏**。Net 的打乱在上游只有 `J` 一个入口,源码自己
问过 "should we have some mouse control for this?"(net.c:2332)而答案是没有——触摸上
它必须有个去处,就是这里。

## 三、光标方案给谁

**上游有光标的三十六个游戏,一个不落全部设计。** 判据是源码,不是「这个游戏看起来精不精细」。

**上游没有光标的四个**,分两种情况:

| 游戏 | 源码事实 | 二类给什么 |
| --- | --- | --- |
| **Cube** | `new_ui` 返回 NULL(cube.c:1032),`game_ui` 里没有任何光标字段 | **方向键方案**:方向键本身就是走子,不需要光标,也不需要绑定的确认键 |
| **Fifteen** | `game_ui` 只有一个偏好位(fifteen.c:457),没有光标 | 同上 |
| **Inertia** | `game_ui` 只有动画和计数字段(inertia.c:1484) | 同上,八向 |
| **Loopy** | **完全不接受键盘输入**。源码原话:"I think it's only possible to play this game with mouse clicks, sorry"(loopy.c:3070) | **不提供**。上游没有可映射的东西 |

前三个的方向键方案和光标方案**结构上不同**:没有光标,所以没有「移过去再确认」这一步,
方向键按下即走子,也就没有 B3 说的那种绑定关系。它们仍然是一个整组开关,解决的仍然是
小屏精度问题——只是形状不一样。

## 四、明说的取舍

下面这些上游能力,触摸方案**没有覆盖**。列在这里而不是散在各节,是为了让「漏了什么」
一眼可数。

| 能力 | 上游入口 | 为什么不给 |
| --- | --- | --- |
| Twiddle 的九个方位速记 | `a`-`d` 和小键盘九宫 | 触摸上直接点那个区块更快更准。速记键是键盘专属的加速器,不是能力 |
| Net 的平移视野 / 移信号源 | Shift / Ctrl + 方向键 | 纯显示,不改棋盘(见 inputs.md 的 Net 一节)。棋盘在手机上整个可见时无意义;环绕棋盘上的卷动,留给双指拖拽这类系统手势更合适,不占用本方案的三个手势 |
| Sixteen / Twiddle 的小键盘入口 | 小键盘数字 | 与方向键或点击完全重合,没有新增能力 |
| 上游的「触摸专属」三态循环 | `MOD_STYLUS`,五个游戏 | `emcc.c` 的鼠标入口没有这一位,网页版**根本收不到**(见 inputs.md 1.7)。这是上游自家网页版就有的限制,不是这套设计的取舍——但结果一样:拿不到 |

除这四条之外,上游的每一项棋盘能力在触摸上都有通路。各节的「覆盖」一栏会逐个对照。

## 五、六个族群 —— 设计在哪里复用

四十个游戏的操作形态其实只有几种。**同族的游戏必须拿到同一套手势**,否则读者每换一个游戏
就要重学一次。下面这张分族表就是逐节设计时的模板;各节只写它和族里其他成员**不一样**的
地方。

### 族 A · 多态循环(12 个)

格子有三个或更多状态,上游用左右键正反两个方向推。**点击正向、长按反向,一律不给按钮。**

| 成员 | 循环的是什么 |
| --- | --- |
| Slant · Range · Unruly · Mosaic · Pattern | 一格的状态 |
| Light Up · Singles · Tents · Magnets | 两条**互不相通**的链,点击管一条、长按管另一条 |
| Loopy · Palisade · Dominosa | 一条**边**的状态(不是格) |

后两组的差别值得记住:Magnets 的两条链之间**推不过去**(magnets.c:1877),而 Slant 那种
是一个环——同样是「点击 / 长按」,前者会遇到「按了没反应」,后者不会。

边类那三个对**命中精度**的要求最高,判定要按「离哪条边最近」划分,格子正中和四角留死区。

### 族 B · 拉丁方填值(5 个)

Solo · Keen · Towers · Unequal · Undead。**这一族是「值键属于一类」的全部来源。**

共用的形状:

- 点击选中、长按用另一档选中
- **值键 + 清空键**(缺了就玩不成)
- **「铅笔」开关**(高频右键,长按扛不住)
- 二类只要**一个**确认键:切换普通 / 铅笔档

差别只有三处:值的写法(Solo 大棋盘用字母、Unequal 从 0 起、Undead 是三个怪物)、
Towers 和 Unequal 多一个「划掉线索」的能力、Unequal 的两个确认键在上游是等价的。

### 族 C · 拖拽(10 个)

Pearl · Tracks · Bridges · Signpost · Untangle · Map · Galaxies · Rect · Pegs · Filling。

**拖拽承担主操作,长按后拖(G3)承担第二种拖拽。** 这一族是 G3 存在的全部理由——没有它,
Rect 的擦除框、Bridges 的标记、Map 的铅笔、Galaxies 的箭头、Tracks 的打叉、Signpost 的
反向连,六项能力一次性全丢。

二类在这一族里长得也一样:确认键**起止**一次键盘拖拽,方向键在拖拽中改为移动落点。

### 族 D · 外圈滑动(2 个)

Sixteen · Netslide。点击外圈朝内滑、长按朝外滑;外圈箭头细,命中区要外扩,而这正是
光标方案在这两个游戏里最值钱的地方。

### 族 E · 方向键即走子(3 个)

Cube · Fifteen · Inertia。**上游没有光标**,所以二类是「方向键方案」而不是光标方案:
按下即走子,没有确认键,也就没有绑定关系。基础方案一律是「点击棋盘,按方位角决定方向」。

### 族 F · 一点即动(8 个)

Net · Twiddle · Samegame · Flip · Guess · Mines · Blackbox · Flood。点击就是主操作,
长按是第二操作(如果有的话),二类是标准的「方向键 + 一到三个确认键」。

Loopy 不属于任何一族的二类——它是唯一一个只有基础方案的游戏。

## 六、四十个游戏

按上游收录顺序。每节四栏:**上游能力**(以能力计,不以键位计)、**一类**、**二类**、
**三类**,最后一栏**覆盖对照**逐条交代每项能力去了哪。

手势一律按 [G1–G6](#一手势语言),不再重复解释。

---

### 1. Net — 旋转管道拼出连通网络

**上游能力** ① 把一格转到任意朝向(上游给了三个快捷:逆时针、顺时针、180°) ② 锁定/解锁一格
③ 打乱全部未锁定格

**一类 · 基础**

| 输入 | 作用 |
| --- | --- |
| 点击格子 | 逆时针转 90° |
| 长按格子 | **锁定 / 解锁**该格 |

点击遍历四个朝向,长按管锁定,两个手势就够。

**上游的顺时针和 180° 这两个快捷不给。** 旋转的能力是「把这一格转到我要的朝向」,连点四下
以内到得了任何一个,所以少的是两下点击,不是一项能力。锁定不同——它正交于旋转,没有任何
点击组合能到达,所以它拿走长按。

**二类 · 光标**

方向键的十字留出四个角,确认键就放在角上:

```
[ 逆时针 ]   ↑   [ 锁定 ]
     ←       ·       →
             ↓
```

| 输入 | 作用 |
| --- | --- |
| 方向键 | 移动光标(上游取模移动,非环绕棋盘也绕回) |
| 左上 · 逆时针 | 光标格逆时针转 90° |
| 右上 · 锁定 | 光标格锁定 / 解锁 |

**两个键,文案照抄 `current_key_label`**(net.c:2124):未锁定的格上报 "Rotate" / "Lock",
已锁定的格上次确认键报 "Unlock"、主确认键返回空——锁住的格子转不动,那个键该置灰。
这正好对上上游的 `CURSOR_SELECT` 和 `CURSOR_SELECT2`,不需要任何自己编的文案。

顺时针同样不给,理由同基础方案。

**三类 · 附加**

| 按钮 | 作用 |
| --- | --- |
| 打乱 | 把所有未锁定的格子随机转向 |

上游只有 `J` 一个入口,源码自己问过 "should we have some mouse control for this?"
(net.c:2332),答案是没有。它作用于整盘、与光标无关,是三类的样板。

**覆盖对照** ①点击(逆时针,连点遍历四个朝向)/ 左上键 ②长按 / 右上键 ③打乱按钮。
视野平移和移信号源见[取舍表](#四明说的取舍)——它们不改棋盘。

**没有覆盖的**:顺时针和 180° 这两个快捷。

---

### 2. Cube — 滚动多面体收集蓝格

**上游能力** ① 朝四个正交方向滚 ② 在三角格上朝斜向滚 ③ 按点击点相对当前格的方位角滚

**一类 · 基础**

| 输入 | 作用 |
| --- | --- |
| 点击棋盘任意处 | 按点击点相对多面体当前格中心的**方位角**决定往哪滚 |

**不需要任何按钮。** 上游的左键行为(cube.c:1136)本来就是为「指哪走哪」设计的,正方形格
分四个 45° 扇区、三角格分三个 120° 扇区——这对手指是天然的,比方向键还直接。

**二类 · 方向键(无光标)**

Cube **上游没有光标**(`new_ui` 返回 NULL,cube.c:1032),所以这不是光标方案:
**方向键按下即走子**,没有「移过去再确认」那一步,也就没有绑定的确认键。

| 输入 | 作用 |
| --- | --- |
| 方向键 · 四正向 | 朝该方向滚一格 |
| 方向键 · 四斜向 | 仅在三角格上有效,对应上游小键盘 `7 9 1 3` |

**八向布局,按当前格实际可走的方向亮灭。** 正方形格没有斜向出口(cube.c:1201 返回
`MOVE_NO_EFFECT`),那四个键应当置灰而不是按下去没反应——上游靠「按了没动」告诉玩家,
屏幕按钮可以提前告诉他。

它解决的是精度问题:方位角判定要求点得离中心足够偏,在小屏上不总是好控制。

**三类 · 附加** 无。

### 9. Solo — 数独(含 Killer、Jigsaw、X 变体)

**上游能力** ① 普通选中一格 ② 铅笔选中一格 ③ 往选中格填一个值 ④ 清空选中格
⑤ 在普通档和铅笔档之间切换 ⑥ 把所有空格填满剩余候选

设棋盘边长为 `cr`(= c×r,标准数独 9)。

**一类 · 基础**

| 输入 | 作用 |
| --- | --- |
| 点击格子 | 按当前档选中(默认普通档) |
| 长按格子 | 按**另一**档选中(不改变开关的档位) |
| **值键 `1`…`cr`** | 往选中格填该值;铅笔档下记候选 |
| **清空键** | 清空选中格(上游 `\b` / `CURSOR_SELECT2`) |
| **「铅笔」开关** | 切换点击的默认档 |

**值键是这一节的核心,也是整份文档里「按钮是一等公民」最硬的证明。** 没有它,手指表达不了
「九个值里的第七个」,Solo 在触摸设备上归零——这不是「够不着」,是玩不成。

值的写法照上游 `request_keys`(solo.c:3627):`1`–`9`,再往上用 `a`、`b`…,一共 `cr` 个,
末尾一个清空键。

**「铅笔」开关的理由是频率**,不是够不着:长按已经能进铅笔档,但数独里记候选是高频动作,
每记一次都长按会让长按变成负担(见 [G2](#g2--长按--上游右键))。

**二类 · 光标**

| 输入 | 作用 |
| --- | --- |
| 方向键 | 移动高亮 |
| 确认键 | 在普通档和铅笔档之间切换 |

文案照抄 `current_key_label`(solo.c:4635):有高亮时读 "Pencil" 或 "Ink"。

**值键不属于二类,属于一类,两套方案共用。** 它们依赖的是「有没有格子被选中」,不依赖
选中是怎么来的——点出来的和方向键走出来的一样能用。

**三类 · 附加**

| 按钮 | 作用 |
| --- | --- |
| 补候选 | 把每个空格填满「本行本列本宫还允许的全部候选」(上游 `M`) |

作用于整盘,与光标无关,所以是三类。

**覆盖对照** ①点击 ②长按 / 铅笔开关 ③值键 ④清空键 ⑤铅笔开关 / 确认键 ⑥补候选按钮。
全部覆盖。

### 10. Mines — 扫雷

**上游能力** ① 开一个盖着的格 ② 插旗 / 取消插旗 ③ 在已开的数字格上连开周围

**一类 · 基础**

| 输入 | 作用 |
| --- | --- |
| 点击盖着的格 | 开格 |
| 点击已开的数字格 | **连开**周围未插旗的格(周围旗数等于该数字时) |

| --- | --- |

| 确认 A | 开格;光标在已开的数字格上时是连开 |

| --- | --- |
| 方向键 · **未进入跳跃** | 移动光标,**只停在洞或棋子上**(棋盘可能是不规则形状) |
| 方向键 · **已进入跳跃** | 朝该方向跳,光标跟着落到终点 |
| 确认键 | 光标在棋子上:**进入跳跃状态**;已在跳跃:**退出**(反悔) |

**这是二类绑定关系最纯粹的一个例子:确认键不做任何走子,它只是把方向键的含义从「移动」
切换成「跳」。** 单给方向键,永远只能挪光标;单给确认键,进了跳跃状态却没方向可挑。两个
都在才成立。

上游两个确认键在这里等价(pegs.c:982 用的是 `IS_CURSOR_SELECT`),所以**只给一个**。

**三类 · 附加** 无。

**覆盖对照** ①拖拽 ②确认键 + 方向键。全部覆盖。

### 15. Dominosa — 把数字对切成骨牌

**上游能力** ① 在跨过某条边的两格上放/撤一块骨牌 ② 在某条边上画/擦「这里不是骨牌」的记号
③ 高亮某个数字(最多同时两个)

**一类 · 基础**

| 输入 | 作用 |
| --- | --- |
| 点击格子**靠近某条边**处 | 放/撤跨过那条边的骨牌 |
| 长按格子**靠近某条边**处 | 画/擦那条边上的「不是骨牌」记号 |
| 长按格子**正中央** | 高亮/取消高亮这个数字 |

**长按的两种落点分工照搬上游右键**(dominosa.c:2812 判「离中心 < 2/5 格宽」),不是我们
发明的:同一个右键,点正中是高亮数字,点靠边是画记号。

鼠标更容易落在对角线上,所以这条要保留而不是「就近取一个」:猜错方向比不动更糟。

**二类 · 光标**

| 输入 | 作用 |
| --- | --- |
| 方向键 | 在「格 / 缝」交替的双倍网格上移动(`2w-1` × `2h-1`) |
| 确认 A | 光标停在缝上时:放/撤骨牌 |
| 确认 B | 光标停在缝上时:画/擦「不是骨牌」记号 |

光标停在格子上时两个键都是 `MOVE_NO_EFFECT`(dominosa.c:2854),按 B3 应当置灰。

**三类 · 附加**

| 按钮 | 作用 |
| --- | --- |
| 数字 `0`…`n` | 高亮/取消高亮该数字,最多同时两个 |

**这排数字键是三类而不是一类,因为它和位置无关**——高亮的是「这个数字」,不是「这一格」
(dominosa.c:2868 完全不看光标)。基础方案靠长按格子正中也能高亮,所以拿掉它照样能玩;
它的价值是在小屏上不必去点那个「离中心 2/5 格宽」的小圈。

按同一个数字是取消;已经高亮两个时按第三个无效(dominosa.c:2881),该按钮此时置灰。

**覆盖对照** ①点击/确认 A ②长按靠边/确认 B ③长按正中/数字键。全部覆盖。

### 16. Untangle — 拖动顶点解开交叉

**上游能力** ① 拖动一个顶点到新位置 ② 循环选中下一个顶点 ③ **反向**循环 ④ 键盘起止拖拽

**一类 · 基础**

| 输入 | 作用 |
| --- | --- |
| 从一个顶点拖走 | 顶点跟着走,松手落位 |
| 拖出窗口外松手 | **取消**,顶点回原位 |

**不需要按钮。** 上游三个鼠标键在这里完全等价(untangle.c:1355 用 `IS_MOUSE_DOWN`),
所以长按不必另有含义;拖拽就是这个游戏的全部。

**二类 · 光标**

| 输入 | 作用 |
| --- | --- |
| 方向键 · 未拖拽 | 选中该方向 ±45° 扇区内**欧氏距离最近**的顶点 |
| 方向键 · 拖拽中 | 把被拖的顶点朝该方向挪半格 |
| 确认键 | 抓起 / 放下当前顶点 |
| **下一个** | 循环到下一个顶点 |
| **上一个** | **反向**循环 |

**Untangle 没有 `current_key_label`**(五个没实现的游戏之一),所以这三个键的文案由我们

**三类 · 附加** 无。三个偏好(吸附网格、高亮交叉边、顶点画法)是设置项,不是按钮。

**覆盖对照** ①拖拽/确认键+方向键 ②「下一个」 ③「上一个」 ④确认键。全部覆盖。

### 17. Blackbox — 用激光找出盒中的球

**上游能力** ① 在竞技场内放/撤一个猜测的球 ② 锁定/解锁一格 ③ 从外圈发射器发射激光
④ 锁定/解锁整行或整列 ⑤ 揭晓答案

**一类 · 基础**

| 输入 | 作用 |
| --- | --- |
| 点击竞技场内的格 | 放/撤一个球 |
| 长按竞技场内的格 | 锁定/解锁该格(防手滑) |
| 点击外圈发射器 | 发射激光 |
| 长按外圈的上下边 | 锁定/解锁**整列** |
| 长按外圈的左右边 | 锁定/解锁**整行** |
| 点击左上角 | **揭晓**(须已可揭晓) |

**一个按钮都不需要,而且不是勉强凑的**:上游的左键/右键分工在这里正好是「做」与「锁」,
tap 和长按接得严丝合缝。

揭晓是不可逆的,而它现在挂在一次普通点击上——**建议加一次确认**,这是本设计里少数几处
主动偏离上游交互的地方,理由是手指误触的代价在这里特别高(一局就此结束)。

**二类 · 光标**

| 输入 | 作用 |
| --- | --- |
| 方向键 | 在**外扩一圈**的范围内移动(`w+2` × `h+2`);四个角除左上外不许停 |
| 确认 A | 等同左键:放球 / 发射 / 揭晓,按光标落在哪里 |
| 确认 B | 等同右键:锁格 / 锁行 / 锁列 |

**`current_key_label` 在这里是全 collection 最细的一个**(blackbox.c:534),直接用它:
左上角报 "Check",竞技场里按球和锁的有无报 "Ball"/"Clear"/"Lock"/"Unlock",发射器上报
"Fire",整行整列的锁**按当前已锁过半没有**决定报 "Lock" 还是 "Unlock"。自己是编不出
这套文案的。

**三类 · 附加** 无。

**覆盖对照** ①点击/确认 A ②长按/确认 B ③点击/确认 A ④长按外圈/确认 B ⑤点击左上角/确认 A。
全部覆盖。

### 20. Map — 四色填色

**上游能力** ① 从一个区域拿颜色填进另一个区域 ② 拿颜色到空白区域上画铅笔标记
③ 清空一个区域 ④ 开关区域编号显示

**一类 · 基础**

| 输入 | 作用 |
| --- | --- |
| 从一个区域拖到另一个区域 | 把起点的颜色**填**进终点 |
| 长按后不抬手拖(G3) | 把颜色画成终点的**铅笔标记** |
| 从**空白**区域拖到某个区域 | 清空那个区域(拿起的是「空」) |
| 拖到边界上松手 | 取消 |

**Map 没有调色板,颜色只能「从别处拿」**,这是上游的设计(map.c:2541 取起点区域的颜色),
不是遗漏——题目一定带几个已填色的不可变区域,第一笔从那里拿。触摸方案保留这一点,不发明
一个上游没有的调色板。

铅笔标记只在「从有色区域拖到空白区域」时成立;有色区域上不能画铅笔(map.c:2594)。

**二类 · 光标**

| 输入 | 作用 |
| --- | --- |
| 方向键 | 移动区域光标 |
| 确认 A | 拿起 / 填入 |
| 确认 B | 拿起 / 画铅笔标记 |
| 确认键 · **原地不动按第二次** | **清空**该区域 |

最后一条是上游键盘独有的操作(map.c:2532,`!ui->cur_moved` 时把颜色置空),鼠标没有对应
动作。它依赖「光标从拿起到现在有没有移动过」,是彻底的光标绑定,留在二类。

文案照抄 `current_key_label`(map.c:2469),它把这套状态机全报出来了:没拿颜色时 "Pick";
拿了但没移动是 "Clear" 或 "Cancel";移动过则按目标情况给 "Fill" / "Stipple" / "Cancel" /
"Clear"。

**三类 · 附加**

| 按钮 | 作用 |
| --- | --- |
| 区域编号 | 开关区域上的数字(上游 `L`) |

纯显示,与位置无关。它和偏好 `show-numbers` 是同一个开关(map.c:2345)。

**覆盖对照** ①拖拽/确认 A ②长按拖/确认 B ③从空白拖/原地按两次 ④区域编号按钮。全部覆盖。

### 21. Loopy — 沿格线画一个闭环

**上游能力** ① 把一条边切成「有线」或切回未知 ② 把一条边切成「打叉」或切回未知

**一类 · 基础**

| 输入 | 作用 |
| --- | --- |
| 点击最近的一条边 | 未知 → **有线**;有线或打叉 → 未知 |
| 长按最近的一条边 | 未知 → **打叉**;打叉或有线 → 未知 |

**中键在这里不需要补。** 上游中键是「一律擦成未知」(loopy.c:3100),而这两个手势各自
在非未知态上就是擦——点击擦掉线、长按擦掉叉。中键没有第三种结果,是纯粹的便利键。

**判定落在「最近的一条边」上**(`grid_nearest_edge`),而不是格子里。Loopy 的网格可以是
六边形、三角形等各种形状,边比格子细得多——**这是四十个游戏里对触摸精度要求最高的一个**,
命中半径要给足。

**二类 · 光标 —— 不提供**

**Loopy 上游完全不接受键盘输入。** 源码原话:"I think it's only possible to play this
game with mouse clicks, sorry"(loopy.c:3070);`interpret_move` 的 `switch` 只有三个
鼠标 case,其余一律 `return NULL`(loopy.c:3086)。

没有光标、没有方向键、没有确认键可映射。**硬造一套是发明上游没有的东西**,不做。

代价要说明白:Loopy 因此是唯一一个**只有基础方案**的游戏,精度问题只能靠命中半径和
棋盘缩放来缓解。

**三类 · 附加** 无。

**偏好 `auto-follow`**(loopy.c:944)开启后,一次点击会顺着唯一确定的路径把一整串边设成
同一状态——这在触摸上尤其值钱,一笔顶十笔。它是上游偏好,沿用即可,不必新做按钮。

**覆盖对照** ①点击 ②长按。全部覆盖。

### 22. Inertia — 滑行收集宝石

**上游能力** ① 朝八个方向滑到撞墙 ② 按点击点的方位角决定方向 ③ 播放求解答案的下一步

| 输入 | 作用 |
| --- | --- |
| 点击棋盘任意处 | 按点击点相对角色的**八分之一圆(45° 扇区)**决定往哪滑 |

和 Cube 同一族做法(inertia.c:1601),只是分了八档而不是四档。点在角色所在格上什么也不做。

| 输入 | 作用 |
| --- | --- |
| 方向键 · 八向 | 朝该方向滑到撞墙为止 |

**八向布局。** 上游的四个正向来自方向键、四个斜向来自小键盘 `7 9 1 3`

**三类 · 附加**

| 按钮 | 作用 |
| --- | --- |
| 下一步 | 按求解答案走一步 |

**这个按钮只在求过解之后才有意义**,没有解法时上游返回 `MOVE_UNUSED`(inertia.c:1626),

Inertia 是唯一一个把确认键接到求解结果上的游戏——这个能力很容易被漏掉,因为它在上游

### 23. Tents — 每棵树配一顶帐篷

**上游能力** ① 空→帐篷 / 非空→清空 ② 空→叉 / 非空→清空 ③ 沿一行或一列把所有空格打叉
④ 直接设成帐篷 ⑤ 直接设成叉 ⑥ 直接清空 ⑦ 光标移动时沿途打叉(两档:只改空格 / 连帐篷一起改)

**一类 · 基础**

| 输入 | 作用 |
| --- | --- |
| 点击格子 | 空 → 帐篷;非空 → 清空 |
| 长按格子 | 空 → 叉;非空 → 清空 |
| 长按后不抬手拖(G3) | 沿一行或一列,把经过的**所有空格**打叉 |

**普通拖拽在这里没有含义,因为上游左键拖拽本来就没有效果**——`drag_xform` 明写「左拖当作
在起点单击处理」(tents.c 的 `drag_xform`)。不硬给它一个上游没有的意思。

树永远不变(同一函数里的 "trees are inviolate always"),点上去不该有反馈动作。

**二类 · 光标**

| 输入 | 作用 |
| --- | --- |
| 方向键 | 移动光标 |
| 确认 A | 空 → 帐篷;非空 → 清空 |
| 确认 B | 空 → 叉;非空 → 清空 |
| **帐篷** / **叉** / **清空** | 在光标处**直接设成**该态,不走循环 |
| **「沿途打叉」三档开关** | 关 / 只改空格 / 连帐篷一起改 |

后三个直接设值键对应上游的 `T` `N` `B`(tents.c:1706),它们作用在光标格上,是光标绑定的。
和确认键的差别同 Slant:**直接赋值,不必先看当前是什么**。

三档开关对应上游的 Shift+方向 和 Ctrl+方向(tents.c:1678):Shift 只把沿途的**空格**打叉,
Ctrl 连**帐篷**也一起改成叉。两档语义差别很大(后者会毁掉已放的帐篷),所以做成三档循环
而不是一个二态开关——读者得看得见自己在哪一档。

**三类 · 附加** 无。

**覆盖对照** ①点击/确认 A ②长按/确认 B ③长按拖 ④⑤⑥直接设值键 ⑦三档开关。全部覆盖。

### 24. Bridges — 在岛之间连桥

**上游能力** ① 在两岛之间拉一座桥 ② 拉一道「这里不能有桥」的标记 ③ 切换某岛的「已完成」标记
④ 跳到最近的、桥数是某个值的岛 ⑤ 开关「显示可能的桥位置」 ⑥ 走一步求解提示

**二类 · 光标**

| 输入 | 作用 |
| --- | --- |

| 按钮 | 作用 |
| --- | --- |

### 27. Filling — 给每个连通块填上它的大小

**上游能力** ① 选中一格(并清掉原有选择) ② 拖拽累加多选 ③ 给所有选中的格填一个数
④ 清空 ⑤ 取消整个选择 ⑥ 切换单个格的选中状态

**一类 · 基础**

| 输入 | 作用 |
| --- | --- |
| 点击格子 | 清空当前选择,选中这一格 |
| 拖拽 | **累加**多选,把经过的格都加进来 |
| **值键 `0`…`max(w,h)`** | 给所有选中的格填这个数 |
| **清空键** | 等同按 `0`(上游 `\b` 就是这么折的,filling.c:1544) |

**值键是一类里最硬的一档,同 Solo。** 没有它,Filling 在触摸上归零。

**键的个数不照抄上游的 `request_keys`,这是有意的。** 那个函数固定返回 `1`–`9` 加一个退格,
一共十个,**不看棋盘大小**(filling.c:1302);而 `interpret_move` 实际只接受到 `max(w,h)`
(2×2 棋盘上是 3),超出的一律 `MOVE_UNUSED`(filling.c:1548)。照抄会在小棋盘上摆出一排
按了没用的键。按实际可用范围裁到 `1`…`max(w,h)` 更准,而清空键顶替上游那个退格——
上游本来就把退格折成 `0`(filling.c:1544)。

**多选靠拖拽是上游本来的设计**(filling.c:1474 的 `LEFT_DRAG` 不清空、只累加),对手指
比对鼠标还顺——这是少数几个「触摸天然比键鼠好用」的地方。

**二类 · 光标**

| 输入 | 作用 |
| --- | --- |
| 方向键 | 移动光标;键盘拖拽开启时同时把经过的格加进选择 |
| 确认 A | **开关键盘拖拽**;开启时顺带选中当前格 |
| 确认 B | 切换当前格的选中状态,并关掉键盘拖拽 |

文案照抄 `current_key_label`(filling.c:1425):确认 B 按当前格已选没选报 "Select" /
"Deselect"。

确认 A 是又一个纯粹的绑定样板:它自己不填任何数,只是把方向键的含义从「移动」切换成
「移动并选中」。

**三类 · 附加**

| 按钮 | 作用 |
| --- | --- |
| 取消选择 | 清掉当前选择(上游 `Esc`) |

**这个按钮不能省。** 基础方案里点击任意一格都会「清空并选中那一格」,没有任何手势能回到
「一个都没选中」——而上游有(`Esc`,filling.c:1537)。它与位置无关,所以是三类。

**覆盖对照** ①点击 ②拖拽/确认 A ③值键 ④清空键 ⑤取消选择按钮 ⑥确认 B。全部覆盖。

画/擦**叉** ④ 取消进行中的拖拽 ⑤ 走一步提示

**一类 · 基础**

| 输入 | 作用 |
| --- | --- |

| 点击格子靠近某条**边**处 | 画 / 擦那条**线** |

### 35. Undead — 镜子里的吸血鬼、幽灵和僵尸

**上游能力** ① 普通选中 ② 铅笔选中 ③ 放 Ghost ④ 放 Vampire ⑤ 放 Zombie ⑥ 清空
⑦ 切换普通/铅笔档 ⑧ 划掉/恢复外沿线索 ⑨ 切换怪物画法(图案 / 字母) ⑩ 循环剩余计数的
显示样式 ⑪ 补候选

**一类 · 基础**

| 输入 | 作用 |
| --- | --- |
| 点击格子 | 按当前档选中 |
| 长按格子 | 按**另一**档选中 |
| **怪物键 · 幽灵 / 吸血鬼 / 僵尸** | 往选中格放该怪物;铅笔档下记候选 |
| **清空键** | 清空选中格 |

**怪物键是一类,同 Solo 的数字键**:手指表达不了「三种怪物里的第二种」。
上游 `request_keys` 返回的正是这四个键:`G`、`V`、`Z`,加一个**退格**作清空
(undead.c:1334)。注意清空在上游有四种写法(`E`、`0`、退格、次确认键,undead.c:1952),
而它自己推荐上屏的是退格那一个。

**键面画什么要跟着棋盘走。** 上游 `A` 键在「怪物图案」和「字母」之间切换整个显示
(undead.c:1909),键面必须跟着换——一个画着吸血鬼却往格子里写 V 的按钮,是在同一块屏幕上
放两套符号。这个 bit 从偏好里读得到。

**棋盘上方的计数区也是一个输入**(undead.c:1900):点某种怪物等同按那种怪物的键,点该格
已有的那种则变成删除。它和怪物键是同一个能力的两个入口,不必在键盘上重复给,但**计数区
本身要可点**。

**二类 · 光标**

| 输入 | 作用 |
| --- | --- |
| 方向键 | 移动高亮(夹在边界,不环绕) |
| 确认键 | 切换普通/铅笔档 |

**只给一个确认键。** 上游的 `CURSOR_SELECT2` 在 Undead 里是清空(undead.c:1952),而清空
已经有专用键了。

**三类 · 附加**

| 按钮 | 作用 |
| --- | --- |
| 怪物画法 | 图案 ↔ 字母(上游 `A`) |
| 计数样式 | 循环剩余计数的显示方式(上游 `C`) |
| 补候选 | 把每个空格填满剩余候选(上游 `M`) |

前两个是纯显示开关,上游把它们排在所有棋盘检查之前(undead.c:1909),任何状态下都有效。

**覆盖对照** ①点击 ②长按/铅笔开关 ③④⑤怪物键 ⑥清空键 ⑦铅笔开关/确认键 ⑧点外沿线索

### 36. Unruly — 每行每列黑白各半

### 38. Tracks — 铺一条从 A 到 B 的铁轨

**上游能力** ① 沿路拖出一条**铺轨**路径 ② 沿路拖出一条**打叉**路径 ③ 单击格心翻转整格
④ 单击某条边翻转它 ⑤ ③④ 的打叉档

**一类 · 基础**

| 输入 | 作用 |
| --- | --- |
| 拖拽 | 沿路累积**铺轨**,松手一次提交 |
| 长按后不抬手拖(G3) | 同样,但是**打叉** |
| 点击格**中心**(< 1/4 格) | 翻转整格:铺满 / 清空 |
| 点击靠近某条**边** | 翻转那条边:铺轨 / 清除 |
| 长按格中心或边**不移动** | 同上两条,但走**打叉**那一档 |

**这一节是 G3 那条判定顺序的最好例证**:长按之后抬手是「右键单击」,长按之后移动是
「右键拖拽」——Tracks 两者都要,而且都是上游有的能力。一条规则接住两件事。

**笔刷方向按起点当前状态取反**(tracks.c:2271 的 `clearing`),所以从一段已铺的轨道拖出去
是在擦而不是在铺。这个细节要保留,它让「拖一条、再拖回去」变成撤销那一笔的自然动作。

**二类 · 光标**

| 输入 | 作用 |
| --- | --- |
| 方向键 | 在双倍网格上移动,**自动跳过格子的四角**(tracks.c:2362) |
| 确认 A | 光标在边上则翻转那条边;在格心则翻转整格 |
| 确认 B | 同上,但走打叉那一档 |

**三类 · 附加** 无。

**`H` 不是 Tracks 的键**——tracks.c:2393 那个提示键包在 `#if 0` 里,不参与编译。不要给
它一个上游没有的提示按钮。

**覆盖对照** ①拖拽/确认 A ②长按拖/确认 B ③④点击/确认 A ⑤长按/确认 B。全部覆盖。

### 39. Palisade — 把棋盘切成等大的块

**上游能力** ① 一条边:未定 → 画上 / 已画 → 清除 ② 一条边:未定 → 标成「一定不是边界」/
已标 → 清除 ③ 方向键直接标(**仅 Full-grid 模式**)

**一类 · 基础**

| 输入 | 作用 |
| --- | --- |
| 点击格子靠近某条**边**处 | 画 / 清除那条边 |
| 长按同一位置 | 标成「一定不是边界」/ 清除 |

**点在格子正中或正角上什么也不做**(palisade.c:979:「不存在唯一最近的边」)。这和 Pearl
的中央死区是同一个道理,而 Palisade 多了四个角也是死区——手指的命中区要按「离哪条边最近」
划分,四角留白。

**二类 · 光标**

| 输入 | 作用 |
| --- | --- |
| 方向键 | 移动光标;走法由偏好 `cursor-mode` 定(Half-grid 每次一步、停在格与边;Full-grid 每次两步、只停格心) |
| 确认 A | 画 / 清除光标所在的边 |
| 确认 B | 标成「一定不是边界」/ 清除 |
| **「方向键直接标」三档开关** | 关 / 画边 / 标非边界。**仅 Full-grid 模式下出现** |

**Palisade 没有 `current_key_label`**(五个没实现的游戏之一),所以确认键的文案由我们
写死:「边」和「非边界」。光标停在格心或角上时上游返回 `MOVE_NO_EFFECT`
(palisade.c:1076),两个键置灰。

**三档开关只在 Full-grid 模式下给,和上游一致。** 上游的 Ctrl/Shift+方向确实只在那个模式
下有效(palisade.c:1013:Half-grid 下修饰符被直接忽略),这是全 collection 里唯一一处
「偏好决定某个组合存不存在」。触摸方案**不去补齐它**——补了就是造一个上游没有的能力,
而这份文档的基准是上游能力。

**三类 · 附加** 无。

**覆盖对照** ①点击/确认 A ②长按/确认 B ③三档开关(Full-grid)。全部覆盖。

### 40. Mosaic — 按数字涂格

**上游能力** ① 格子前进一档 ② 前进两档(等于反向一档) ③ 沿直线把一整段刷成同一状态

**一类 · 基础**

| 输入 | 作用 |
| --- | --- |
| 点击格子 | 前进一档 |
| 长按格子 | 前进两档 |
| 拖拽 | 沿直线把整段刷成**起点那一格决定的状态** |
| 长按后不抬手拖(G3) | 同样,但走反向那一档 |

- **一类按钮只有八个游戏需要。** 五个拉丁方(Solo、Unequal、Keen、Towers、Undead)和
  Filling 要值键与清空键;Pattern 和 Mines 各要一个模式开关。**其余三十二个游戏,
  纯手势就能完成全部棋盘操作**——这是「按钮是一等公民,但不滥用」的结果。
- **两个模式开关的理由不一样。** Pattern 的「擦」补的是**能力**:它在上游绑在中键上,而
  Pattern 的长按另有正事(刷成叉),腾不出来。Mines 的「旗」补的是**频率**:长按本来就能插旗,
  只是一局要插几十面。前者不给会丢东西,后者不给只是难用。
- **同样是正交的第三个动作,Net 没有开关而 Pattern 有**,分水岭是长按腾不腾得出来。这是
  [B2](#b2--模式开关--一类) 那条判据在四十节里唯一一次给出不同答案的地方。
- **拖拽用在十二个游戏上,长按后拖用在九个。** 后者不是族 C 独有:族 C 占六个(Rect、
  Map、Bridges、Galaxies、Signpost、Tracks),族 A 里的 Pattern、Tents、Mosaic 也各要一个
  ——它们的第二种拖拽同样是上游的右键拖拽。少了 G3,这九项能力一次性全丢。
- **确认键给一个还是两个,严格看上游区不区分。** 只给一个的十个游戏分四种原因:
  上游两个确认键**本来就等价**(Flip、Pegs、Galaxies、Unequal);次确认键的活是**清空**,
  已经被专用清空键接走(Solo、Keen、Towers、Undead);次确认键的活**不看光标**,挪去了三类
  (Flood 的播放解法);次确认键的活**变成了独立按钮**(Untangle 的循环顶点)。
- **只有 Loopy 没有二类**,而且理由是源码事实——它完全不接受键盘输入——不是设计取舍。
- **三类按钮共二十三个,分布在十八个游戏上**,全部是提示、整盘操作或显示开关。
  **没有一个是位置相关的**,这条线在四十节里没有例外。

## 八、还没有回答的问题

这份文档定的是形状,不是像素。下面几件事要等真机上手才知道:

- **长按的时长。** 350ms 是个常见起点,但 Mines 这类连续操作多的游戏可能嫌长,Blackbox
  这类每一下都重要的可能嫌短。可能需要按游戏调,也可能需要做成偏好。
- **命中半径。** 族 A 里的边类三个(Loopy、Palisade、Dominosa)和 Pearl、Tracks 都是
  「点边不点格」,上游的判定阈值是为鼠标定的(Pearl 是 1/4 格,Dominosa 是 2/5 格宽),
  手指要不要放宽、放宽多少,量过才知道。
- **模式开关放在哪。** 两个模式开关(Pattern 的擦、Mines 的旗)必须在拇指够得到的地方,
  而且要能一眼看出当前档位——这比它们叫什么名字重要得多。
- **光标方案的开关粒度。** 现在是「每个游戏一个开关」。是否该有一个全局默认,以及第一次
  打开某个游戏时该不该默认开着,取决于读者是拿它当精度工具还是当主要玩法。
- **Blackbox 的揭晓要不要二次确认。** 这是本文档唯一一处主动偏离上游交互的建议
  (见第 17 节),值得单独验证:多一步确认换来的安全感,是否抵得过多出来的那一下点击。
