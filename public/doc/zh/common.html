第 2 章：通用功能

本章描述所有游戏共有的功能。

2.1 通用操作

除各游戏特有的操作之外，以下这些操作都可以从‘游戏’菜单以及键盘快捷键使用。

（在 Mac OS X 上，为符合本地用户界面标准，这些操作改为位于‘文件’和‘编辑’菜单中。）

新游戏（‘N’、Ctrl+‘N’）
以随机的初始状态开始一局新游戏。
重新开始游戏
把当前游戏重置为它的初始状态。（此操作可以撤销。）
载入
从磁盘上的文件载入一局已保存的游戏。
保存
把你这局游戏的当前状态保存到磁盘上的文件中。

载入和保存操作会保留你完整的游戏历史（因此你可以保存、重新载入，并且仍然能够撤销和重做你在保存之前所做的操作）。

打印
在支持的平台上（目前仅限 Windows），会弹出一个对话框，允许你打印任意数量的、依据当前参数随机生成的谜题，并可选择把当前的谜题也包含进去。（当然，这只适用于那些适合打印的谜题 – 很难想出 Fifteen 有什么合理的可打印表现形式！）
撤销（‘U’、Ctrl+‘Z’、Ctrl+‘_’、‘*’）
撤销一步操作。（你可以一直撤销到本次会话的开始。）
重做（‘R’、Ctrl+‘R’、‘#’）
重做先前被撤销的一步操作。
复制
以文本格式把你这局游戏的当前状态复制到剪贴板，这样在你与别人讨论这局游戏时，就可以把它粘贴到（比如）电子邮件客户端或网络留言板中。（并非所有游戏都支持此功能。）
求解
立即把谜题变换为它的已解状态。对某些游戏（Cube）而言，完全不支持此功能，因为它没有什么特别的用处。对另一些游戏（例如 Pattern）而言，如果你根本看不出解怎么可能存在，或者想知道自己在哪里犯了错，已解状态可以给你提供信息。而对于再另一些游戏（例如 Sixteen），自动求解并不会告诉你如何到达解，但它确实提供了一种快速抵达那里的实用方式，让你可以试验成套的移动与变换。

某些游戏（例如 Solo）能够求解你从别处输入进来的游戏 ID。另一些游戏（例如 Rectangles）无法求解并非自己生成的游戏 ID，但当游戏 ID 是它们自己生成的时候，它们本来就已经知道解是什么了。还有一些游戏（Pattern）可以求解部分外部游戏 ID，但前提是这些游戏 ID 不太难。

‘求解’命令会把已解状态添加到该谜题撤销链的末尾。换句话说，如果你在看过答案之后想回去继续自己解，只需按撤销即可。

退出（‘Q’、Ctrl+‘Q’）
完全关闭应用程序。
首选项
在支持的平台上，会弹出一个对话框，允许你配置关于某个特定游戏的个人首选项。其中一些首选项是某个特定游戏专有的；另一些则是所有游戏共有的。

所有游戏共有的一个选项允许你关闭单键快捷键，比如用于开始新游戏的 ‘N’ 或用于退出的 ‘Q’，这样误触它们的可能性就会小一些。你仍然可以配合 Ctrl 键使用同样的快捷键。

2.2 用游戏 ID 指定游戏

有两种方式可以把一局游戏的规格说明从谜题程序中保存出来并在日后重建它，或者在别人的同一谜题程序副本中重建它。

‘指定’和‘随机种子’这两个选项来自‘游戏’菜单（在 Mac OS X 上则来自‘文件’菜单），它们各自会显示一段文本（一个‘游戏 ID’），这段文本足以在日后精确地重建出完全相同的一局游戏。

你可以在日后把这两段文本中的任意一段重新输入到程序里（通过同样的‘指定’或‘随机种子’菜单选项），程序就会重建出同一局游戏。你也可以把其中任意一段用作命令行参数（在 Windows 或 Unix 上）；更多细节见第 2.4 节。

两种形式的区别在于：描述性游戏 ID 是对游戏的一段字面描述，说明它的初始状态；而随机种子只是一段任意文本，它被用作创建该谜题所使用的随机数生成器的输入。这意味着：

  • 在许多谜题中，描述性游戏 ID 往往比较长（不过有些谜题，例如 Cube（第 4 章），只需要非常简短的描述）。因此，若要记下你当前正在玩的谜题，或者把它告诉别人以便对方玩到和你一样的那一局，随机种子往往是更快捷的方式。
  • 任何文本都是有效的随机种子。自动生成的种子是十五位数字，但任何内容都可以；你可以输入自己的全名，或者一个你刚编出来的词，程序就会据此生成一个有效的谜题。这为两人或多人比赛完成同一个谜题提供了一种方式：你想出一个随机种子，然后所有人同时把它输进去，谁也不会因为比别人先看到生成出来的谜题而占到便宜。
  • 通常可以把来自其他来源的谜题（例如报纸上的‘数织’或‘数独’）转换成适合这些程序使用的描述性游戏 ID。
  • 如果你把随机种子用在谜题程序的不同版本上，并不保证会产生相同的结果。这是因为生成算法在后续版本的代码中可能已被改进或修改，因此在给定相同的随机数序列时会产生不同的结果。如果你不确定随机种子会被用在与你相同版本的程序上，请使用描述性游戏 ID。

    （使用‘关于’菜单选项可以查出程序的版本号。版本号相同的程序即使运行在不同平台上，也应当仍然保持随机种子兼容。）

描述性游戏 ID 以一段文本开头，这段文本编码了当前游戏的参数（例如网格大小）。接着是一个冒号，冒号之后是对游戏初始状态的描述。随机种子同样以一串类似的参数开头，但之后是一个井号，井号后面跟着任意数据。

如果你输入的是描述性游戏 ID，程序将无法向你显示生成它的随机种子，因为它并不是从随机种子生成出来的。然而，如果你输入的是随机种子，程序就能够向你显示由该随机种子导出的描述性游戏 ID。

请注意，两种形式中的游戏参数字符串并不总是完全相同。对某些游戏而言，随机种子会附带一些描述性游戏 ID 中未包含的参数数据。这是因为那部分参数信息只在生成谜题网格时才有意义，而在游玩它们时并不重要。因此，举例来说，Solo（第 11 章）中的难度等级就没有在描述性游戏 ID 中提及。

如果你输入一个游戏 ID，这些附加参数也不会被永久设定。例如，假设你把 Solo 设为‘高级’难度等级，然后一位朋友希望你帮他解决一个‘极易’谜题；于是这位朋友念出一个指定了‘极易’难度的随机种子，你把它输了进去。程序会为你生成你朋友遇到麻烦的那个‘极易’网格，但一旦你玩完了它，当你要求开始新游戏时，程序会自动回到它先前设定的‘高级’难度。

2.3 ‘类型’菜单

‘类型’菜单（如果存在的话）可能包含一份预设游戏设置的列表。选择其中之一，将以所指定的参数开始一局新的随机游戏。

‘类型’菜单还可能包含一个‘自定义’选项，它允许你精细调整游戏参数。可用的参数是各游戏特有的，将在后续各节中描述。

2.4 在命令行上指定游戏参数

（本节不适用于 Mac OS X 版本。）

本合集中的游戏刻意从不把信息保存到它们所运行的计算机上：它们没有高分榜，也没有保存下来的首选项。（这是因为我预计至少会有一些人在工作时玩它们，而这些人大概会希望尽可能少留下痕迹！）

不过，如果你确实希望让其中某个游戏默认使用某一组特定的参数，你可以在命令行上指定它们。

最简单的做法是：先用‘类型’菜单（见第 2.3 节）设置好你想要的参数，然后从‘游戏’或‘文件’菜单中选择‘随机种子’（见第 2.2 节）。‘游戏 ID’框中的文本将由两部分组成，中间以一个井号分隔。其中第一部分代表游戏参数（例如游戏区域的大小，以及你用‘类型’菜单设置的其他任何内容）。

如果你在命令行上只带着那段参数文本运行游戏，它就会以你所指定的设置启动。

例如：如果你运行 Cube（见第 4 章），从‘类型’菜单中选择‘八面体’，然后转到游戏 ID 选择处，你会看到一个形如‘o2x2#338686542711620’的字符串。只取井号之前的部分（‘o2x2’），并在命令行上带着这段文本启动 Cube：‘PREFIX-cube o2x2’。

如果你把整个游戏 ID 复制到命令行上，游戏就会以所描述的那局具体游戏启动。相比把游戏 ID 粘贴到游戏 ID 选择框中，这偶尔是启动某个特定游戏 ID 的更方便的方式。

（你也可以用‘指定’菜单选项而不是‘随机种子’来取得编码后的游戏参数，但如果那样做，某些选项就会缺失，例如 Solo 中的难度等级。关于这一点的更多细节见第 2.2 节。）

2.5 Unix 命令行选项

（本节仅适用于 Unix 移植版本。）

除了可以在命令行上指定游戏参数（见第 2.4 节）之外，还有其他各种选项：

--game
--load
这两个选项分别决定命令行参数是被当作指定游戏参数，还是被当作一个存档文件来载入。只应指定其中之一。如果这两个选项都没有指定，程序会根据参数的格式作出猜测。
--generate n
如果指定了此选项，程序将不显示谜题，而是构造出若干个描述性游戏 ID 并打印到标准输出。这有助于在不必使用前端界面的情况下使用游戏生成算法。

如果在命令行上指定了游戏参数，就会用它们来生成这些游戏 ID；否则将使用一组默认参数。

此选项最常见的用法是与 --print 配合使用，此时它的行为略有不同；见下文。

--delete-prefs
此选项会让谜题程序删除保存其用户偏好设置的配置文件（如果存在这样的文件的话）。
--print wxh
如果指定了此选项，程序将不显示谜题，而是把一个或多个未解谜题的打印表现形式以 PostScript 格式送到标准输出。

在每一页谜题上，横向会排 w 个，纵向会排 h 个。如果谜题数量多于 w×h，就会打印不止一页。

如果同时还指定了 --generate，就会用构造出来的游戏 ID 来产生打印输出。否则，程序会期望从标准输入读入一份游戏 ID 列表（可以是描述性 ID 或随机种子；见第 2.2 节），其格式与 --generate 所产生的相同。

例如： 

PREFIX-net --generate 12 --print 2x3 7x7w | lpr

将生成两页打印出的 Net 谜题（其中每一个都有一个 7×7 的环绕网格），并把输出通过管道传给 lpr 命令，在许多系统上该命令会把它们送到真正的打印机上。

还有其他各种影响打印的选项；见下文。

--save file-prefix [ --save-suffix file-suffix ]
如果指定了此选项，程序将不显示谜题，而是把一个或多个未解谜题的存档文件写入根据所提供的前缀和/或后缀构造出的文件中。

如果同时还指定了 --generate，就会用构造出来的游戏 ID 来产生打印输出。否则，程序会期望从标准输入读入一份游戏 ID 列表（可以是描述性 ID 或随机种子；见第 2.2 节），其格式与 --generate 所产生的相同。

例如： 

PREFIX-net --generate 12 --save game --save-suffix .sav

将生成十二个 Net 存档文件，文件名从 game0.sav 到 game11.sav。

--version
打印关于该游戏的版本信息，然后退出。

以下选项只有在同时指定了 --print 时才有意义：

--with-solutions
在排满未解谜题的那些页面之后，将附上这些谜题的解答。
--scale n
调整每个谜题打印出来时的大小。数值越大，谜题越大；默认值为 1.0。
--colour
谜题将以彩色而非黑白方式打印（如果该谜题支持的话）。
